# 채우기 이미지 평가

`fill_image`는 문서를 보유하지 않으며 입력에서 straight RGBA8 이미지나 영역을 반환합니다. 왼쪽 아래가 원점이며 행 우선입니다. UV·평면·트라이플래너·구면·원통·데칼을 지원합니다. 레이어 설정, 리소스 검색, Undo와 저장은 호출자가 담당합니다.

1. `ImageMipChain::build`에 이미지, 색상 변환, 휘도 변환, 추가 단계의 예산, 취소 플래그를 전달합니다. 원본 이미지는 빌려서 사용합니다. Color/Emission에서 선형 이미지를 읽을 때는 `Conversion::LinearToSrgb`, 나머지는 `None`입니다. Roughness/Metallic/Height는 `luminance = true`로 설정합니다. 노멀은 색상 변환하지 않습니다.
2. `FillInput`에 `Projection`, 해상도, 이미지와 대체 값을 넣고 `FillSampler::bind`로 입력을 검증합니다. 모델 투영에는 위치 맵, 원래 경계 상자, 모델 프레임을 전달합니다. 트라이플래너와 데칼에는 노멀도 필요합니다.
3. `render(x, y, width, height, budget, cancel)`로 영역을 평가합니다. `pixel`은 1픽셀을, `decal_coverage`는 모양 이미지를 곱하기 전의 상자·깊이·면 방향에 따른 커버리지를 반환합니다.

밉은 홀수 길이 변의 마지막 3텍셀까지 포함해 평균하고, 미리 곱한 알파 가중치로 쌍선형·삼선형 보간합니다. `FillInput::anisotropic` (데칼의 다른 채널 모양은 `shape_anisotropic`)을 켜면 픽셀의 풋프린트 (이웃 픽셀과의 위치 차이에서 구한 텍셀 차이)가 길쭉할 때 긴 방향을 따라 종횡비에 해당하는 수 (올림. 1% 이하의 소수 부분은 버림, 상한 `MAX_ANISOTROPY` = 16)의 점을 같은 간격으로 취합니다. 각 점을 짧은 방향의 길이 (상한으로 부족하면 길이 ÷ 개수)에 해당하는 단계에서 읽고 평균합니다. 풋프린트가 둥글거나 확대된 픽셀, 한쪽 차이를 알 수 없는 픽셀은 켜도 C#과 같은 1회의 삼선형 보간을 사용합니다. 기본값은 꺼짐 (C#과 모든 바이트 일치)이며 문서에서는 레이어의 채널별 설정 (기본값 켜짐)을 전달합니다. 켠 경로는 Rust에서 생성한 정답 (`tests/golden/fill-image-anisotropic`)과 모든 바이트를 비교합니다. 결과 알파가 0으로 반올림된 픽셀의 RGB도 C# 규칙에 따라 남깁니다. 투영 회전 순서, 가까운 이웃을 선택하는 풋프린트, 경도 이음새, 트라이플래너의 혼합 폭은 C# `FillImageSampler`와 같습니다. Rayon 호출자의 풀에서 병렬도를 설정할 수 있습니다.

데칼 채널이 픽셀마다 다른 값 (그라데이션 램프의 결과 등)을 가질 때는 `apply_decal_to_value` (1픽셀) 또는 `render_decal_values` (영역. 값은 영역과 같은 배열의 RGBA8)에 값을 전달합니다. C#의 `ApplyDecalToValue`와 마찬가지로 상자·깊이·면 방향·다른 채널의 모양 커버리지만 값의 알파에 곱하고 자신의 이미지는 사용하지 않습니다 (`FillInput::image` 유무와 무관). 배치할 수 없는 데칼은 투명하며, 데칼 이외의 투영은 거부합니다. `FillInput::fallback`의 1색으로 대신하면 픽셀마다 값이 달라야 하는 채널이 알림 없이 단색이 됩니다.

데칼은 위치·노멀이 없는 픽셀과 상자 밖에서 투명해집니다. 모양 이미지는 채널 순서상 첫 번째 이미지를 호출자가 선택합니다. 해당 채널 자체에는 `image`로만 전달하고, 다른 채널에는 `shape`에도 전달하세요. 자신의 이미지를 `shape`에 중복 전달하면 알파가 두 번 곱해집니다. 값만 있는 채널은 `image = None`입니다. 이미지를 지정했지만 불러오지 못했다면 `missing_image = true`로 설정해 이유를 남깁니다.

## geometry 연결

`ModelMaps::from_geometry`는 `SurfaceGeometry`의 삼각형·UV 무게중심 좌표·면 노멀에서 16 bit 위치와 노멀을 만듭니다. 머티리얼은 집합 (`MaterialSet`. 텍스처 세트가 가진 여러 머티리얼. 항목 1개의 집합은 기존 머티리얼 번호와 같은 결과)으로 지정하며, 중복 UV에는 입력 순서상 첫 번째 면을 사용합니다. 메모리 예산은 픽셀당 13바이트이며 작업 예산은 삼각형과 UV의 대조 횟수입니다. bounds와 revision을 보존합니다.

이 경로는 면 노멀·픽셀 중심 1점·여백 없음 방식입니다. C#의 완전한 메시 베이커 (스무스 노멀, 하이폴리 참조, 앤티앨리어싱, 여백 채우기)를 대신하지 않습니다. 그 결과를 사용하려면 `Map`에 16 bit RGB와 커버리지를 전달합니다. 오래된 맵은 호출자가 `stale_position` / `stale_normal`로 명시합니다.

## 예산과 거부

- 밉 예산은 C#과 마찬가지로 단계 0을 제외한 RGBA8 총량입니다. 관리 배열이나 빌린 원본 이미지는 포함하지 않습니다. 새 밉을 만들기 전에 기존 밉을 합친 상주 메모리까지 제한하려면 호출자가 남은 예산을 전달합니다.
- 영역 출력 예산은 반환할 바이트 수입니다. 취소 여부는 밉의 단계와 행, 출력의 행과 256픽셀마다, geometry의 삼각형과 행에서 확인하며 중간 출력을 반환하지 않습니다. 배열 할당 자체를 중간에 멈추는 계약은 아닙니다.
- C#의 독립 `ImageMipChain` / `FillImageSampler`에는 취소와 출력 예산 인자가 없습니다. Rust에서 추가로 제공하는 보장입니다. 문서·캐시 전체 예산을 재현하지는 않습니다.
- 미해결 이미지, 누락/이전 세대/다른 해상도 맵, 알 수 없는 모델 프레임은 `reason()`으로 구분합니다. 일반 투영은 대체 값, 배치할 수 없는 데칼은 투명입니다. 잘못된 설정은 `FillError`로 거부합니다.
- C#의 `MayCover` / `MayCoverTiles` / `AddDecalTiles` (위치 타일의 경계를 이용해 데칼이 덮을 수 없는 타일을 미리 제외하는 최적화)는 이식하지 않았습니다. 호출자가 평가할 영역을 정해 `render`에 전달합니다.
- 극단적인 모델 좌표로 중간 계산이 넘치거나 보수적으로 추정한 이미지 텍셀 좌표가 32 bit 정수를 초과하면 평가 전에 거부합니다. 범위를 벗어난 `double → int`가 실행 환경에 따라 달라지는 C#과의 차이입니다. 너비·높이는 1〜8192입니다.

## 대조와 측정

`cargo test -p yolu-core --test reference fill_image::`로 알려진 정답·거부·예산·취소·C# 정답과의 모든 바이트 대조를 실행합니다. 데칼의 픽셀별 값 (`ApplyDecalToValue`)은 같은 8개 설정의 데칼에 좌표만으로 정해지는 값을 전달한 8개 사례를 같은 병렬도·타일 분할·1픽셀 경로로 대조합니다. geometry에서 베이크한 맵은 평면·트라이플래너·데칼에 그대로 전달해 알려진 픽셀을 확인합니다 (z 폭이 0인 판과 기울어진 판. 위치 인코딩과 bounds 전달이 1개라도 어긋나면 실패). 취소는 `cargo test -p yolu-core --lib cancellation_tests`로 밉 구성·geometry·일반 출력·데칼 값 출력을 확인합니다. 테스트 전용 단일 워커에서 행·단계·256픽셀마다 취소 확인 횟수를 세고 중간에 플래그를 설정해, 다음 확인까지 진행하지 않고 취소를 반환하는지 검증합니다. 경과 시간이나 실제 장치의 응답 시간은 합격 여부에 사용하지 않습니다. 48개 사례 (6개 투영×8개 설정)는 37×29픽셀이며, 홀수 길이 변/1픽셀 변, 투명 RGB, 색상/휘도 변환, 3종류의 외부 처리, 축소/확대, 회전하는 모델과 배치, 데칼의 다른 이미지/값을 포함합니다. Rust 병렬도 1/2/4와 타일 분할, C# 병렬도 1/4도 대조합니다.

정답은 Unity에 의존하지 않는 C# Core 원문 (Unity 브리지 태그 `0.4.0`의 `Runtime/Core`)의 출력을 이어받은 것입니다. 다시 만들 때는 Rust 출력에서 생성합니다. `source.txt`에 버전과 평가식 지문을 남깁니다. `contracts.txt`는 잘못된 설정 12건과 5×3 이미지의 밉 예산 11/12바이트 경계입니다.

4096² 비교는 다음 명령으로 실행합니다 (Linux, CPU 0〜3 사용).

```sh
cargo build --release -p yolu-core --example bench_fill_image
taskset -c 0-3 target/release/examples/bench_fill_image 3 4
```

인공 이미지 31×23, 투영별 동일 설정, 예열 1회와 실측 3회입니다. 출력 할당은 포함하고 맵과 밉 준비는 제외합니다. 데칼은 상자 밖을 포함하므로 모든 픽셀을 이미지로 덮을 때의 속도는 아닙니다. Rust는 release입니다. 실제 데이터나 Windows의 성능을 보장하지 않습니다.
