# Generator·램프·Anchor 이미지 평가

`Settings`를 `BoundGenerator::bind`로 검사하고 읽기 전용 입력에 바인딩합니다. `evaluate`는 `Source`의 지정 영역에서 새 RGBA8 이미지를 반환합니다.
`Image`는 연속 이미지용입니다. 타일 입력은 `Source`를 구현하여 캔버스 좌표의 픽셀을 반환합니다. 영역 분할 방식이나 Rayon 풀의 병렬도에 따라 계산 결과가 달라지지 않습니다.
입력과 설정은 빌려 사용하므로 평가 중인 스냅샷은 변경할 수 없습니다. 호출 측에서는 성공한 이미지만 채택합니다.

지원 종류는 EdgeWear, Dirt, PositionGradient, Thickness, Direction(월드/벤트 노멀), ShapeGradient, IdColor, Anchor와 Rust 구현 전용 Noise(64)·Grunge(65)·Image(70), 아래의 0.5.0 종류(66~69)입니다.
노이즈는 각 종류에 겹치는 4옥타브 값 노이즈이며 UV 또는 모델 공간을 사용합니다. ShapeGradient는 상자·구·평면, 루트 위치와 회전, 모양의 중심·회전·크기·감쇠를 가집니다.
`Ramp`는 독립적인 RGB 및 불투명도 정지점, 중간점, PCHIP 값 곡선, 5종 프리셋을 가집니다. 색상은 저장된 sRGB 값 그대로 보간하며 투명 픽셀의 RGB를 유지합니다.
색상 정지점의 α는 평가에 사용하지 않으며 C#의 `GradientStop`과 마찬가지로 `Ramp::new`가 255로 맞춥니다(불투명도는 별도 정지점이 가짐). α가 다른 입력으로 만든 램프는 `==`로 비교하면 같습니다.
스칼라와 마스크 램프는 휘도 0.2126/0.7152/0.0722를, Anchor의 색상 읽기는 C#과 같은 0.3/0.59/0.11을 사용합니다.

맵은 C# Core와 같은 u16 성분과 커버리지를 전달합니다. `MapState`는 호출 측이 베이킹 출처와 현재 모델을 대조한 결과를 나타냅니다.
생성·출처 계산·업데이트 감시는 포함하지 않습니다. 누락, 오래됨, 미검증, 크기 불일치, 핀 불일치, 루트 미상, 바운딩 박스 크기 0, ID 미선택, Anchor 사용 불가는
`Inactive`로 반환하고 단계 입력을 통과시킵니다. 커버리지가 0인 픽셀도 입력을 통과시킵니다. 잘못된 설정·이미지 길이·출처 형식·유한하지 않은 값은 `Error`로 거부합니다.
극단적인 유한 좌표의 연산이 무한대가 되는 경우도 거부합니다(C# 모델 프레임에서 거대한 쿼터니언을 정규화할 수 있는 경우보다 엄격함).

`BoundGenerator::sample`은 `Generated`(램프 없으면 `Scalar(f64)`, 램프 있으면 계산된 straight RGBA8의 `Mapped([u8; 4])`)를 반환합니다.
스칼라는 항상 유한한 0..1이며 값이 없는 픽셀(커버리지 0·입력을 통과시키는 단계)은 `None`입니다. 필터의 `GeneratorInput`이 받는 `Generated`와 같은 형식이므로
`sample(slot, x, y)`에서 바인딩된 `BoundGenerator::sample(x, y, scalar)`의 결과를 그대로 반환할 수 있습니다(`filter::Generated`는 이 타입을 재공개한 것).
행 단위 진입점 `sample_row(slot, x0, y, out)`은 `BoundGenerator::sample_row`에 그대로 전달할 수 있으며 필터 단계는 행마다 이쪽을 호출합니다.
필터 등 다른 평가기에 전달할 때 스칼라/마스크 대상은 `scalar = true`를 지정합니다. `evaluate`의 `Target::Mask`는 A를 숨기는 양으로 읽으며 출력은 RGB=0·A=숨기는 양입니다. 색상의 완전 투명 픽셀은 RGB도 변경하지 않습니다.
탄젠트 공간 노멀은 대상에 포함하지 않습니다. `Settings::algorithm_version`은 램프가 없으면 1, 있으면 2입니다.

`Settings::anchor`(`anchor::Reference`)는 C#의 `GeneratorSettings`에 해당하는 AnchorId·AnchorChannel·AnchorRead(정본 버전 20)를 가집니다.
`id`는 `Point::id`이며 0은 미선택, `channel`은 읽을 채널, `read`는 `ReadMode::Value`(값×커버리지) 또는 `Coverage`(커버리지)입니다.
Anchor의 기본값은 Height이고 다른 종류는 Color입니다(C#과 동일). `Settings::validate`는 C#과 같이 Anchor가 아닌 종류에 기본값 이외의 설정이 있는 경우와
Anchor가 Normal 채널을 읽는 경우를 거부합니다(Normal 종류의 사용자 채널은 `Plan::new`가 거부). 마스크 Anchor는 `channel`과 `read`를 무시합니다.
읽기 순서는 `Reference::resolve` → `Point`(레이어 번호와 배치) → 레이어라면 `Plan::new(layers, point.host, dimensions, チャンネルの種類)`와
`Reference::read_for(チャンネルの種類)`로 만든 `LayerSample`, 마스크라면 `MaskSample` → `BoundGenerator::bind`의 `anchor`입니다.

`anchor::resolve`는 미선택·누락·같은 레이어/상위 레이어를 거부합니다. 모든 참조가 더 작은 레이어 번호를 가리키므로 순환을 만들 수 없습니다.
점 목록을 받는 시점에 `validate_points`를 호출하여 ID와 배치 중복을 거부합니다. 레이어 순서가 바뀌면 다시 해석합니다.
`anchor::Plan`은 한 채널의 계산된 레이어 이미지를 받아 그 레이어까지의 스택을 합성합니다. 그룹·마스크·클리핑·조정 레이어를 지원합니다.
통과 그룹에서는 아래부터 이어 가고 분리 그룹에서는 투명 상태부터 시작합니다. Anchor가 host의 조상을 따라갈 때도 문서 합성과 마찬가지로, 바로 위 형제 레이어가 클리핑된 조상 그룹은 그 형제의 표시 여부나 내용 종류와 관계없이 분리 그룹으로 취급하며 그룹 바깥의 아래 내용을 읽지 않습니다. 조상 자체의 불투명도·마스크·표시 여부를 사용하지 않는 규칙은 그대로입니다. Anchor 위쪽의 클리핑과 조상 자체의 불투명도·마스크·표시 여부는 포함하지 않습니다.
레이어 필터는 입력 이미지에 미리 적용해야 합니다. 그룹 자체의 필터나 투영은 호출 측에서 이미지로 계산하여 전달합니다.
레이어 결과를 `LayerSample`에 전달하면 값×커버리지·색상 휘도×커버리지·커버리지를 읽을 수 있습니다. `MaskSample`은 필터가 적용된 숨김 양에 활성 상태·반전·농도를 적용합니다.
문서 편집, 저장, 기록, 캐시, Anchor 연쇄의 스냅샷 생성 순서는 호출 측에서 관리합니다.

작업 한도는 반환할 RGBA8의 `幅×高さ×4`바이트입니다. 다른 픽셀 버퍼는 만들지 않습니다(행 작업 공간은 스레드마다 너비 × 8바이트 값 행과 격자 캐시를 가지지만 픽셀 버퍼가 아니므로 한도에 포함하지 않음). 외부 입력, 설정·합성 계획 등의 메타데이터, 스레드 스택도 포함하지 않습니다.
C# FilterEngine은 블록용 작업 버퍼를 계산하므로 같은 숫자의 한도에서도 거부 경계는 일치하지 않습니다.
취소는 행 경계와 반환 직전에 검사하며 실패하면 중간 이미지를 반환하지 않습니다(`evaluate`와 `Plan::evaluate` 모두 병렬도 1에서 읽은 픽셀 수를 세어 행별 확인과 마지막 확인을 별도로 테스트). C# FilterEngine에는 취소 토큰이 없으므로 Rust에서 추가한 계약입니다.

## 행 단위 평가와 SIMD

`evaluate`는 행 단위로 평가합니다(`evaluate/rows.rs`). 입력 행을 `Source::read_row`로 읽고 종류별 기본값 행 → 레벨·감쇠·반전 → 덧씌울 노이즈 → 램프·혼합 합성 순서로,
픽셀마다 바뀌지 않는 항목(종류·혼합·램프 유무·모양 종류)을 루프 밖에서 결정하여 처리합니다. 값이 없는 픽셀은 `Option::None`과 같은 의미의 표시로 전달하며 `BoundGenerator::sample_row`는
픽셀별 `sample`과 같은 결과를 행으로 묶어 반환합니다(`Generated`는 f64까지 비트가 일치). `ValueSource::value_row`·`Source::read_row`의 기본 구현은 픽셀별 호출이며 행을 한 번에 읽을 수 있는 구현으로 대체할 수 있습니다.

노이즈·그런지 난수는 레이어·옥타브·셀 프레임마다 바인딩 시 한 번만 생성합니다(`procedural::Plan`). 격자 모서리 값(Value·Perlin의 기울기 방향·Worley 특징점·선분)은 hash만으로 정해지므로
직전 격자를 기억하고 같은 격자에 속한 이웃 픽셀에서는 다시 계산하지 않습니다(다른 격자로 들어가면 다시 계산). 캐시는 스레드별 작업 공간이 보유하며 픽셀을 하나씩 호출하는 경로(`sample`, 필터의 대략적 평가)에서도 계획별로 재사용합니다.

SIMD 경로는 `math::simd` 기반입니다(x86_64는 런타임에 AVX2·SSE4.1·스칼라, aarch64는 NEON·스칼라를 선택하며 `YOLU_SIMD`로 낮출 수 있음). 덧씌울 노이즈·레벨·노이즈·그런지 11종·번짐·트라이플래너·램프 색상·모든 혼합 합성을 N픽셀(AVX2는 4,
SSE4.1·NEON은 2)씩 묶어 계산합니다. N픽셀이 같은 격자에 속한 묶음은 모서리 값을 모든 레인에서 공유하며 격자를 가로지르는 묶음·커버리지 없는 픽셀을 포함한 묶음·방향이 결정되지 않은 픽셀을 포함한 묶음은 픽셀별 공식으로 계산합니다.
레인 공식은 픽셀 하나의 공식과 같은 IEEE 연산을 같은 순서로 배치한 것이며 FMA 융합 곱셈-덧셈도 사용하지 않으므로 **모든 경로에서 결과 바이트가 같습니다.** 램프 색상 혼합(일반·선형·지각적)도 레인으로 계산합니다(선형·지각적 혼합의 무거운 공식은 경로별 `inline(never)` 진입점 `MixLanes::mix_curved`에 하나씩 두며 ramp·합성 진입점으로 인라인하지 않음).
선형·지각적 공식은 + − × ÷와 sqrt만 사용합니다(`mixing.rs`: 정지점의 선형광은 256값 테이블, 세제곱근은 [1/8, 1]로 맞춘 뒤 뉴턴법 4회,
`c^(1/2.4)`는 `r·√√r`, OS의 `powf`·`cbrt`·`hypot`은 사용하지 않음). 따라서 레인과 단일 픽셀 공식의 연산이 같으며 OS 수학 함수 차이의 영향도 받지 않습니다.
정지점별 선형광·Oklab·채도는 `Ramp` 생성 시 한 번만 계산합니다. 이전 공식(OS 수학 함수)과의 차이는 색상 조합 3,081 × 가중치 513 × 혼색 2 × 보정 3의
약 2,845만 값에서 0입니다(glibc, `mixing.rs` 테스트). 혼합 비율 곡선이 있는 구간은 N픽셀이 같은 구간이면 곡선의 레인 공식으로, 구간을 가로지르면 픽셀별 곡선 공식으로 가중치를 구합니다.

`cargo run --release -p yolu-core --example generator_perf`는 종류 × 크기(256²·1024²·4096²) × 스레드 수(1·8) 표를 출력합니다(환경 변수 `GEN_SIZES`·`GEN_THREADS`·`GEN_ROWS`·`GEN_RUNS`로 제한).
출력에는 전체 픽셀의 SHA-256이 있으며 매번 같습니다. `GEN_BREAKDOWN=1`은 4096²·스레드 1에서 단계별 내역(입력 읽기·값·노이즈·행·전체)을 보여 줍니다. `GEN_FUZZ=件数`는 측정 대신 고정 시드 난수로 만든 설정·맵·입력·영역 조합을 평가하여 출력 해시를 건별로 표시합니다. 변경 전후 커밋에서 빌드한 예제 출력을(`YOLU_SIMD`를 바꾼 경우도) `diff`하면 다양한 설정의 입력에서도 바이트가 바뀌지 않았는지 확인할 수 있습니다.
입력은 C# 일치 테스트와 같은 합성 입력(`rand`, 맵 값이 픽셀마다 바뀌므로 격자 캐시가
적중하지 않음)과 메시 맵에 가까운 매끄러운 입력(`smooth`) 두 가지입니다.

정답 `tests/generator-index.txt`는 0.4.x까지의 Unity 브리지 C# Core(태그 `0.4.0`의 `Runtime/Core`)에서 합성 입력을 평가한 출력을 이어받은 것이며 다시 만들 때는 Rust 출력으로 만듭니다. 테스트는 전체 픽셀 SHA-256을 이 값과 비교합니다.
`GEN_THREADS=1`과 `4`로 병렬도를 지정할 수 있습니다.
`cargo run --release -p yolu-core --example generator_bench`는 4096²에서 준비 실행 1회·측정 1회를 수행합니다. 입력 이미지와 설정 생성 시간은 제외하고 바인딩과 반환 이미지 할당 시간은 포함합니다.

`YOLU_GENERATOR_GOLDEN`에 C# 출력(`<事例名>.rgba`)이 있는 폴더를 지정하여 테스트하면 338개 사례를 C# 출력의 각 바이트와도 직접 비교합니다. 다만 위의 분리 규칙을 의도적으로 C#과 다르게 바꾸었으므로 `anchor-16`·`20`·`28`·`32`·`40`·`44`의 6개 사례는 C# 출력과 일치하지 않습니다(`tests/generator-index.txt` 값은 변경 후 값).

## 노이즈·그런지(Rust 구현 전용 종류)

`Kind::Noise`(64)와 `Kind::Grunge`(65)는 C# 대응 구현이 없으며 맵을 읽지 않고 위치·방향·UV로 값을 만듭니다(설정은 `Settings::procedural`). C# 종류(0~7)와 겹치지 않는 64부터 번호를 부여하고
`.ylp` 저장은 정본 버전 23입니다(`docs/YLP_FORMAT.md`의 「Generator」). 레벨(low·high·softness·invert)이 임계값·대비를 담당하며 blend·강도·마스크 대상은 다른 종류와 같습니다.

- 노이즈: 기본 함수는 값·Perlin(기울기)·Worley(셀, F1·F2·F2−F1), 겹침 방식은 fBm·ridged·turbulence이며 옥타브 1~8·라쿠나리티 1~4·게인 0~1·크기·시드·회전·번짐(좌표 왜곡)을 지원합니다.
- 그런지: 프리셋은 오염 얼룩·녹 얼룩·긁힌 자국·먼지·지문·직물·균열·물방울 자국·벗겨진 페인트·나뭇결·가죽 무늬입니다(`GrungePreset`). 노이즈 레이어(`Layer`)와 임계값·삼각파를 조합하며 값 1이 「존재함」을 뜻합니다.
  `GrungePreset::default_scale`은 프리셋 선택 시 무늬 크기, `Settings::grunge(preset)`은 기본 설정입니다. `preview(&settings, w, h)`는 UV 공간 미리보기입니다(회색 RGBA8, 화면 썸네일용).
- 공간: 위치(Position 맵으로 3D 처리, UV 아일랜드 이음새에서 무늬가 어긋나지 않음)·트라이플래너(Position과 WorldNormal, 채우기 투영과 같은 가중치)·UV(x·y 격자를 주기로 감아 가장자리 이음새 제거)입니다.
  2D 무늬 프리셋(긁힌 자국·지문·직물)은 위치 공간에서 자동으로 트라이플래너가 됩니다. 위치 맵을 사용할 수 없으면 입력을 그대로 통과시키지 않고 UV로 대체하며 `BoundGenerator::fallback`이 이유를 반환합니다.
  (`Document::generator_fallback`·`fallback_effect_list`, `inactive`와 별개.) `used_maps`는 설정만으로 결정합니다(사용 가능 여부는 확인하지 않음).
- 결정성: 공식은 + − × ÷ sqrt floor와 정수만 사용합니다(libm을 사용하지 않으며 회전은 다항식 sin·cos). 픽셀마다 위치·좌표만으로 정해지므로 스레드 수·영역 분할·평가 블록 크기에 따라 결과가 달라지지 않습니다.
  취소는 다른 종류와 같이 행 경계에서 확인하고 한도는 반환할 RGBA8 크기입니다. 구현을 고정하는 해시는 `tests/procedural-index.txt`입니다(회귀 고정값이며 외부 정답은 아님).

## 이미지(Rust 구현 전용 종류)

`Kind::Image`(70)는 에셋 이미지를 채우기 레이어 이미지와 같은 투영(UV·트라이플래너·평면·구·원기둥, 데칼 제외)으로 읽습니다(설정은 `Settings::image`:
이미지 ID·`fill_image::Projection`·성분). `.ylp` 저장은 정본 버전 28입니다.

- 이미지 자체는 문서 외부 입력입니다(`EffectInputs`의 이미지). `BoundGenerator::bind` 후 `with_image(&FillSampler)`로 투영·문서 크기·위치와 방향 맵·
  모델 루트를 바인딩한 샘플러를 전달합니다(문서 평가의 `document/eval.rs`가 색상 대상에는 색상 밉맵을, 마스크·스칼라에는 값을 그대로 사용하는 밉맵을 만들어 전달).
  전달 전이거나 이미지가 선택되지 않았거나 투영에서 읽을 맵을 사용할 수 없으면 `inactive`(`NoImage`·`MissingImage`·`MissingMap` 등)로 입력을 그대로 통과시킵니다.
- 값: 색상 채널은 픽셀 색상(`invert`는 RGB 반전, 알파는 가시성에 곱함)을 `blend`로 합치고 마스크·스칼라는 선택한 성분(R·G·B·A·휘도)을
  레벨(low·high·softness·invert)에 통과시킵니다. 이미지 값이 없는 픽셀(바깥이 투명한 이미지의 외부·위치 맵에 표면이 없는 픽셀)은 입력을 유지합니다.
- 읽기는 `FillSampler::projected`(채우기 레이어와 같은 밉맵 및 투영 공식)를 사용하므로 색상 채널에서는 같은 이미지·같은 투영의 채우기 레이어와 픽셀이 같습니다.
  (`tests/effects/image_stage.rs`.) 마스크·스칼라 휘도는 보간 후 RGB에서 반올림 없이 구합니다. 채우기 레이어가 스칼라 채널에서 읽는 휘도는 원본 픽셀마다
  8 bit로 반올림한 뒤 보간하므로 보간이 적용되는 투영에서는 값이 조금 다릅니다(R·G·B·A 성분은 채우기 레이어에 해당 읽기 방식이 없음).
  행 평가(`sample_row`)도 픽셀마다 `projected`를 호출합니다(레인 공식으로 구현하지 않음).

## 패턴·조명·마스크 빌더(0.5.0, Rust 구현 전용 종류)

`Kind::Pattern`(66)·`Kind::UvIslandVariation`(67)·`Kind::Light`(68)·`Kind::MaskBuilder`(69)입니다. 설정은 `Settings::pattern`·`island`·`light`·`mask_builder`입니다.
(해당 종류가 아니면 기본값 유지.) 덧씌울 노이즈는 없으며 패턴·조명은 공통 `softness`를 0으로 두고 자체 `softness`를 사용합니다(마스크 빌더는 공통 감쇠 사용).
공식(`kinds050.rs`)은 + − × ÷ sqrt floor와 다항식 sin·cos만 사용하며 픽셀별로 처리합니다(행 평가도 같은 공식 호출, SIMD 미사용).

- 패턴: UV(픽셀 중심)를 회전하고 scale회 반복합니다. 줄무늬·체크무늬·점·격자는 반복 내부에서, 테두리는 UV 정사각형 가장자리와의 거리로 안팎을 정하고 softness 너비로 smoothstep을 적용합니다. 맵은 읽지 않습니다.
- 조명: 월드 노멀 n과 빛 방향 d(azimuth는 +Z에서 +X로, elevation은 수평에서 +Y로)로 lit = clamp((n·d + softness) / (1 + softness))를 계산하고 값은 ambient + (1 − ambient) × lit입니다.
  방향을 정할 수 없는 노멀의 픽셀에는 값이 없습니다.
- 마스크 빌더: 곡률·AO·위치 높이(Y)·두께를 히스토그램 스캔과 같은 공식(level·contrast)으로 0~1로 만들고 invert 후 가중치를 적용하여 곱하기(1 − w + w·t)·최대(w·t)·더하기(최대 1)로 결합합니다.
  가중치가 0인 맵은 읽지 않습니다(없어도 거부하지 않음). 읽는 맵의 커버리지가 없는 픽셀에는 값이 없습니다.
- 아일랜드별 변동: 텍셀의 UV 아일랜드 번호 i(`geometry::IslandMap`, 모델이 같으면 해상도와 무관하게 같은 번호)와 시드로
  u = `cell_hash(seeds(seed)[0], i, 0, 0)` × 2^-32를 구하며 범위는 [0, 1)입니다(u32 → f64와 2의 거듭제곱 곱셈에는 반올림 없음). 값은 min + (max − min) × u입니다(min ≤ max, 같으면 아일랜드와 무관하게 같은 값).
  공통 레벨·감쇠·반전을 적용합니다. 아일랜드 맵은 바인딩 후 `BoundGenerator::with_islands`로 전달하며 전달 전에는 `Inactive::NoModel`, 작업 한도 때문에 만들 수 없으면
  `islands_refused`로 `Inactive::IslandMap`이 됩니다(입력 그대로 통과). 아일랜드 바깥(0)의 픽셀에는 값이 없습니다. 겹치는 텍셀은 번호가 작은 삼각형의 아일랜드를 사용합니다(아일랜드 맵 규칙).
  행 평가는 아일랜드 맵 행의 연속 구간을 따라가며 구간마다 한 번만 값을 구합니다.
