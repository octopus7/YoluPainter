# 스마트 에셋

`Document::capture_smart_material`은 선택한 레이어와 그룹의 하위 항목을 독립적인 조각으로 만듭니다. `capture_smart_mask`는 마스크만 저장합니다. 원래 문서와 픽셀 복사본은 쓰기 시점에 분리합니다.

`place_smart_material`은 여러 최상위 레이어를 이름 있는 그룹으로 묶고, 부모와 위치를 선택하여 Undo 한 번으로 되돌릴 수 있게 배치합니다. 최상위 (부모 없음)에 배치할 때의 대상 레이어 세트는 `SmartPlacement::set`으로 선택합니다 (`None`은 첫 번째 레이어 세트. 부모가 있으면 부모의 레이어 세트를 사용하며, 다른 레이어 세트를 전달하면 거부). `SmartPlacement::channels`에 포함되지 않은 채널은 값과 픽셀을 유지하면서 비활성화합니다. 표준 채널은 종류에 따라 대응합니다. 사용자 채널은 레이어가 내용을 보유한 번호 (활성 상태이거나, 비활성 상태라도 표면·채우기 값·채널별 합성이 있음)에 대해 배치 대상에 같은 번호·같은 정보의 채널이 없으면 거부합니다. 레이어가 사용하지 않는 채널 정의는 조각에 넣지 않습니다. `apply_smart_mask`의 교체도 Undo 한 번으로 되돌릴 수 있습니다.

크기가 다르면 기본적으로 확대에는 이중 선형, 축 하나라도 축소되면 면적 평균을 사용합니다. 최근접도 선택할 수 있습니다. 타일 크기만 다르면 픽셀을 그대로 복사합니다. 투명 픽셀의 RGB와 노멀 정규화는 C#과 같은 규칙을 따르며, Color·Normal·마스크 결과를 C# 출력과 모든 바이트에 대해 비교합니다 (희소한 원본·타일 크기만 다른 경우 포함). 읽을 원본 타일이 하나도 없는 대상 타일은 계산하지 않으며, 원본이 모두 같은 단색이면 그 색상으로 채웁니다 (결과 바이트는 바뀌지 않음). 배치 전에 픽셀 예산과 레이어 수를 검사하며, 거부하면 문서를 변경하지 않습니다.

파일과 프로젝트 에셋은 `yolu_io::smart::SmartFile`과 `yolu_io::shelf::Shelf`로 처리합니다. `SmartFile::to_core`는 픽셀 예산 없이 열며 (`to_core_within`으로 상한을 지정할 수 있음), 배치할 문서의 예산은 배치할 때 검사합니다. core 레이어가 보유할 수 있는 속성만 편집할 수 있습니다. 사용자 채널을 사용하는 에셋은 0.4.x까지의 Unity 브리지가 읽을 수 없는 버전이 되므로 .ylsmart (형식 1)로 저장하지 않고 거부합니다. 이미지를 포함하는 에셋과 베이크 고정을 다시 연결해야 하는 Generator (`repin`)가 있는 에셋은 편집용으로 열 수 없으며 (`yolu_io::smart`의 `REFUSAL_IMAGES`·`REFUSAL_GENERATORS`), SmartFile 원본을 유지합니다. Generator의 베이크 고정 재연결과 이미지 참조를 사용하는 채우기 렌더링은 지원하지 않습니다.

기본 제공 스마트 머티리얼 (`smart_library`)은 채우기 레이어 (채널별 값)와 해당 마스크의 노이즈·그런지 Generator만으로 만듭니다. 외부 이미지나 픽셀 레이어가 없으므로 어떤 크기의 텍스처에도 배치할 수 있으며 맵을 베이크하기 전에도 같은 모습으로 표시됩니다.
