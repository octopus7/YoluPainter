# 레이어에 적용하는 효과

레이어와 마스크는 필터 배열 (`filters`)을, 레이어는 Generator 설정, Anchor 참조, 채우기 이미지와 투영, 채널별 그라데이션, 2D·3D 경로 (`LayerPath`)를 가질 수 있습니다. 효과는 표준 채널 (Color·Roughness·Metallic·Height·Normal·Emission의 0〜5번)만을 대상으로 합니다. 모두 `Document` 편집 API로 변경하며 편집 1개가 Undo 1회가 됩니다. 강도·설정·투영·그라데이션의 연속 드래그는 한 번으로 묶입니다. 거부한 편집은 아무것도 바꾸지 않습니다.

<a id="評価"></a>

## 평가

효과는 캐시를 원본으로 삼지 않습니다. 설정과 원래 픽셀만 저장하고 합성할 때 기존 `filter`·`generator`·`fill_image` 평가를 호출하여 레이어 출력을 만듭니다. 공식을 여기서 중복 구현하지 않으며 단독 평가와 같은 바이트열이 됩니다.

평가는 정사각형 블록 (기본 256픽셀)마다 수행하며 원래 픽셀·설정·입력·Anchor의 참조 대상이 바뀐 블록만 다시 평가합니다. 블록 크기에 따라 결과가 달라지지 않습니다. 부족한 블록은 작업 메모리 예산 안에서 병렬 평가하며 취소할 수 있습니다. 전체 통계 (정규화)와 이미지 밉맵은 병렬 처리 전에 각각 한 번 만듭니다. 예산을 초과하는 설정은 편집할 때 `WorkingBudgetExceeded` 등으로 거부합니다. 스트로크와 Undo뿐 아니라 픽셀·마스크 픽셀·타일 직접 쓰기 (`set_pixel` 등)도 쓴 타일과 영향 범위를 포함하는 블록만 다시 평가하며, 다른 레이어의 평가 캐시는 버리지 않습니다 (외부 입력 전달·구조 변경 편집은 전부 버림).

<a id="外から渡すもの"></a>

## 외부에서 전달하는 데이터

메시 맵·모델 루트·이미지는 이 문서 외부의 데이터입니다. `Document::set_effect_inputs`로 `EffectInputs`를 전달합니다. 저장하지 않으며 Undo 대상도 아닙니다. 같은 내용을 다시 설정해도 재평가하지 않습니다. 입력이 전달될 때까지 이를 사용하는 Generator와 채우기는 입력을 그대로 통과시키며, `inactive_effects()`가 작동하지 않는 효과를 한 행씩 반환합니다. `yolu-io`의 `Project::image_inputs()`는 .ylp 이미지 리소스로 이미지 입력을 만듭니다.

## Anchor

Anchor는 레이어 또는 마스크에 배치하는 이름 있는 연결점입니다. 레이어 Anchor는 해당 레이어까지의 스택 결과 (모든 채널)를, 마스크 Anchor는 마스크가 레이어를 드러내는 양을 가리킵니다. 위쪽 레이어의 Anchor Generator가 이를 읽습니다. 참조 대상을 선택하지 않았거나, 대상이 없거나, 읽는 레이어보다 아래에 있지 않으면 Generator는 입력을 그대로 통과시키고 `anchor_issues()`가 이유를 반환합니다. Anchor를 읽는 레이어는 참조 대상의 픽셀이 바뀌면 재평가됩니다. 효과는 해당 레이어가 속한 레이어 세트 안에서만 읽습니다. 다른 레이어 세트의 Anchor를 가리키는 참조는 사라진 Anchor와 마찬가지로 입력을 그대로 통과시킵니다.

<a id="パス"></a>

## 경로

경로 레이어는 설정 (경로와 그리는 방법)으로 픽셀을 만듭니다. 손으로 그리기·칠하기·선택 영역 채우기·머티리얼 칠하기는 거부합니다. `rasterize`로 경로를 제거하면 픽셀 레이어로 돌아갑니다.

<a id="ロック"></a>

## 잠금

효과 설정 (단계 추가·삭제·설정·강도·채널·순서, Anchor 추가·삭제·참조 대상, 픽셀을 바꾸지 않는 투영 변경)은 픽셀을 바꾸지 않으므로 “모두 잠금”에서만 거부합니다 (Anchor 이름 변경은 거부하지 않음). 픽셀을 다시 결정하는 작업 (채우기 이미지·그라데이션·값, 이미지가 있는 레이어와 데칼의 투영, 경로 교체)은 이미지 잠금과 투명 픽셀 잠금에서도 거부합니다. 경로로 그린 레이어에 손으로 쓰려면 먼저 잠금을 확인하고, 통과하면 경로 레이어라는 이유로 거부합니다 (이동할 때만 경로 레이어를 먼저 확인). 부모 그룹의 잠금은 내부 레이어와 앞으로 들어올 레이어에도 적용됩니다.

<a id="レイヤーの操作"></a>

## 레이어 작업

복제는 효과와 Anchor에 새 ID를 부여하고 복사본 내부의 Anchor를 읽는 단계가 복사본의 Anchor를 읽게 합니다 (외부 Anchor는 유지). 삭제 시에는 사라진 Anchor를 읽는 단계가 입력을 그대로 통과시킵니다. 병합은 효과와 경로를 픽셀에 베이크하며 (결과에는 효과가 없음), 작동하지 않는 효과가 포함되어 있으면 거부합니다 (격리 병합은 아래쪽 레이어의 마스크 효과도 베이크하므로 해당 마스크의 비활성 Generator도 거부합니다. C#은 이를 확인하지 않고 아무 알림 없이 버립니다). 위쪽 레이어의 Anchor는 결과로 옮겨지고 아래쪽 레이어의 Anchor는 없어집니다. 유지하는 마스크의 단계는 새 ID로 결과에 복사됩니다. 이미지 크기를 바꾸면 흐림·선명하게의 반경을 배율에 맞추고 (범위에 맞추느라 제한한 부분은 알림), 2D 경로는 점과 반경을 맞춰 다시 그립니다 (캔버스만 이동하는 변경은 2D 경로의 점을 픽셀과 같은 양만큼 옮겨 다시 그립니다. C#에 대응 작업이 없는 Rust 고유 규칙입니다). 모델 위의 경로는 유지되며 보고서에 해당 레이어를 명시합니다. 변형은 경로로 그린 레이어를 거부합니다. 어떤 작업이든 거부하면 아무것도 바꾸지 않고, 평가 출력은 새 픽셀·크기로 다시 만듭니다. 기록 비용은 C#과 비교한 작업에서 같은 방식으로 계산합니다.

<a id="保存"></a>

## 저장

`yolu-io`의 `to_core` / `from_core`는 필터·Generator·Anchor·채우기 이미지와 투영·그라데이션·경로를 .ylp 원본과 바이트 단위로 일치하게 왕복 변환합니다. `.ylp` 형식은 올리지 않습니다. 원본 버전은 사용하는 기능에 따라 결정됩니다 (0.4.x까지의 Unity 브리지가 쓸 수 있는 효과는 버전 21을 유지하고, 0.5.0의 필터 종류 70〜79와 Generator 종류 66〜70은 버전 28 이상. 표는 `docs/YLP_FORMAT.md`의 “원본 버전 결정 규칙” 참조). Generator 알고리즘 버전은 계조 (ramp)가 있을 때만 2가 됩니다. 효과 종류 목록은 `effects::catalog`, 필터 공식은 `filter/README.md`, Generator 공식은 `generator/README.md`에 있습니다.
