# 비파괴 필터

`filter::evaluate`는 읽기 전용 `Source`와 순서가 있는 `Stage`를 받아 지정 영역의 RGBA8을 반환합니다. 전체 이미지가 메모리에 있으면
`Image::new`를 사용할 수 있습니다. 타일이면 `Source::pixel`에서 캔버스 좌표를 타일 내부 좌표로 변환합니다. 평가 중에는 입력과 Generator 값을 고정합니다.
입력 갱신·기록·저장은 이 API에서 수행하지 않습니다. 성공했을 때만 반환된 이미지를 채택합니다.

지원하는 일반 필터는 흐림·선명하게·노이즈·레벨·반전·정규화입니다. 각 단계는 활성 상태와 강도를 가집니다.
색상과 스칼라는 같은 픽셀 공식을 사용하며 스칼라의 색상 노이즈는 거부합니다. 탄젠트 공간 노멀은 벡터를 다시 정규화하는 흐림만 허용합니다.
마스크는 입력 A를 숨기는 양으로 보아 불투명 회색으로 펼친 후 출력을 RGB=0·A=숨기는 양으로 되돌립니다.

Rust 구현에만 있는 색조 보정 단계 (그라데이션 맵·톤 곡선·색상 균형·밝기/대비·이진화·포스터화. 단계 종류 번호는
64〜69)는 조정 레이어 (`adjust`)와 같은 값 자료형과 공식을 사용하며 강도는 원래 색상과의 혼합입니다. 픽셀별 점 처리로 반경은 0입니다. 그라데이션 맵과 색상 균형은
색상만 허용하고 (스칼라·마스크는 거부), 톤 곡선은 스칼라와 마스크에서 전체 RGB 곡선만 적용되며, 모두 탄젠트 공간 노멀에는 배치할 수 없습니다.

흐림은 알파를 미리 곱한 16비트 값을 가로·세로 순서로 정수 박스 흐림에 통과시킵니다. 3회 박스 반경의 합계가 지정 반경이 됩니다.
캔버스 밖에서는 가장자리 픽셀을 반복하고 타일 경계에서는 이웃 타일을 읽습니다. 점 연산도 투명 픽셀의 RGB를 처리하지만 선명하게는 투명 픽셀을 유지합니다.
흐림 결과 출력 알파가 0인 픽셀은 원래 RGB를 유지합니다. 부분 강도는 알파가 바뀌는 경우 알파를 미리 곱한 상태로 혼합합니다.
정규화 통계는 지정 영역뿐 아니라 해당 단계 전체 입력에서 알파가 양수인 픽셀로 구합니다.
`statistics`는 통계만 구합니다 (반환 배열은 단계와 같으며 활성 Normalize 단계만 `Some`). 스캔은 블록 병렬 처리이며 결과는 병렬 처리 수·블록
크기에 영향을 받지 않습니다. `Options::statistics`에 전달한 단계는 스캔하지 않고 해당 값을 사용하므로 문서 측에서 (입력·스택·Generator 값의) 세대별로
통계를 보유하면 영역별 `evaluate`가 전체 이미지를 다시 읽지 않습니다. 전달한 값의 출처 대조는 호출 측이 담당하며 이 모듈은 단계 종류와 개수만 검증합니다.

Generator 단계에는 `GeneratorInput`이 반환한 해석된 스칼라 또는 램프 적용 후 RGBA를 전달합니다. 7가지 혼합은 C#의
`BoundGenerator.Combine`과 같습니다. 비교는 2가지입니다. `Combine` 단독의 상세 비교 (투명 픽셀 처리와 마스크 변환은 비교 도구 측 복사 구현)와,
C#의 실제 `FilterEngine`이 해석한 값 (`BoundGenerator.TryValue`와 램프 평가)을 그대로 입력으로 사용한 전체 비교 (스칼라·램프 포함·
마스크·값 없는 픽셀·앞뒤 단계 조합)입니다. 비교 범위 밖인 맵에서 값을 계산하는 기능은 Rust에 없습니다.
스칼라 입력은 유한한 0..1로 제한됩니다. 스칼라 채널·마스크용 램프는 호출 측에서 회색으로 평가합니다. 마스크에서는 가시도로 변환하여 합성한 뒤 숨기는 양으로 되돌립니다. 누락 좌표를 `None`으로 반환하면 입력을 유지합니다.
맵 자체의 생성, 출처 대조, Anchor 의존성 해석, 램프 평가, 유효하지 않은 맵의 이유 표시는 이 모듈 밖에서 처리합니다.
Generator 단계는 행마다 `GeneratorInput::sample_row`를 1회 호출하고 (투명 픽셀이 16픽셀 이상 연속되면 나누어 호출) 값을 만든 뒤 픽셀별로 합성합니다.
기본 `sample_row`는 `sample`을 픽셀 1개씩 호출하므로 `sample`만 있는 입력도 그대로 사용할 수 있습니다. 투명 픽셀 (마스크 제외)의 값은 이전처럼 사용하지 않습니다
(짧은 틈의 픽셀은 값을 생성한 뒤 버림). 행 값의 작업 영역 (블록 너비 × 16바이트)은 픽셀 버퍼가 아니므로 예산에 포함하지 않습니다.
문서 평가는 바인딩된 Generator의 행 평가 (SIMD 경로)에 전달하며 결과 바이트는 픽셀별로 `sample`을 호출했을 때와 같습니다 (`filter/generated.rs` 테스트가
모든 종류·램프 혼색·색상·스칼라·마스크를 이 CPU의 모든 경로에서 기존 픽셀별 평가를 그대로 작성한 참조 구현과 비교). 거친 평가 (보폭을 두고 샘플링)는 픽셀이
떨어져 있으므로 픽셀 1개씩 처리하는 방식을 유지합니다.

예산은 반환 이미지와 동시에 살아 있는 작업 버퍼의 합계입니다. 입력, 샘플러 소유 메모리, 메타데이터, 스레드 스택은 포함하지 않습니다.
C#의 블록 픽셀 추정치에 세로 패스의 행 누적과 반환 이미지를 더하므로 C# 작업 예산과 수치가 같아도 거부 경계는 일치하지 않습니다.
최대 32단계·활성 단계 반경 합계 512픽셀은 C#과 같습니다. 예산으로 동시 실행 수를 제한합니다 (주 처리는 반환 이미지를 뺀 나머지, 통계 스캔은 반환 이미지를
할당하기 전이므로 전체 예산까지). rayon의 호출 측 풀을 사용하므로 `ThreadPool::install`로 병렬 처리 수를 지정할 수 있습니다. 각 픽셀의 연산 순서는
병렬 처리 수에 영향을 받지 않습니다.

취소 플래그는 블록·행·단계 경계에서 확인합니다 (흐림과 선명하게는 박스 흐림의 가로·세로 각 패스와 출력도 행별로, 점 단계·Generator
샘플링·통계 스캔도 블록별·행별로 확인). 마지막 검사를 통과한 후 완성 이미지를 반환하므로 계산이 끝난 뒤 플래그를 켜도 취소됩니다.
잘못된 설정, 예산 부족, 취소 시에는 완성 이미지를 반환하지 않고 입력을 변경하지 않습니다.
C# FilterEngine 자체에는 취소 토큰 인자가 없으므로 취소 플래그는 이 API가 추가한 계약입니다.

픽셀 계산 (강도에 따른 혼합·테이블 단계·노이즈·박스 흐림·흐림과 선명하게의 마지막 행)은 x86_64에서 실행 시 AVX2·SSE4.1을 판별하여 사용하고 aarch64에서는 NEON을 사용합니다 (`filter/rows.rs`).
결과 바이트는 픽셀별 공식과 같으며 다른 CPU에서는 픽셀별 공식을 그대로 사용합니다. 나눗셈 반올림 (박스 흐림 평균과 미리 곱한 값을 되돌리는 나눗셈)은 f64 연산이 정수 몫의
버림과 일치하는 범위 (분자가 약 2²⁶까지·몫 경계와의 거리가 반올림 오차보다 충분히 큼: 박스 흐림은 0.5/(2r+1) 이상, 미리 곱한 값을 되돌리는 나눗셈은 1/(2·qa) 이상)에서만 수행합니다. 환경 변수 `YOLU_SIMD`로 하위 경로를 선택할 수 있습니다.

## UV 이음새를 넘는 이웃 참조 단계 (`seams.rs`)

`Options::seams`를 전달하면 이웃 참조 단계 (영향 반경 1 이상)는 UV 이음새를 넘어 읽습니다. 단계 전에 입력 복사본에서 아일랜드 바깥 띠의 텍셀을 이음새 띠 매핑 (`geometry::SeamBand`)이 가리키는 상대 아일랜드의 픽셀로 채웁니다 (이중 선형. 알파를 미리 곱해 혼합하고 탄젠트 공간 노멀은 이음새 방향에 맞춰 XY를 회전). 단계 후에는 아일랜드 밖을 입력 그대로 복원합니다 (내보내기 패딩과 별개). 점 단계는 그대로입니다. 상대 픽셀이 블록 입력 밖에 있으면 해당 점을 포함하는 작은 사각형을 이전 단계까지 평가하여 읽으므로 블록 분할 방식에 따라 같은 픽셀의 값이 바뀌지 않습니다. 이음새 띠 매핑·아일랜드 맵·토폴로지 대응은 처음 필요할 때 만듭니다 (거친 평가도 블록을 병렬 처리하기 전에 한 번 만들어 각 블록에 전달합니다. rayon 스레드 안에서 만들 때는 병렬화하지 않고 같은 순서·같은 값으로 차례대로 만들므로 생성 중에 다른 블록이 같은 데이터를 기다리며 멈추지 않음). 문서 설정 `filter_seams` (기본값 켜짐. 끄면 원본 버전 32)가 모델 UV 토폴로지가 있는 문서에서 이 기능을 사용합니다.

## 0.5.0 단계 (종류 70〜79)

값 테이블 2종 (히스토그램 스캔·히스토그램 범위)은 점 처리 (`point`의 256개 테이블), 이웃 참조 8종은 `spatial.rs`입니다. 모두 스칼라 단일 경로
(SIMD를 사용하지 않음)이므로 `YOLU_SIMD` 경로와 관계없이 같은 바이트입니다. 이웃 값 누적은 f64 (이중 선형·평균) 또는 정수 (박스 흐림·빈도)를 사용합니다.

| 종류 | 공식 | 영향 반경 | 값 종류 |
|---|---|---|---|
| 히스토그램 스캔 | 폭 w = max(1 − contrast, 1/255), out = clamp((in − (position − w/2)) / w) | 0 | 스칼라·마스크 |
| 히스토그램 범위 | out = clamp(position + (in − 0.5) × range) | 0 | 스칼라·마스크 |
| 슬로프 흐림 | 기본 제공 값 노이즈 (Generator 값 노이즈와 같은 hash, 격자 변 scale 픽셀)의 기울기 방향으로 현재 위치와 intensity × k / samples (k = 1〜samples) 위치를 이중 선형 (알파를 미리 곱한 값)으로 읽어 평균·최솟값·최댓값 계산 | ceil(intensity) | 색상·스칼라·마스크 |
| 방향성 흐림 | 각도 방향 (다항식 sin·cos)의 양쪽 ±distance를 2·ceil(distance)+1개 점 (최대 512)에서 읽어 알파를 미리 곱한 상태로 평균 | ceil(distance) | 색상·스칼라·마스크 |
| 왜곡 | 값 노이즈 기울기 ÷ 1.875 × intensity (길이는 최대 intensity)만큼 옮긴 위치를 이중 선형으로 읽음 | ceil(intensity) | 색상·스칼라·마스크 |
| 형태학 | 원형 범위 (dx² + dy² ≤ r²)의 최댓값·최솟값 (행별 최댓값·최솟값 테이블로 조회. 투명 픽셀은 세지 않음) | radius | 스칼라·마스크 |
| 가장자리 검출 | width로 흐림 (흐림과 같은 박스 3회), Sobel 강도 / (4 × 255)를 0〜1로 변환, threshold 이하는 0 | width + 1 | 스칼라·마스크 |
| 하이패스 | out = 0.5 + in − 흐림(in, radius) (흐림 단계와 같은 값). A는 원래 값 | radius | 색상·스칼라·마스크 |
| 중앙값 | 정사각형 범위의 아래쪽 중앙값 (RGB는 A가 양수인 픽셀만, A는 전부. 가장자리는 가장자리 픽셀 반복) | radius | 색상·스칼라·마스크 |
| 글로우 | out = in + 흐림(max(in − threshold, 0)) (알파를 미리 곱한 값) × intensity. A는 원래 값 | radius | 색상 |

이미지 밖에서는 가장자리 픽셀을 반복하고 읽는 위치를 영향 반경 안으로 제한하므로 블록 분할 방식·영역·병렬 처리 수가 달라도 같은 픽셀은 같은 값이 됩니다. A를 바꾸지 않는 단계의 투명 픽셀과
결과 A가 0이 되는 픽셀은 입력 RGB를 유지합니다. 작업 메모리는 종류별로 추정하며 (`spatial::working_bytes`), 흐림과 마찬가지로 예산 및 영향 반경 합계 512 검사에 포함됩니다.
거친 평가 (`coarse`)에서는 픽셀 단위 길이·반경·노이즈 크기를 보폭으로 나눕니다.
