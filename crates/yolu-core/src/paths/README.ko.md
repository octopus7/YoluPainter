# 편집 가능한 경로

`CanvasPath`는 캔버스상의 점을, `SurfacePath`는 삼각형 번호와 무게중심 좌표로 이루어진 점을 가집니다. `PathBrush`의 반경은 전자에서는 픽셀, 후자에서는 모델 공간 단위입니다. `material: None`은 기준 채널과 브러시 색상을 뜻하며, `Some`은 중복 없는 표준 6채널 조합입니다. 구조체를 직접 편집할 수 있으며 평가 진입점에서 반드시 검증합니다. 아주 작은 음수 무게중심 좌표는 `PathPoint::new`에서 정규화합니다.

`render_canvas`와 `render_surface`는 `Options`의 크기·한도에 따라 채널별 새 `Surface`를 반환합니다. 문서·선택 영역·Undo는 건드리지 않습니다. 실패하거나 취소되면 결과 전체를 반환하지 않습니다. 호출자는 성공한 결과와 경로를 함께 확정해야 합니다. 계산한 픽셀을 기존 레이어에 넣는 작업, 저장, Undo는 이 API에 포함되지 않습니다.

레이어는 여러 경로의 목록(`LayerPathEntry`: 이름·표시 여부·경로)을 가지며 `render_list`가 표시할 경로를 아래부터 순서대로 같은 작업 면에 그립니다(뒤의 경로가 위에 놓이며, 지우개·문지르기 경로는 앞선 경로의 픽셀에 작용). 목록의 경로는 같은 종류(2D 또는 3D)·같은 기준 채널·(3D의 경우)같은 지문을 사용해야 합니다.

점별 접선(`Tangent`): 구간 양 끝이 매끄러우면 아래의 Catmull–Rom을, 한쪽이라도 모서리나 핸들이면 3차 베지어를 사용합니다(`bezier.rs`. 매끄러운 끝의 제어점은 해당 끝의 Catmull–Rom 미분에서 구함). 모서리·핸들이 없는 경로는 이전과 같은 바이트로 그립니다. 핸들은 점에서의 방향이며 3D에서는 기본 포즈 모델 공간을 사용합니다.

종류(`PathStyle.kind`): 스트로크(아래의 원형 브러시)·지우개(같은 스트로크로 지움)·문지르기(같은 곡선으로 기존 픽셀을 끌어옴. 3D에서는 표면의 dab 전체를 칠하고 UV 이음새에서 이전 위치를 잊음)·채우기(`fill.rs`. 곡선 내부를 4 × 4 하위 샘플로 채움. 3D에서는 하나의 UV 아일랜드 내부에 한정)·리본(`ribbon.rs`. 에셋 이미지를 방향에 맞게 회전한 직사각형 dab으로 나열하거나 늘림. 이미지는 `Options::images`에서 가져옴)이 있습니다.

대칭(`PathStyle.symmetry`): 2D는 캔버스 대칭(세로·가로·양쪽·방사형·선대칭, 선대칭은 Rust 구현만 지원), 3D는 기본 포즈 모델 공간의 미러 평면입니다. 반사된 경로는 보관하지 않고 그릴 때 만들어 원래 경로 바로 뒤에 같은 작업 면에 그립니다. 3D 원형 브러시 끝에는 가장자리 안티앨리어싱(`PathBrush::anti_alias`)이 적용되며, 브러시 끝 이미지가 있는 경로에는 적용되지 않습니다.

숨겨진 면(`Options::hidden`): 3D 경로로 그리지 않을 면을 삼각형 번호별 표시로 전달합니다. 표시된 면에는 광선을 쏘지 않고 dab도 확장하지 않습니다(경로 점의 삼각형 번호와 지문은 제외하기 전 형상을 유지). 아무것도 숨기지 않으면(`None` 또는 표시가 하나도 없음) 제외할 면이 없는 그리기 방식과 같은 바이트가 나옵니다. 표시 수가 삼각형 수와 다르면 `Error::ModelMismatch`로 거부합니다.

머티리얼 조합: 텍스처 세트에 포함된 여러 머티리얼은 `MaterialSet`으로 전달하고 `rebind_surface_path`는 그 조합의 모든 삼각형에 경로를 다시 배치합니다. 머티리얼이 하나인 조합은 기존 머티리얼 번호를 사용한 결과와 같습니다.

2D는 구심 Catmull–Rom 폴리라인을 기존 원형 브러시에 전달합니다. 3D는 현재 삼각형에서 위치를 복원하고 곡선을 노멀 방향으로 투영한 뒤 기존 표면 dab을 그립니다. 투영할 수 없는 샘플은 그리지 않고 `gaps`에 집계합니다. dab 거부 또는 0..1 범위를 벗어난 커버리지는 오류입니다. 지문은 삼각형 수·순서·렌더러·슬롯·UV로 만들며 위치와 포즈는 포함하지 않습니다. 일치하지 않으면 이유와 함께 거부합니다.

## 호환성과 한도

테스트가 읽는 `tests/golden/paths`는 0.4.x까지의 Unity 브리지(태그 `0.4.0`) 원문으로 만든 인공 데이터의 정답을 이어받은 것입니다. 다시 만들 때는 Rust 출력으로 만듭니다. 수록된 입력 25개·면 27개의 전체 바이트, 3D dab 수·누락 수, 지문용 형상 4개, 거부 사유 19건을 `cargo test -p yolu-core --test paths`로 대조합니다.

- 2D 입력은 빈 경로·1점·2점·곡선·중복·캔버스 밖·필압 0·채널 조합입니다. 지우개 입력은 빈 작업 면에서 지우므로 모든 픽셀이 0으로 남는지만 확인합니다(지우개 의미 자체를 대조하는 것은 아님).
- 3D 입력은 평면 위의 빈 경로·1점·2점·곡선·중복·채널 조합 외에 떨어진 평면 사이(누락 발생), 높이가 다른 평면, 노멀이 맞지 않는 급경사 면(노멀 판정과 아래에서 쏘는 광선), 필압 0인 점(dab 생략, 브러시 필압 할당 2종)입니다. 급경사 면과 지문 형상에는 서로 다른 렌더러·슬롯이 포함됩니다.
- 지문은 평면·떨어진 평면·급경사 면(렌더러 1·슬롯 2)·렌더러와 슬롯이 0이 아니거나 음수이고 UV가 소수·음수·-0.0인 형상, 총 4개에서 C#과 일치시킵니다. 위치와 포즈가 지문에 포함되지 않는지는 위치만 옮긴 면으로 별도로 확인합니다.
- 거부 사유는 한도·샘플 수·지문 불일치·2D 점·브러시·조합 외에 3D 지문 길이(빈 값·128·129자 및 UTF-16으로 128·130단위가 되는 이모지 문자열)·점 수(4096·4097)·반경 상한·비표준 채널·중복 조합입니다.

워커 수는 C#과 대조하는 27개 면에서 1·2·4로 바꾸어 모든 바이트가 일치하는지 확인합니다. 다만 대조용 캔버스는 64²이고 3D에서는 dab 하나의 차폐 검사 광선이 1024개에 미치지 않아 어떤 워커 수에서도 순차 경로를 사용합니다. 따라서 3D는 별도 테스트에서 256² 캔버스·반경 0.2인 dab(dab당 8000개가 넘는 광선)처럼 여러 워커에 분산될 크기에서도, 가림판을 사이에 둔 면으로 1·2·4의 결과가 일치하는지 확인합니다(C# 대조가 아닌 자기 일치). 2D는 병렬 타일 임계값을 0으로 설정해 평소에는 병렬화되지 않는 작은 캔버스도 병렬 경로를 통과시킵니다.

수록된 정답을 만들 때 Unity의 `Bounds.SqrDistance`는 대체 공식을 사용했습니다. 네이티브 `Vector3.Slerp`는 Mono만으로 실행할 수 없으므로 노멀이 같은 경우에만 항등 사상으로 대체하고 그 외에는 거부했습니다(해당 생성기는 남아 있지 않음). **서로 다른 노멀을 잇는 3D 경로는 구현되어 있지만 Unity 실행 환경과의 전체 바이트 일치는 검증하지 않았습니다.** Rust의 모서리를 가로지르는 테스트는 결정성을 확인하는 것이며 C# 대조가 아닙니다.

소스와 스트로크 한도는 모든 채널의 합계입니다. 현재의 단일 채널 브러시를 채널별로 유지하므로 조합의 스트로크 한도에는 커버리지도 채널 수만큼 포함됩니다. C#은 커버리지를 공유하므로 이 경우 Rust가 더 보수적으로 거부합니다. 조합의 합계 검사는 각 입력점·픽셀 처리 후 실행하며, 중간 할당까지 포함하는 엄격한 프로세스 메모리 상한은 아닙니다. 각 브러시 내부에서는 개별 한도를 먼저 검사합니다. 단일 채널의 소스·되돌리기 한도에 따른 거부 사유는 C#과 대조합니다. 채우기(종류 `Fill`)는 다각형 점·하위 샘플 행별 교차점·3D 곡선과 아일랜드 격자 캐시를 리본에서 수집한 픽셀처럼 스트로크 한도에 포함합니다(항목당 추정 크기로 계산). 초과하면 `StrokeBudgetExceeded`로 거부합니다.

2D는 합계 400만 샘플, 3D는 구간별 100만 분할을 상한으로 합니다. C# 정수 변환에서 범위를 벗어나는 극단적인 입력도 Rust에서는 명시적으로 거부합니다. 취소는 Rust에서 추가한 기능이며 각 샘플·dab·픽셀·결과 반환 전에 확인합니다. 기존 브러시나 표면 dab을 한 번 호출한 내부에서는 중단하지 않습니다. 확인 위치별 횟수를 기록하고 각 위치의 첫 번째·두 번째·중간·마지막 확인에서 플래그를 설정하는 단일 워커 테스트(시간에 의존하지 않음)로 해당 확인에서 Canceled를 반환하고 이후 확인으로 진행하지 않으며 결과를 반환하지 않는지 검사합니다. 병렬 실행에서도 픽셀 연산 순서는 바꾸지 않고 채널은 입력 순서대로 평가합니다.
