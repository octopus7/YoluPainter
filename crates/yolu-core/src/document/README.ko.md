# 문서의 레이어 조작

`Document`는 단일 작성자가 편집합니다. 스트로크 중에는 구조 편집·변형·크기 변경·Undo/Redo를 거부합니다.

- `set_layer_locks` / `change_layer_locks`: 투명 영역·이미지·위치·전체 잠금입니다. 상위 그룹의 잠금도 적용됩니다. 거부 시 `CoreError::LayerLocked`로 대상과 잠금 소유자를 반환합니다.
- `topmost_of`: 다중 선택의 중복과 선택한 그룹에 포함된 하위 항목을 제외합니다. 삭제·복제·표시·이동·한 단계 이동은 여러 항목이어도 Undo 한 번입니다.
- `transform_layer` / `transform_layers`: 모든 채널과 마스크를 이동·회전·확대/축소합니다. 선택 영역이 있으면 그 부분만 들어 올리고 선택 영역도 같은 단계에서 이동합니다. `transform_layer_region`은 명시한 영역과의 교차 부분을 옮기며 선택 영역 자체는 움직이지 않습니다.
- `resize_image`: 최근접·쌍선형·영역 평균으로 이미지와 선택 영역의 크기를 변경합니다. 투명 픽셀의 RGB와 노멀 정규화를 보존하고 Height → Normal 강도를 배율에 맞춥니다. `resize_canvas`는 픽셀을 보간하지 않고 지정 위치에 배치한 뒤 캔버스 밖을 잘라냅니다. 둘 다 `ResizeReport`를 반환합니다 (축소로 제외된 저장된 선택 영역 수는 기록을 지우는 호출자가 알릴 수 있도록 `dropped_saved_selections`에 문장 대신 수치로 기록). 레이어·마스크·선택 영역은 같은 경로로 만듭니다 (타일별로 처리하며 읽을 원본이 없으면 건너뛰고, 전체가 같은 균일 색이면 계산 없이 채움. 묶음마다 취소 확인). 효과와 경로는 다음과 같이 처리합니다. `resize_image`는 흐림·선명화 반경을 가로세로 배율의 기하평균에 맞추며 (상한으로 제한한 부분은 보고서에 기록), 2D 경로는 점과 브러시 반경을 조정해 다시 그립니다 (C# `Resampled`와 동일). 모델 위의 경로는 유지하고 `ResizeReport::surface_path_layers`에 레이어를 나열합니다. `resize_canvas`는 2D 경로 점을 픽셀과 같은 양만큼 이동해 다시 그리며 (C#에 해당 작업이 없어 Rust에서 자체 결정), 반경은 바꾸지 않습니다. 둘 다 새 크기에서 단계의 도달 반경·작업 메모리가 상한을 초과하면 아무것도 변경하지 않고 거부하며, 평가 캐시는 모두 버립니다. `resize_image`의 실패 가능한 전반부 (결과 사본 생성)는 `prepare_resize_image`, 후반부 (Undo 1회 단계로 삽입)는 `commit_prepared_resize`로 나눠 사용할 수 있습니다. 여러 문서를 “전부 변경하거나 1개도 변경하지 않기”로 처리할 때 먼저 모두 준비하면, 중간 문서가 예산 때문에 거부되어도 앞 문서의 기록 (Undo·Redo)을 쌓거나 버리지 않습니다. 준비 후 문서가 변경되었거나 다른 문서의 준비 결과를 넣으려 하면 아무것도 변경하지 않고 거부합니다.
- `merge_down` / `merge_visible` / `merge_group` / `merge_layers`: 병합 결과와 원래 합성을 비교하고 허용 오차를 초과하면 거부합니다. `LayerMergeReport`는 비교한 픽셀 수·변경된 픽셀 수, 저장 값의 최대 차이·보이는 차이를 반환합니다. 기본 허용 오차에 해당하는 값은 `Document::MERGE_ROUNDING_TOLERANCE` (2)이며, 255는 모든 차이를 허용합니다. 병합은 효과와 경로를 픽셀로 베이크합니다 (결과는 효과를 보유하지 않으며 `LayerMergeReport::notes`에 표시). 적용되지 않는 효과 (사용할 맵이나 Anchor가 없는 Generator·배치할 수 없는 데칼)가 있으면 버리지 않고 `CoreError::InactiveEffect`로 거부합니다. 아래 레이어의 마스크를 유지하는 경우 (분리 병합이 아닌 경우)에는 효과와 함께 결과로 이동하므로 검사하지 않습니다. 분리 병합에서는 픽셀로 베이크하므로 해당 마스크의 적용되지 않는 Generator도 거부합니다 (C#은 이를 검사하지 않고 알림 없이 버림. Rust는 의도적으로 거부하며 `seam_ops` 테스트로 확인). 위 레이어의 Anchor는 결과로 이동하고 아래 레이어의 Anchor는 사라집니다 (이를 읽는 단계는 이유를 알리고 입력을 그대로 통과시킴).
- `set_rulers` / `move_rulers` / `set_snap_ruler`: 레이어 (그룹 포함)에 붙은 자 (직선 자·평행선·동심원·투시·대칭, 1개 레이어당 최대 64개)를 변경합니다. 생성·이동·삭제·다른 레이어로 이동·설정 변경·스냅할 특수 자 표시가 각각 Undo 1회이며 픽셀과 합성은 변경하지 않습니다. `coalesce`를 지정하면 드래그나 슬라이더를 1회로 묶습니다. `rulers_seen_from`은 그릴 레이어에서 보이는 자 (표시 범위·자 표시 여부·소유자와 상위 항목의 눈 상태)를, `snapping_special_rulers`는 적용되는 특수 자 (2D와 3D 각각 표시된 1개)를 반환합니다. 복제된 자에는 새 ID가 부여됩니다. 병합은 제거되는 레이어의 자를 결과 레이어로 모두 옮기며 (64개를 초과할 때만 거부), `resize_image`·`resize_canvas`는 2D 자의 점만 픽셀과 같이 이동합니다. 스마트 머티리얼에는 자를 포함하지 않으며 복사할 때 제외하고 알립니다.

- 레이어 세트 (`layer_sets.rs`): 문서 안의 이름이 지정된 레이어 묶음입니다. 문서의 레이어 순서는 1개의 배열로 유지하며, 레이어가 속한 세트는 `layer_set_of`로 읽습니다 (그룹 하위 항목은 상위 항목과 같음). 합성은 레이어 세트마다 해당 레이어만으로 수행하고, 채널의 최종 결과는 `channel_output`의 할당 (`set_channel_output`, 할당이 없으면 해당 채널의 기본값)이 가리키는 레이어 세트의 합성입니다. `add_layer_set`·`duplicate_layer_set`·`rename_layer_set`·`move_layer_set`·`remove_layer_set` (마지막 1개는 삭제할 수 없으며 삭제한 세트에서 출력하던 채널은 할당 없음으로 변경)·`move_layers_to_set`·`add_layer_in_set`는 각각 Undo 1회입니다. 순서 변경·부모/자식·그룹화·병합은 같은 레이어 세트 안에서만 가능하며 세트를 가로지르는 요청은 거부합니다 (`children_in_set`은 레이어 세트별 순서를 계산). `insert_layers_from`·`insert_layers_as_layer_set`는 다른 문서 (PSD를 읽은 문서 등)의 레이어를 복사해 삽입합니다. 효과는 해당 레이어가 속한 세트 내부만 읽습니다. 레이어 세트가 1개이고 이름이 비어 있으며 모든 채널이 그곳에 할당된 문서 (`has_default_layer_sets`)는 합성과 저장 바이트 모두 레이어 세트가 없었을 때와 같습니다. 형식은 `docs/YLP_FORMAT.md`의 “layer_sets와 route”에 있습니다.
- `copy_mask` / `set_masks` / `move_mask` / `add_black_layer_mask` / `paste_into_mask` (`mask_ops.rs`): 레이어 마스크 전체 사본 (`MaskCopy`: 표면·활성화·반전·밀도·마스크 필터. `Anchor`는 복사하지 않음)을 다른 레이어의 마스크로 지정하고, 다른 레이어로 이동하고, 검은 마스크를 추가하고, 클립보드 이미지를 마스크에 붙여넣습니다. 모두 Undo 1회이며 변경되는 쪽 (대상과 이동 원본)의 “모두” 잠금으로만 거부합니다 (복사 원본의 잠금은 검사하지 않음). 이동은 `Anchor`까지 옮기고 복사는 대상의 기존 `Anchor`를 유지합니다. 캔버스 크기가 다른 마스크는 붙여넣을 수 없습니다.

레이어 픽셀의 복사·잘라내기·붙여넣기와 교체 (`clipboard.rs`), 여러 편집을 Undo 1회로 묶는 `batch` (`batch.rs`)입니다.

- `save_selection` / `rename_saved_selection` / `delete_saved_selection` / `recall_saved_selection` / `restore_saved_selections`: 이름을 지정해 문서에 남긴 선택 영역입니다 (`saved_selections`: 최대 32개, 이름은 앞뒤 공백 없이 1〜256자·제어 문자 없음·중복 없음). 저장·이름 변경·삭제·현재 선택 영역과의 조합 (`SelectionCombine`)으로 불러오기는 모두 Undo 1회이며 픽셀을 변경하지 않습니다. 같은 이름으로 다시 저장하면 해당 위치를 교체하고, 내용과 이름이 모두 같으면 단계를 쌓지 않습니다. 기록 비용은 교체된 쪽에서 공유하지 않는 선택 영역의 크기입니다. 캔버스 크기 변경 (`resize_image` / `resize_canvas`)은 저장한 선택 영역도 현재 선택 영역과 같은 경로로 새 크기에 맞춰 다시 만들고 (축소 후 아무것도 선택하지 않게 되는 항목은 제거하고 보고서에 기록), 실행 취소하면 원래 크기로 돌아갑니다. 레이어 변형은 저장된 선택 영역을 움직이지 않습니다. `capture_snapshot` 사본은 같은 배열을 보유하며 원본의 편집을 따라가지 않습니다. `restore_saved_selections`는 불러온 직후 복원용입니다 (단계와 버전이 증가하지 않으며, 기록이 생긴 뒤 또는 규칙에 맞지 않는 배열은 거부).
- `copy_pixels` / `copy_merged`: 선택 영역 (없으면 전체)의 레이어 자체 픽셀 (마스크면 불투명 회색) 또는 보이는 합성을 값이 있는 픽셀의 경계 사각형인 `PixelClipboard`로 복사합니다. 문서는 변경하지 않습니다. 완전히 선택한 픽셀은 투명 픽셀의 RGB까지 복사하고, 부분적으로 선택한 픽셀은 미리 곱한 알파로 투명 쪽으로 혼합합니다. 사각형이 `max_bytes`를 초과하는 시점에 거부합니다 (타일은 Y, 다음 X 순서로 단일 작업 예산의 1/4, 최대 16 MiB씩 읽음).
- `cut_pixels`: 복사 후 `fill` (지우기)·`fill_mask` (보이기)로 지우며 Undo 1회입니다. 채우기·보정·그룹은 복사 전에 거부하고 이미지·투명 영역 잠금으로 거부합니다 (마스크는 전체 잠금만). 잠금 검사는 복사 전이므로 거부되면 아무것도 복사하지 않습니다.
- `paste_as_layer`: 새 래스터 레이어 (지정 채널만)를 추가하고 선택을 해제하는 Undo 1회 작업입니다. 복사 당시와 같은 크기의 문서에는 원래 위치에, 다르면 중앙에 배치하고 (정수 나눗셈은 0으로 반올림), 밖으로 나가는 부분은 잘라 그 수를 반환합니다. 외부 이미지는 `PixelClipboard::from_image`를 사용합니다 (해당 이미지 크기의 문서에서 복사한 것으로 취급). 기록 단계는 `Compound`입니다 (비용은 단계 합계 + 32. C#의 `CompositeCommand`).
- `replace_pixels`: 문서와 같은 크기의 이미지로 교체합니다. 투명 영역 잠금 상태에서는 색상만 교체합니다.
- `batch`: 내부 편집을 실제 문서에 적용하고 쌓인 단계를 `Compound` 1개로 묶습니다 (비용은 합계 그대로. C#의 `CompoundCommand`). 실패 (`Err`·panic)하면 쌓인 단계를 최신부터 되돌리고 Redo와 기록 바이트 수도 시작 전으로 복원합니다. 기록 정리는 종료 후 1회만 수행합니다. 내부에서는 스트로크·Undo·Redo·기록을 지우는 쓰기 (불러오기용 직접 쓰기)를 `CoreError::BatchActive`로 거부하며 중첩할 수 없습니다 (`ensure_loadable`이 진입점으로 레이어·채널 검증보다 먼저 수행됨. C# `RefuseInBatch`와 같은 위치이므로 배치 안에서 잘못된 채널이나 없는 레이어를 전달해도 거부 이유는 `BatchActive`).
- 거부는 `CoreError::Clipboard(ClipboardRefusal)`입니다. 경로 레이어의 `cut_pixels`는 픽셀 쓰기와 동일한 경로 레이어 거부 (잠금 뒤)를 그대로 반환하며 `ClipboardRefusal`로 감싸지 않습니다 (C# `CutPixels`도 거부).

`tests/reference/clipboard_golden.rs`는 0.4.x까지의 Unity 브리지 C# Core 출력과 모든 바이트를 대조합니다 (1019개 사례를 병렬도 1과 4로 실행). 사례에는 레이어·마스크·6개 채널·4가지 선택 영역·4가지 상한의 복사, 레이어 속성을 바꾼 문서의 병합 복사, 5가지 잠금과 타입 거부의 잘라내기, 대상 크기 3가지·선택 영역·그룹 내부·단일 작업 및 픽셀 예산 거부의 붙여넣기, 잠금·선택 영역·`within_selection`의 교체, `batch`의 성공·실패·금지가 포함됩니다. 출력은 결과 타입 (잠금은 거부된 레이어와 소유자), 사본·기록 바이트 수·문서 전체 상태 및 Undo·Redo 이후 상태입니다. 정답은 사례별 SHA-256으로 `golden/clipboard/index.txt`에 저장합니다 (불일치 시 `CLIPBOARD_GOLDEN_DUMP`로 Rust 출력 자체를 내보냄). 이 대조 범위에 포함되지 않는 것은 거부 이유 문장 (타입만 비교), `SourceBudget`이 소진되는 경계의 세부 수치 (대상 예산을 “현재 픽셀 + 8”로 설정한 1가지 경우만 포함), 병렬 픽셀 계산의 결과 일치 외의 속도입니다.

픽셀 쓰기 진입점은 기록 전에 `Document::pixel_write_guard` (잠금으로 거부하고 투명 영역 잠금으로 알파를 보존할지 반환)를 거쳐 반환 값을 `StrokeState::new`의 `keep_alpha` 또는 채우기 식 (`fill_pixel`)에 전달합니다. 두 경우 모두 `keep_alpha`가 필수 인자이므로 새 진입점에서 전달을 빠뜨리면 컴파일에 실패하지만, 보장 범위는 여기까지입니다 (`false`를 전달하는 진입점이나 `edit_material_region` 클로저에서 인자를 무시하는 진입점은 통과하며, `edit_region`·`edit_region_tiles`는 검사를 거치지 않고 호출할 수 있음). 진입점 추가 누락을 자동으로 발견하는 장치는 없으며 아래 `write_entries` 표에 추가하는 절차만이 방어 수단입니다. 비활성 채널을 활성화하거나 표면을 만들기 전에 거부합니다 (거부 후 아무것도 남지 않음). 마스크 쓰기 진입점은 전체 잠금으로만 거부합니다 (`refuse_lock`).

검사 순서는 C#과 같습니다. 픽셀 진입점은 래스터 레이어인지 타입 검사부터 하고 잠금을 확인하므로 타입 거부 시 잠금 이름을 표시하지 않습니다 (`begin_stroke`의 4개 진입점만 보정·그룹 레이어에서는 잠금이 먼저임. C# `BeginStroke`가 표면을 얻는 `GetChannel`의 타입 거부를 잠금 검사 뒤에 두기 때문이며 채우기 레이어만 타입이 먼저). 비활성 채널 거부는 단일 채널의 영역 채우기 (`fill`·`gradient`·`begin_triangle_fill`)에서는 잠금보다 먼저, 단일 채널 스트로크에서는 잠금 뒤에 수행합니다. 마스크 쓰기 및 마스크 변경 진입점 (`set_layer_mask_*`·`remove_layer_mask`)은 마스크 유무를 잠금보다 먼저 확인하므로 마스크가 없는 레이어는 어떤 잠금이든 “마스크 없음”으로 거부합니다. `add_layer_mask`는 반대로 이미 마스크가 있는지 먼저 확인합니다. 경로 (`LayerPath`)로 그린 레이어에 직접 쓰기 (스트로크·채우기·그라데이션·머티리얼)는 다음 다시 그리기에서 사라지므로 거부합니다. 이 거부는 잠금 뒤입니다 (C#은 `RefuseLockedPixels` → `RefusePathLayer` 순서). 이동 작업 (`transform_layer(s)`)만 경로 레이어 거부가 잠금보다 먼저입니다 (C# `RequireTransformable`). 경로 레이어의 마스크에는 그릴 수 있습니다. 효과 설정을 바꾸는 진입점 (단계·Anchor·읽기 대상·채우기 이미지와 투영 및 그라데이션·값·경로 교체)도 잠금을 확인합니다. 픽셀을 변경하지 않는 설정은 전체 잠금만, 픽셀을 다시 결정하는 설정은 이미지·투명 영역 잠금으로도 거부합니다. 변하지 않는 설정 (`set_fill_value`의 동일 값·`set_channel_enabled`의 동일 상태)은 잠금 검사 전에 아무것도 하지 않고 반환합니다 (C#과 동일). `set_fill_value`는 채우기 레이어인지 타입 검사도 잠금보다 먼저 합니다. 조합 (material)이 없는 경로 레이어는 경로가 그리는 채널을 비활성화할 수 없습니다 (조합이 있는 경로는 어떤 채널이든 비활성화 가능).

| 진입점 | 검사 |
| --- | --- |
| `begin_stroke` / `begin_stroke_in` / `begin_brush_stroke` | `pixel_write_guard` |
| `begin_material_stroke` / `begin_material_brush_stroke` | `pixel_write_guard` (모든 채널이 `keep_alpha`) |
| `begin_triangle_fill` / `begin_material_triangle_fill` | 위 진입점을 거쳐 반환된 `keep_alpha`를 삼각형 식에 전달 |
| `fill` / `fill_material` / `gradient` / `gradient_material` | `pixel_write_guard` (영역 식은 `fill_pixel`) |
| `begin_mask_stroke` / `begin_brush_mask_stroke` / `begin_mask_triangle_fill` / `fill_mask` / `gradient_mask` / `apply_smart_mask` | `refuse_lock(ALL)` |

`tests/edit/docops.rs`의 `every_pixel_write_entry_goes_through_the_layer_locks`는 진입점마다 레이어 자체 및 상위 그룹의 잠금으로 거부하는지, 거부 후 아무것도 변경되지 않는지 (기록·변경 번호·모든 채널의 활성 상태와 픽셀·마스크), 잠금을 해제하면 같은 진입점이 통과하는지 확인합니다. 진입점을 추가하면 `write_entries`에도 추가합니다.

투명 영역 잠금은 그리기·채우기의 알파를 고정하며 알파 0의 RGB도 그대로 남깁니다. 지우기와 선택 부분 변형은 거부합니다. 이미지 잠금 상태에서도 레이어 전체의 정수 픽셀 이동과 마스크 그리기는 가능합니다. 위치 잠금은 변형을 거부합니다. 전체 잠금에서도 이름·표시·레이어 순서·복제·삭제는 가능합니다. 불러오기용 `import_tile` / `set_channel_pixel`은 잠금 검사를 우회하므로 불러오기 마지막에 `set_locks_for_load`를 사용합니다. 많은 타일을 불러올 때의 `import_tiles_with`는 `import_tile`을 순서대로 호출한 것과 결과·오류가 같으며 타일 내용 기록과 패킹을 워커에 분배합니다.

원자적인 다중 작업은 타일을 공유하는 준비용 상태 (`Document::edit_copy`)에서 계산하고 성공한 상태만 교체합니다 (`State`). Undo는 다시 계산하지 않고 원래 상태로 복원합니다. `edit_copy`와 `State::take`는 `Document`의 모든 항목을 `..` 없이 나열하며, 준비용으로 복사하지 않거나 교체하지 않는 항목에는 이유를 적어 두었습니다. `Document`에 항목을 추가하면 여기서 컴파일에 실패하므로 준비용 문서만 바뀌고 실제 문서에 반영되지 않는 상황이 조용히 발생하지 않습니다. 교체 대상은 레이어·치수·Normal 설정·선택 영역·이름을 지정해 저장한 선택 영역뿐이며, 채널 표·기록·진행 중인 스트로크 (머티리얼 스트로크와 삼각형 채우기 포함)·변경 기록·예산·수동 ID 색상은 실제 문서의 것을 유지합니다 (ID 색상은 레이어 작업·변형·크기 변경으로 바뀌지 않음). 효과 상태 (`effects`)는 입력 (메시 맵·이미지·모델 루트), 예산, 블록 크기만 준비용으로 복사합니다 (병합·변형·크기 변경은 준비 과정에서 단계를 추가하고 합성해 전후를 비교하므로 입력이 없으면 실제 문서와 다른 외관으로 비교하게 됨). 평가 캐시·원본 픽셀 시계·Anchor 해석 서명은 복사하거나 교체하지 않습니다 (준비용 문서의 시계는 0부터 다시 세므로 가져오면 서로 다른 내용에 같은 키가 붙을 수 있음). 교체로 픽셀이 바뀐 레이어는 `swap_state`가 전후 동일 ID 레이어의 타일을 비교해 내용이 다른 타일만 원본 픽셀 시계를 진행시킵니다. 따라서 평가 출력은 새 픽셀에서 다시 생성하고, 픽셀을 바꾸지 않는 교체 (여러 레이어의 표시 전환·순서 변경·복제·삭제)는 캐시를 버리지 않습니다. 캔버스 크기를 바꾸는 교체는 모든 캐시를 버립니다. 복제는 효과와 Anchor에 새 ID를 부여하며 (사본 내부 Anchor를 읽는 단계는 사본을 읽음), 병합은 유지하는 마스크 단계에도 새 ID를 부여합니다 (`renew_effect_ids`).

변경 기록 (`changed_tiles`) 표시는 교체가 변경할 수 있는 레이어에만 전후 모두 붙입니다 (`Dirty`). 잠금만 바꾸는 경우에는 표시하지 않습니다 (단일 `set_layer_locks`와 동일). 삭제·복제·표시·한 단계 이동·병합·변형은 움직인 레이어 (그룹은 내용 포함), 크기 변경은 모든 레이어에 표시합니다. 클리핑 조합은 레이어가 1개라도 움직이면 표시합니다. 픽셀 예산과 단일 작업 예산은 별개입니다. 변형은 대상 타일의 원래 저장량 + 타일당 64바이트, 병합은 결과 저장량 + 타일당 64바이트를 단일 작업 예산으로 계산합니다. 레이어 복제는 공유한 픽셀도 픽셀 예산에 포함합니다. 취소 가능한 변형·이미지 크기 변경은 타일 묶음마다 취소 여부를 확인합니다.

C# `Resampled`는 기록 없는 별도 문서를 반환하지만 Rust의 크기 변경은 치수·픽셀·선택 영역·설정을 Undo 한 번으로 되돌려야 하므로 전후 저장량 (+128)을 기록 비용에 포함합니다. 이 비용은 문서의 2배 이상이므로 기록 예산 (기본 64 MiB)에 들어가지 않을 수 있습니다 (4096²의 레이어 1개를 2048²로 줄이면 전후 합계 약 80 MiB). 이때도 거부하지 않고 해당 크기 변경의 1단계만 예산을 초과한 채 유지하며 (이전 단계 삭제), `ResizeReport::history_over_budget`로 알립니다. 유지되는 것은 해당 단계가 최신인 동안뿐이며, 다음 편집의 정리에서는 일반 단계로서 삭제될 수 있습니다. 거부하는 방안 (4096²급 문서가 기본 예산에서 크기를 바꿀 수 없게 됨)과 알림 없이 Undo를 버리는 방안 (크기 변경을 되돌릴 수 없게 됨)은 채택하지 않았습니다. 픽셀 예산을 초과하거나 취소하면 기록을 버리지 않고 거부합니다. 해상도 변경 자체는 C#과 마찬가지로 레이어 잠금을 무시합니다. 너비·높이는 1〜8192입니다.

레이어 잠금 저장은 I/O 측 (yolu-io의 `core_bridge`)이 `locks()` (쓰기)와 `set_locks_for_load` (불러오기 완료 후 설정)로 연결하며 정본 버전 12의 배열로 읽고 씁니다. 문서는 효과 (필터·Generator·Anchor·채우기 이미지와 투영 및 그라데이션)와 경로를 보유하며 레이어 조작도 이를 처리합니다 (위의 각 항목과 `effects/README.md`의 “레이어 조작”). C# `BakeFilters` (레이어 1장의 효과를 픽셀로 베이크)에 해당하는 작업은 아직 core에 없습니다.

대조 정답은 0.4.x까지의 Unity 브리지 C# Core (태그 `0.4.0`의 `Runtime/Core`) 출력을 이어받은 것입니다. 다시 만들 때는 Rust 출력에서 생성합니다.

대조는 C# Core 인공 데이터 출력을 이어받은 정답을 대상으로 `cargo test -p yolu-core --test reference docops_golden::`로 실행합니다. 582개 사례를 병렬도 1과 4로 모든 바이트 비교합니다. 원시 픽셀·레이어 속성·부모/자식·마스크·선택 영역·합성·병합 보고서·기록 바이트 수·Undo/Redo를 비교합니다. 다만 이미지 크기 변경 (`resize`·`selected_resize`의 108개 사례)은 C# `Resampled`가 기록 없는 별도 문서를 반환하므로 변경 직후의 픽셀·속성만 비교합니다 (크기 변경의 Undo·기록·예산은 `tests/edit/docops.rs`와 `resize.rs` 테스트에서 확인). 잠금으로 병합이 거부되거나 허용되는 34가지 경우 (`mergelock`: 거부된 레이어·잠금 소유자·잠금, 거부 후 문서 불변, 상위 그룹 상속 포함)와 이동 픽셀의 경계 사각형 `transform_bounds` (`bounds`·`selected_bounds`)도 C#과 비교합니다.

효과·경로·잠금·레이어 작업의 연결 부분은 C# `PaintDocument`에 같은 시나리오를 통과시킨 출력을 이어받은 `tests/golden/seam.txt` (511개 사례)를 `cargo test -p yolu-core --test reference seam_golden::`가 병렬도 1과 4로 모든 바이트 비교합니다. 효과 설정 진입점 × 잠금 × 레이어/상위 그룹, 직접 쓰기 × 잠금 × 경로 레이어/래스터 레이어, 변형, 경로 레이어 추가, 복제·삭제·순서 변경·병합·이미지 크기를 결과 타입 (거부된 레이어·소유자·잠금), 기록 비용, 전후 및 Undo/Redo 문서 (모든 채널의 합성)까지 포함해 비교합니다. 대조는 인공 데이터·메시 맵 없음 범위이며 맵이 필요한 단계 (도형 그라데이션 등)는 “비활성 효과”로서의 처리만 비교합니다. 3D 경로 다시 그리기와 캔버스만 움직이는 `resize_canvas`는 C#에 없어 비교하지 않습니다. 의도적으로 C#과 다르게 처리한 부분은 3개입니다. 읽히는 Anchor가 병합으로 사라질 때의 변경을 병합 보고서에 포함 (C#은 누락), 분리 병합에서 아래 마스크의 비활성 Generator를 거부 (golden 사례는 분리되지 않는 형태), 이름을 생략했을 때의 기본 Anchor 이름 (golden은 이름을 전달)입니다.

잠긴 레이어에 그리기 (머티리얼 스트로크·영역 채우기·그라데이션 2종·삼각형 채우기·단일 채널 그라데이션·삼각형 채우기·스트로크, 마스크의 4종)는 C# 출력을 이어받은 `tests/golden/material.txt`의 `lock` (1024개 사례)·`lockmask` (512개 사례)를 `cargo test -p yolu-core --test reference material_golden::`가 병렬도 1과 4로 모든 바이트 비교합니다. 거부된 레이어·잠금 소유자·잠금, 거부 후 Undo/Redo 가능 여부와 모든 채널의 활성 상태·픽셀, 통과했을 때 Undo/Redo 후 픽셀까지 확인합니다. 레이어 픽셀은 투명 픽셀이 채널마다 다르며 (알파 식에 채널 번호 포함), 문서 선택 영역을 설정한 사례, 비활성 채널에 쓰는 단일 채널 사례, 마스크 없는 레이어 사례를 포함합니다. 채우기·보정·그룹 레이어에 쓰기에서 타입 거부와 잠금 거부 중 어느 것이 먼저인지는 `locknr` (576개 사례, 병렬도 1만)이 비교합니다.

이 대조 범위 밖인 사항: 예산 거부 (스트로크·픽셀·기록)는 C#과 비교하지 않습니다. 롤백 계산 방식이 C#과 다르므로 (Rust는 채널마다 커버리지를 보유하며 `rollback` 행이 C# 값과 배율을 고정) 잠금 상태에서 예산이 소진되는 경계는 C#과 일치하지 않습니다. Rust 테스트 (`locked_writes_refused_by_the_stroke_budget_leave_everything_as_it_was` 등)는 거부 후 원래 상태로 복원되는지만 확인합니다. 마스크가 있는 레이어에 `apply_smart_mask` 적용·수동 ID 색상 (레이어 작업으로 바뀌지 않음은 `manual_id_colours_survive_layer_operations_transforms_and_resizes`에서 확인, C# `Resampled`는 이어받지 않음)도 C#과의 모든 바이트 대조에 포함되지 않습니다.

측정은 `cargo run -p yolu-core --release --example docops_bench`로 실행하며, 인공 레이어 2개의 512² / 1024²에서 각각 세 번 측정한 중앙값을 출력합니다. 희소 레이어 (8192², 그려진 타일 1장, 나머지는 없거나 균일)의 크기 변경은 `-- --sparse`입니다 (측정값은 STATUS에 기록).

합성 진입점은 용도별로 4개입니다. 모두 픽셀 값은 `composite_into`와 같은 바이트입니다 (거친 합성 제외).
- `composite_into`: 사각형을 호출자의 영역에 합성합니다. 그리는 동안에는 그릴 레이어 아래의 메모 (아래 항목)를 사용합니다.
- `composite_tiles`: 흩어진 타일의 묶음입니다 (화면 표시처럼 변경된 여러 부분을 다시 만들 때). 계획을 1회 만들고 타일을 워커에 나누므로 1장씩 호출하는 것보다 타일 1장당 시간이 짧습니다 (비율은 문서와 부하에 따름. 벤치마크의 `--only call`이 “1장씩 ÷ 묶음”을 출력). 가장자리 타일은 캔버스 내부만 처리합니다.
- `composite_coarse_tiles`: 보폭 (타일 한 변의 약수)마다 1픽셀을 선택하는 거친 합성입니다. 정확한 이미지가 완성되기 전의 임시 이미지와 슬라이더 드래그 중 표시에 사용합니다. 픽셀 (i, j)는 타일 왼쪽 아래에서 (i·보폭, j·보폭) 위치 픽셀의 합성과 같은 바이트입니다. 효과 출력은 평가하지 않은 블록이 있으면 거칠게 평가한 근사치 (축소된 입력에서 흐림·선명화 반경을 보폭으로 나누며 캐시에 넣지 않음), 모두 평가되었으면 정확한 출력을 선택합니다. 행 커널 (SIMD 경로)에는 입력을 64픽셀씩 패킹한 간격 4로 전달하므로 거친 합성에도 경로 차이가 적용됩니다 (`cargo run -p yolu-core --release --example coarse_bench`는 변 길이·레이어 수·보폭·스레드 수별 1회 시간을 출력). `effects_pending`은 해당 타일의 정확한 합성에 평가가 필요한지, `is_coalescing`은 슬라이더 드래그 중인지 반환합니다.
- `composite_below`·`composite_pixel`·그룹 출력은 메모를 사용하지 않는 참조 경로입니다.

작은 합성을 호출 스레드에서만 수행할지, 행 띠로 나눠 워커에 분배할지는 해당 타일에서 픽셀이 있는 레이어 수와 합성 방식의 비용으로 추정한 작업량에 따라 결정합니다 (타일 1장 계산에 약 0.1 ms가 걸릴 때 분배 비용은 약 0.4 ms이기 때문). 결과는 분배 방식에 영향받지 않습니다.

그리는 동안 아래쪽 메모 (`composite/memo.rs`): 스트로크가 건드린 타일에 대해, 그릴 레이어가 포함된 단계 바로 앞까지 합성한 결과 (단계마다 RGBA8로 반올림한 중간값)를 그룹 중첩 단계마다 기억하고 그릴 레이어 단계와 그 위 단계만 합성합니다. 직전 결과에서 이어가므로 모든 레이어를 아래부터 합성한 결과와 바이트가 같습니다. 위 레이어의 합성은 혼합 모드·보정·클리핑·통과 그룹이 아래 결과에 의존하므로 기억하지 않고, 해당 타일에서 픽셀이 있는 위 레이어만 매번 합성합니다. 메모 크기는 스트로크 예산에서 롤백용 사본을 뺀 나머지 안으로 제한됩니다 (초과하는 타일은 기억하지 않고 기존 경로 사용. 스트로크 진행으로 롤백이 커져 남은 예산에 들어가지 않으면 메모를 해제하므로, 점 추가가 끝난 시점과 합성 후에는 메모 + 롤백이 예산 안에 있음. 점 1개를 추가하는 순간에는 롤백이 먼저 커지므로 메모만큼 초과할 수 있음). 그릴 레이어의 픽셀 외의 변경 (변경 기록의 `mark`를 거치는 것)·스트로크 종료·취소·Anchor를 읽는 효과가 있으면 버리고 사용하지 않습니다. `set_composite_memo(false)`로 끌 수 있으며 `composite_memo_stats`로 사용·생성·예산 때문에 건너뜀·해제한 타일 수를 확인합니다.

벤치마크는 `cargo run -p yolu-app --release --example comp2d_bench -- --synthetic 2048` (`--psd <ファイル> --label A`, `--dense 1024 24`, `--only stroke|visible|opacity|effect|zoom|open|hash|merge|call`)이며, 표시 범위별 (프레임 없음·전체 표시·실제 크기) 동기 시간을 TSV로 출력합니다. `--only call`은 합성 호출 1회당 시간과 1장씩 호출할 때 대비 묶음의 비율 (“1장씩 ÷ 묶음”, 반복마다 연이어 측정한 비율의 최솟값·중앙값·최댓값)을 출력합니다. 모든 타일의 보폭 적용 거친 합성 (보폭 2·4·8)과 캔버스 전체를 사각형 1회로 합성하는 시간 (스레드 1·기본값)도 출력합니다. `--only merge`는 표시 결과에 기여하는 레이어 병합과 위에서부터 처음 병합 가능한 레이어를 아래와 병합하는 시간을, 병합 후 합성의 지문과 함께 출력합니다 (병합은 Undo로 복원).
