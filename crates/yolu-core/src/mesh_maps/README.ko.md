# 메시 맵

`MeshBakeInput::new`에 삼각형별 위치·UV·슬롯과 선택적인 정점 속성을 전달하고 `bake`로 베이크합니다.
위치는 월드 축과 모델 루트 원점을 기준으로 한 정적 스냅샷이며, UV와 출력의 원점은 왼쪽 아래입니다.
`MeshBakeSettings`는 총 10가지 종류, 하이폴리 투영, 안티앨리어싱, 패딩, ID의 출처를 지정합니다.

`MeshBakeBudget`의 메모리 추정치를 초과하는 입력, 범위를 벗어난 설정·UV, 베이크할 면이 없는 경우에는 진행률을 알리기 전에 오류로 거부합니다.
곡률의 선분과 UV의 행 구간 참조는 추정치에 포함하지 않으며, 준비에 들어간 뒤 남은 예산 (`max_bytes` − 추정치)을 기준으로 거부할 수 있습니다 (진행률은 "Preparing"까지).
수동 ID 색상이 다른 모델의 것인 경우에도 준비 도중 거부합니다.
시간 초과 또는 `AtomicBool`이나 진행률 콜백을 통한 취소 시에는 `maps`가 비어 있으며 기존 원본을 변경하지 않습니다.
진행률 콜백은 호출한 스레드에서 실행되며, 완료되면 `(1.0, "Done")`을 호출합니다 (이때의 반환값은 확인하지 않음).
rayon의 병렬 처리 수를 바꾸어도 픽셀과 출처 정보는 같습니다. `max_degree_of_parallelism`은 상한이며, 0은 논리 프로세서 수를 뜻합니다.
지정값은 1〜`MAX_PARALLELISM` (256. 한 행 묶음이 최대 256행이므로 그 이상은 사용되지 않음) 범위로 제한하고, 추정치도 제한한 값을 기준으로 계산합니다.

`MeshBakeReport`는 개수와 시간 외에도 결과가 평평하거나 흰색이거나 일부 누락되는 이유를 `notes` (`MeshBakeNote`. `diagnostics`는 그 설명문)로 반환합니다.
순서는 C# 진단과 같습니다. UV 겹침, UV 면적이 0인 삼각형, 정점 노멀의 출처, 탄젠트가 없어 UV에서 생성한 삼각형 (`fallback_triangles`),
비다양체·와인딩이 맞지 않는 변, 하이폴리에 닿지 않은 샘플, ID 파트 수와 색상 간 차이 (수동 색상·정점 색상 없음은 별도 기록),
하이폴리가 없는 탄젠트 공간 노멀과 높이 순서입니다.

`BakedMeshMap`은 16 bit 원본과 텍셀의 출처 정보를 보유합니다. `to_rgba8`은 표시용이므로 원본 대신 저장하지 않습니다.
저장에는 `yolu_io::mesh_map::{read, read_with_limit, write}`를 사용합니다. 형식 1〜3을 읽고 형식 3으로 씁니다.
`.ylp`에 넣을 때는 `Project::with_mesh_map` (형식 7만 지원. 이전 형식은 먼저 `upgraded`), 꺼낼 때는 `Project::mesh_map`을 사용합니다.
파생 데이터를 교체해도 문서와 알 수 없는 엔트리는 유지합니다.

## 겹친 UV 텍셀의 소유자 (베이크 우선순위)

같은 텍셀을 2개 이상의 삼각형이 덮으면 수신 대상 순서에서 먼저 나오는 삼각형이 소유자가 됩니다 (`priority.rs`. 베이크 할당만 바뀌며 베이크 후의 값 계산은 바뀌지 않음). `MeshOverlapPriority`는 자동 결정 방식 (`MeshOverlapRule`: 번호가 작은 삼각형·3D 면적이 큰 아일랜드·모델 공간의 +X 쪽·−X 쪽), 0〜1 밖에 있는 UV 아일랜드의 베이크 제외 여부, 직접 선택한 “베이크 제외”·“우선” 아일랜드를 보유합니다 (각각 최대 4096개. 모델 지문에 연결됨). 기본값 (번호가 작은 삼각형·제외 안 함·수동 선택 안 함)은 기존과 같은 순서이며, 베이크한 값과 출처 키도 바이트 단위로 같습니다. 겹친 텍셀의 그림은 `overlap.rs` (`UvOverlap`. 베이크 우선순위는 고려하지 않음)에 있습니다. 문서 설정은 `.ylp` 원본 버전 33에 저장합니다 (`docs/YLP_FORMAT.md`).

## 이전 맵의 사용 가능 여부 판정

이전 맵을 아무 확인 없이 사용하지 않도록 C#의 `MeshBaker.ConditionKey`와 `MeshMapProvenance.Check`를 이식했습니다.

- `condition_key(input, settings, kind, reference)`는 해당 조건으로 베이크한 맵의 `MeshMapProvenance::condition_key()`와 같은 키를 반환합니다.
  MaterialAsset의 ID 맵에 쓰이는 머티리얼 식별 정보 (`material_identity`)도 입력에서 만듭니다. 키가 같은 맵만 사용합니다.
- `MeshMapProvenance::check(&MeshMapExpectation)`는 `Current`·`Stale` (이유 목록 `MeshMapStaleReason`)·`Unverified` (모델 없음)를 반환합니다.
  `MeshMapExpectation::for_bake`는 입력과 설정에서 “다시 베이크해도 같아지는 조건”을 만듭니다. `Current`일 때만 사용합니다.
- C#의 `MeshMapSet` (종류별로 마지막 맵 1개를 보유하는 컨테이너)은 이식하지 않았습니다. 컨테이너는 호출 측에서 관리합니다.

## 재현과 측정

- 합성 메시의 기준 결과는 0.4.x까지의 Unity 브리지 C# (Unity 브리지 태그 `0.4.0`) 출력을 이어받은 것입니다. 다시 만들 때는 Rust 출력으로 만듭니다 (불규칙한 메시 비교에는 `rough.txt`의 SHA-256 사용).
- `cargo test -p yolu-core -p yolu-io`: 알려진 값, C# 기준 결과, 저장, 거부, 취소, 병렬 처리 수, 예산을 비교합니다.
- `cargo run --release -p yolu-core --example mesh_bench`: Rust 성능을 측정합니다.

측정 모델은 직접 만든 69,312개 삼각형의 세분화된 큐브입니다. 2048², 레이 샘플 8개, 스레드 4개, 안티앨리어싱 1, 패딩 0, 하이폴리 없음입니다.
맵별 소요 시간 (초)에는 준비가 포함되지만 입력 구성과 저장은 포함되지 않습니다. 이 조건에서 탄젠트 공간 노멀·높이·불투명도는 자체 베이크 기본값이 됩니다.
일반 모델, 하이폴리 투영, 기본 설정인 샘플 64개에서의 성능을 나타내는 것은 아닙니다. 측정 각 행의 마지막 열은 내용 (텍셀 출처 정보의 배열 +
리틀 엔디언 16 bit 값)의 SHA-256이며, C#과 Rust에서 10가지 종류가 모두 일치합니다.

## C#과 일치하는 범위

C#의 `MeshBaker` (Unity에 포함된 Mono)와 모든 바이트 (값·텍셀 출처 정보·출처 기록·압축 포함)가 일치함을 확인한 입력:

- 큐브 16개 사례 (노멀 출처·하이폴리·이름 대응·각 ID 출처·수동 색상·여러 슬롯·안티앨리어싱·패딩·UV 겹침·와인딩 반전).
- 불규칙한 좌표 (이진수로 정확히 나타낼 수 없는 값)의 격자 메시 (432〜6,912개 면)와 사각형마다 분리한 파트 메시.
  자체 베이크, AO 뒷면 건너뛰기·거리 감쇠 없음, 겹친 셸의 뒷면에 대한 충돌, 정점 탄젠트 (일부 삼각형에는 없음)·
  정점 노멀 (꺾임 각도 60도로 재구성)·케이지 방향 (정점 노멀/평균), 이름 대응 (대소문자·`_low`/`_high` 유무·대응 없음),
  MaterialAsset·MeshPart·UvIsland·VertexColor의 하이폴리가 있는 ID (파트 25개 이상, 팔레트 단계 4개 이상),
  여러 슬롯과 수동 색상, 69,312개 면의 256² (총 10가지 종류). 병렬 처리 수 1과 4에서 같습니다.
- BVH는 97개 면과 불규칙한 1,728개 면을 사용하여 노드·삼각형 순서와 레이 (탐색 중단·뒷면 건너뛰기·자신의 삼각형 무시)를 확인합니다.
- ID 팔레트 (파트 0〜1,000,000개), 조건 키, 오래된 상태 판정의 상태와 이유 순서, 진단 순서와 수치, 보고서 개수.

이 환경의 Mono는 float 식을 float 그대로 계산합니다 (C# 소스 주석의 “double로 계산한다”는 설명은 여기에는 해당하지 않습니다.
기준 결과에 `float_sum=0` 검사를 넣었습니다. C#으로 다시 만드는 경로는 남겨 두지 않았습니다). Rust의 f32와 반올림이 같으므로 불규칙한 좌표에서도
차이가 나지 않았습니다. 비교 입력은 모두 정수 해시와 문장당 연산 1개로 만들었으며 실제 모델은 사용하지 않았습니다.
일반적인 실제 모델, 서로 다른 OS 수학 라이브러리 (`sin`·`cos`·`atan2`)의 반올림, 기본 설정인 샘플 64개에서의 성능은 확인하지 않았습니다.

CPU 구현의 배정밀도 BVH를 사용합니다. 기존 `geometry`는 단정밀도 미리보기용이며 교차 판정과 분할 규칙이 다릅니다.
GPU·앱 UI는 이 모듈에 의존하지 않습니다.
