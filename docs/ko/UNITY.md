# Unity와 연동


## Live Link

같은 PC의 Unity 에디터에서 씬의 모델 (아바타 등)을 독립 실행형 앱으로 엽니다. Unity 2022.3 이상 프로젝트에 **Unity 브리지 (VPM 패키지
`net.yozolab.yolupainter`)**가 필요합니다. 브리지는 독립 실행형 앱과 같은 버전 번호로 배포하므로 업데이트할 때는 두 버전을 맞춰 주세요.
데이터는 같은 PC의 폴더에 두는 JSON 파일로 주고받으며 네이티브 라이브러리는 사용하지 않습니다 (명세는 [LIVELINK.md](LIVELINK.md)).

1. Unity에서 Hierarchy의 오브젝트를 오른쪽 클릭해 “Open in YoluPainter” (GameObject 메뉴에도 있음)를 선택하거나, `YozoLab → YoluPainter → Live Link` 창에서 오브젝트를 선택하고
   “YoluPainter에서 열기” (영어 표시에서는 Open in YoluPainter)를 누릅니다. 독립 실행형 앱이 실행되지 않았다면 시작합니다.
   독립 실행형 앱은 해당 오브젝트의 FBX와 이미지 파일을 직접 읽고 머티리얼별로 텍스처 세트를 만듭니다 (원본 이미지는 맨 아래 “원본 이미지” 레이어에 배치하며, PSD는 레이어를 유지). lilToon 머티리얼은
   Unity의 값으로 3D 보기에 그립니다 (lilToon 버전 값을 가진 머티리얼·lilToon 패키지의 셰이더만 해당. 이름만 비슷한 셰이더는 lilToon으로 그리지 않음).
2. Unity에서 포즈, BlendShape 또는 머티리얼 값을 바꿨다면 같은 버튼으로 다시 보냅니다 (FBX는 다시 읽지 않고 포즈와 값만 적용합니다. 포즈 패널이나 포즈 모드에서 움직인 본도 덮어씁니다. 원본 이미지 파일이 변경되었다면
   수정하지 않은 세트에는 다시 가져오고, 수정한 세트는 변경하지 않은 채 알려 줍니다).
3. “파일 → 텍스처 내보내기…” 창에서 출력 템플릿을 “lilToon”으로 설정해 내보내면 기본 출력 위치는 Unity가 전달한 폴더입니다. 작성한 PNG 중 lilToon 머티리얼의 속성 (`_MainTex`·`_BumpMap` 등)에
   해당하는 파일을 Unity가 가져오며, 머티리얼에 적용할지는 Unity 창에서 확인합니다. 다른 템플릿과 채널별 PNG는 Unity로 반환하지 않습니다.
   1개의 텍스처 세트에 여러 머티리얼을 할당했다면 같은 PNG를 각 머티리얼에 반환합니다.
4. 작업은 `.ylp`에 저장합니다. Live Link로 연 모델 (FBX 배열·렌더러와 머티리얼의 연결·포즈)도 `.ylp`에 남으므로 Unity 없이 다시 열 수 있습니다.
   Unity에서 받은 머티리얼 값을 `.ylp`에 남길지는 설정의 같은 구분에 있는 “Unity에서 받은 머티리얼 값 저장” (기본값 켜짐)으로 선택합니다.
   “배포용으로 저장”에서 “모델 참조”를 제외하면 사본에서 이 기록도 제거합니다 ([SAVE_FOR_DISTRIBUTION.md](SAVE_FOR_DISTRIBUTION.md)).

독립 실행형 앱은 “편집 → 설정…” (Ctrl+,)의 “Live Link 및 외부 조작”에 있는 “Unity Live Link 수신” (기본값 켜짐)이 켜진 동안 Unity의 열기 요청을 받습니다 (`--livelink`를 붙여 실행하면 설정과 관계없이 수신합니다).
메뉴 모음 오른쪽 끝의 표시로 상태를 보여 줍니다 (수신 안 함·수신 중·Unity에서 연 문서·맞지 않는 항목 있음·폴더 사용 불가). 표시를 누르면 작은 창에 “Live Link: 수신 중” 형식의 상태와
열린 오브젝트 (“Unity: 이름”)가 나타나며 수신 여부를 전환할 수 있습니다. “파일” 메뉴의 “Live Link”에서도 전환할 수 있습니다.

- 열 수 있는 것은 FBX에서 가져온 메시의 렌더러뿐입니다 (.asset 메시 등은 Unity 창에 이유를 표시하고 보내지 않습니다). 가져오기 설정에서 “축 변환 베이크”
  (Bake Axis Conversion)를 켠 FBX는 열 수 없습니다.
- 다른 오브젝트를 열 때 저장하지 않은 변경 사항이 있다면 일반 “열기”와 마찬가지로 확인합니다 (열기를 취소하면 Unity에 이유를 반환합니다). 그리거나 저장하는 도중 Unity에서
  열면 해당 작업이 끝난 뒤 적용합니다.
- 교환 폴더 (Windows는 `%LOCALAPPDATA%\YoluPainter\LiveLink`, Mac은 `~/Library/Application Support/YoluPainter/LiveLink`, Linux는
  `~/.local/share/YoluPainter/LiveLink`)는 해당 사용자만 접근할 수 있어야 합니다. 다른 사용자도 접근할 수 있는 폴더는 사용하지 않습니다. 같은 사용자의 다른 프로그램은
  이 폴더에 파일을 둘 수 있습니다.
- Unity 프로젝트의 원본 텍스처·머티리얼 에셋에는 사용자가 머티리얼에 적용하기로 결정했을 때만 기록합니다.

## 0.4.x까지의 Unity 브리지와 .ylp 교환

Unity 브리지는 0.5.0부터 `.ylp`를 열지 않습니다. Unity 안에서 그리는 기능, `.ylp` 및 `.ylsmart` 가져오기, PSD 읽기·쓰기, 메시 맵 베이크를 제거하고 Live Link와
머티리얼 적용만 제공하는 패키지가 되었습니다. 그리기·`.ylp` 열기·저장은 독립 실행형 앱에서 수행합니다. Assets에 둔 `.ylp`는 Unity에서 일반 파일로 취급합니다.

0.4.x까지의 Unity 브리지에서 `.ylp`를 열 때 읽을 수 있는 범위 (외부 구조·내부 형식·정본 버전·알 수 없는 엔트리 처리)는 [YLP_FORMAT.md](YLP_FORMAT.md)의 “리더별 범위”에 설명되어 있습니다.
0.4.x까지의 Unity 브리지가 읽을 수 있는 정본 버전은 21까지이므로, 사용자 채널·노이즈·그런지·색상 보정·0.5.0의 효과 등을 사용한 세트가 포함된 `.ylp`는 파일을 변경하지 않고 거부합니다.
이전 버전으로 돌아가려면 독립 실행형 앱에서 해당 기능을 제거하고 다시 저장합니다 (버전이 21로 돌아갑니다). 이름을 지정해 저장한 선택 영역 (“저장된 선택 영역”)을 사용하는 `.ylp` (형식 8)도 거부되므로
모두 삭제하고 다시 저장하거나, “배포용으로 저장”에서 “저장된 선택 영역”을 제외한 사본을 만듭니다 ([SAVE_FOR_DISTRIBUTION.md](SAVE_FOR_DISTRIBUTION.md)). 0.4.x까지의 Unity 브리지를 위한 형식 변환 기능은 없습니다.
