# .ylp 파일 형식

YoluPainter 작업 파일 `.ylp`의 사양입니다.

이 문서는 외부 도구 (변환·검사·빌드 도중 .ylp를 읽는 도구)를 만드는 사람과 형식을 변경하는 사람을 대상으로 합니다.
이 문서가 형식의 유일한 사양입니다. 코드와 이 문서가 다르면 버그입니다.
형식을 바꾸는 커밋에서는 같은 커밋 안에서 이 문서도 수정합니다.

- 형식을 선택한 이유·채택하지 않은 대안·보장 범위는 [YLP_DECISIONS.md](YLP_DECISIONS.md)에 있습니다.
- 읽기와 쓰기 코드는 `crates/yolu-io`에 있습니다.
  - 외부 구조는 `package.rs`·`archive.rs`
  - 내부 형식은 `project.rs`
  - 세트 원본은 `native.rs`·`bigdoc.rs`
  - 나머지 엔트리는 각 엔트리의 리더 코드
- `crates/yolu-io/tests/ylp/format_doc.rs`는 이 앱이 쓰는 엔트리·버전 상수·원본 필드 이름·JSON 키가
  이 문서에 실려 있는지 확인합니다.

<a id="概要"></a>

## 개요

<a id="ylp-とは"></a>

### .ylp란

.ylp는 작업 파일이며 텍스처가 아닙니다.
머티리얼에는 내보낸 PNG를 할당합니다. .ylp를 전달받는 환경에 YoluPainter가 있다고 보장할 수 없기 때문입니다.

.ylp는 zip입니다. 이 문서에서는 zip 안의 개별 파일을 엔트리라고 부릅니다.

- 하나의 .ylp는 텍스처 세트 (이하 세트)를 1〜64개 가집니다.
- 세트는 모델의 한 머티리얼에 대응하는 텍스처 묶음이며 문서 (레이어와 픽셀)를 하나 가집니다.
- 에셋 (이미지·스마트 머티리얼·브러시 등)은 .ylp 전체에서 공유합니다.

<a id="中の木"></a>

### 내부 트리

이 앱이 쓰는 일반적인 .ylp입니다. 외부 버전은 `YLP-3`, 내부 형식은 7이며 세트 하나와 에셋이 있습니다.
“있을 때만”으로 표시한 엔트리는 사용하지 않으면 쓰지 않습니다.

```text
example.ylp                      zip
├─ mimetype                      無圧縮。中身は application/x-yolupainter
├─ manifest.sha256               1 行目が外側のバージョン（YOLUPAINTER-YLP-3）。続く行が、mimetype とこのエントリを除く全エントリの
│                                SHA-256・長さ・名前
├─ ylp.json                      中身の形式（7）と、書いたアプリ
├─ project.json                  セットの並びと、今のセット
├─ resources.json                アセットの並び（アセットがあるときだけ）
├─ resources/
│  ├─ <content>.png              アセットの画像
│  ├─ <content>.ylsmart          スマートマテリアル・スマートマスク・マテリアル（あるときだけ）
│  └─ <content>.ylbrush          0.4.x までの Unity ブリッジのブラシ（あるときだけ。このアプリは書かず、読んで残すだけ）
├─ view.json                     画面の状態（モデルのファイルの参照など。あるときだけ）
├─ pose.json                     モデルの今のポーズ（あるときだけ）
├─ livelink.json                 Live Link の相手の文書（あるときだけ）
└─ sets/
   └─ <ID>/                      セット 1 つ。ID は小文字のハイフン付き GUID
      ├─ document.utpaint        セットの正本。レイヤーと画素。正本のバージョンは使う機能で決まる
      ├─ selection.bin           今の選択範囲（あるときだけ）
      ├─ look.json               3D ビューの見た目の設定（あるときだけ）
      ├─ composite/
      │  └─ Color.png ほか       標準のチャンネルの合成（派生）
      └─ meshmap-<種類>.bin      焼いたメッシュマップ（派生。焼いたときだけ）
```

엔트리별 종류와 의미는 [엔트리 목록](#エントリの一覧)에 있습니다.

<a id="言葉"></a>

### 용어

| 용어 | 의미 |
|---|---|
| 엔트리 | zip 안의 개별 파일. 이름은 `sets/<ID>/document.utpaint`처럼 `/`로 구분 |
| 외부 | zip 구성 방법, `mimetype`, `manifest.sha256`, 엔트리 이름과 크기 규칙 |
| 내부 | 엔트리 바이트열의 내용. 표의 “내용” 열은 엔트리나 필드의 내용을 설명 |
| 리더·라이터 | .ylp를 읽는 프로그램·쓰는 프로그램. 단순히 “라이터”·“리더”라고 하면 이 앱을 뜻함. 외부 도구도 지켜야 하는 규칙에는 “모든 라이터”·“모든 리더”라고 명시 |
| 텍스처 세트 (세트) | 한 머티리얼에 대응하는 텍스처 묶음. 문서를 하나 가짐. 순서는 `project.json`이 보유 |
| 에셋 | 레이어나 표시 설정이 `id`로 참조하는 .ylp 전체의 이미지·스마트 머티리얼·브러시. 순서는 `resources.json`이 보유 |
| 본체 | 엔트리 종류 중 하나. 잃으면 작업이 사라지는 엔트리. 읽을 수 없으면 열기를 거부 |
| 상태 | 엔트리 종류 중 하나. 연 후의 화면 상태. 읽을 수 없으면 기본값으로 되돌리고 알리며 엔트리는 바이트열 그대로 유지 |
| 파생 | 엔트리 종류 중 하나. 본체에서 다시 만들 수 있는 것. 읽을 수 없으면 사용하지 않고 다시 생성. 본체 대신 사용하지 않음 |
| 기록 | 엔트리 종류 중 하나. `ylp.json`. 작성 앱과 내부 형식을 보유. 읽을 수 없으면 열기를 거부 |
| 세트 원본 (원본) | `document.utpaint`. 한 세트의 모든 레이어·픽셀·설정을 가진 바이너리. “원본 버전”·“분할 원본”·“원본 필드”의 원본도 이를 뜻함 |
| 원본 버전 | `document.utpaint` 버전. `DOTPAINT` 다음의 int |
| 분할 원본 | 큰 세트 원본을 `document.utpaint`와 `document.utpaint.<n>`으로 나눈 것. 원본 버전은 26 |
| 분할 전 원본 버전 | 분할 원본이 분할 전 배열로 보유하는 원본 버전 |
| 외부 버전 | `manifest.sha256` 첫 번째 줄의 버전. `YOLUPAINTER-YLP-1`〜`4` |
| 내부 형식 | `ylp.json`의 `format`. 엔트리 배열과 각 JSON의 구조를 결정 |
| straight RGBA8 | RGB에 알파를 곱하지 않는 RGBA 각 8 bit 픽셀. 투명 픽셀의 RGB도 유지 |
| 0.4.x까지의 Unity 브리지 | Unity 안에서 그릴 수 있던 시기의 Unity 패키지 (EditorWindow와 임포터). Unity 브리지 0.5.0부터는 .ylp를 열거나 쓰지 않음 |

엔트리 종류는 본체·상태·파생·기록입니다.
“원본”은 종류 이름으로 사용하지 않습니다. `document.utpaint`, 즉 세트 원본이라는 뜻으로만 사용합니다.

<a id="バージョンの数"></a>

### 버전 번호

.ylp에는 서로 독립적인 버전 번호가 여러 개 있습니다. 어느 것도 앱 버전 (0.5.1·0.6.0 등)이 아닙니다.

| 버전 번호 | 기록 위치 | 변경 시점 | 범위 | 이 앱이 쓰는 값 |
|---|---|---|---|---|
| 외부 버전 | `manifest.sha256` 첫 번째 줄의 `YOLUPAINTER-YLP-<n>` | 엔트리 이름과 크기 규칙을 확장할 때 | 1〜4 | 3. 현재 상한에 들어가지 않는 파일만 4 |
| 내부 형식 | `ylp.json`의 `format` | 엔트리 추가·이름·위치·의미를 바꿀 때 | 1〜9 | 7. 이름을 붙여 저장한 선택 영역을 사용하는 파일만 8. 머티리얼을 2개 이상 가진 세트가 있는 파일만 9 |
| 원본 버전 | `document.utpaint`의 `DOTPAINT` 다음 int | `document.utpaint`의 필드를 늘릴 때 | 1〜30·32〜36 (31은 사용하지 않음) | 사용하는 기능에 따라 21〜25·27〜30·32〜36. 512 MiB를 넘는 세트 원본만 26. 분할 전 원본 버전은 21〜25·27〜30·32〜36 |
| 메시 맵 버전 | `meshmap-<種類>.bin`의 `YLPMMAP\0` 다음 int | `meshmap-<種類>.bin` 필드를 바꿀 때 | 1〜3. 엔진 버전은 2 | 3 |
| 선택 영역 버전 | `selection.bin`·`selection-<印>.bin`의 `YLSL` 다음 int | 선택 영역 필드를 바꿀 때 | 1 | 1 |
| JSON의 `format` | `look.json`·`pose.json`·`selections.json`·`livelink.json`의 `format` | 해당 JSON 구조를 바꿀 때 | 1 | 1 |
| `.ylsmart` 버전 | manifest의 `YOLUPAINTER-SMART-1`과 `smart.json`의 `format` | `.ylsmart` 구조를 바꿀 때 | 1 | 1 |
| `.ylbrush` 버전 | manifest의 `YOLUPAINTER-BRUSH-1`과 `state.json`의 `schema` | 0.4.x까지의 Unity 브리지 브러시 구조. 이 앱에서는 변경하지 않음 | `schema` 1〜3 | 쓰지 않음. 읽고 바이트열 그대로 유지 |

- 이 앱은 사용하는 기능에 필요한 가장 낮은 버전으로 씁니다. 같은 앱이라도 사용하는 기능에 따라 쓰는 값이 달라집니다.
- 쓰는 값의 최솟값은 외부 버전 3·내부 형식 7·원본 버전 21입니다.
- 새로운 기능을 사용하지 않는 .ylp는 이전 버전과 같은 배열로 쓰므로 이전 앱에서도 열 수 있습니다.
- 예를 들어 “원본 버전 27”은 `document.utpaint`의 버전 27입니다. 경로 목록을 추가한 버전입니다.
- 예를 들어 “내부 형식 7”은 `ylp.json`의 `format`이 7이라는 뜻입니다. 세트가 머티리얼별 구조입니다.
- 이 문서는 버전 번호를 쓸 때 무엇의 버전인지 덧붙입니다. 단순히 “버전 27”·“형식 7”이라고 쓰지 않습니다.
- 앱 버전별로 읽을 수 있는 범위는 [리더별 범위](#読み手ごとの範囲)에 있습니다.
- 버전별 추가 내용은 [내부 형식 버전](#中身の形式のバージョン)과 [원본 버전별 추가 사항](#正本のバージョンごとの追加)에 있습니다.

<a id="外側"></a>

## 외부

외부는 zip 구성 방법과 엔트리 이름 및 크기 규칙입니다.

<a id="zip-の並び"></a>

### zip 배열

- 첫 번째는 비압축 `mimetype`이며 내용은 `application/x-yolupainter`입니다.
- 다음은 `manifest.sha256`이며 이어서 엔트리를 이름순으로 배치합니다.
- `mimetype`과 이름이 `.png`로 끝나는 엔트리는 압축하지 않고 넣습니다. 나머지는 Deflate로 넣습니다.
- 압축해도 크기가 줄지 않는 엔트리는 압축하지 않고 넣습니다.
- `YLP-4`의 4 MiB 이상 엔트리는 처음 1 MiB를 시험 압축합니다. 97% 미만으로 줄어들지 않으면 전체를 압축하지 않고 넣습니다.
- zip의 날짜·시간과 압축 결과는 형식의 일부가 아닙니다. 같은 내용이라도 바이트열이 같다고 보장하지 않습니다.

### manifest.sha256

UTF-8 텍스트입니다.

- 첫 번째 줄은 외부 버전입니다 (`YOLUPAINTER-YLP-1`〜`4`).
- 이어지는 각 줄은 `<SHA-256> <バイト数> <名前>`이며 이름순으로 정렬합니다.
- `mimetype`과 `manifest.sha256`을 제외한 모든 엔트리를 나열합니다. 이 2개를 나열한 파일은 거부합니다.
- SHA-256은 소문자 16진수 64자리입니다.
- 내용의 무결성은 SHA-256으로 판단하며 zip의 CRC-32도 확인합니다.
- 다음 경우에는 모두 읽지 않고 거부합니다.
  - manifest에 없는 엔트리
  - manifest에는 있지만 파일에 없는 엔트리
  - 길이나 SHA-256 불일치

<a id="エントリの名前"></a>

### 엔트리 이름

- 사용할 수 있는 문자는 영숫자와 `.` `-` `_`이며 최대 96바이트입니다.
- `.`으로 시작하는 이름·`..`가 포함된 이름·빈 이름은 거부합니다.
- 배치할 수 있는 폴더는 외부 버전에 따라 결정됩니다.

| 외부 버전 | 내부 형식 | 배치할 수 있는 폴더 |
|---|---|---|
| `YOLUPAINTER-YLP-1` | 1·2 | 루트와 `composite/` 아래만 가능. 루트에 `document.utpaint` 필요 |
| `YOLUPAINTER-YLP-2` | 3 | 추가로 이름 앞에 `sets/<ID>/` 하나를 허용. `sets/<ID>/composite/`도 가능. 루트 또는 어느 한 `sets/<ID>/`에 `document.utpaint` 필요 |
| `YOLUPAINTER-YLP-3` | 4부터 | 추가로 루트의 `resources/` 아래에 한 단계 이름을 허용. 그 아래에는 폴더를 둘 수 없음. `sets/<ID>/resources/`도 불가 |
| `YOLUPAINTER-YLP-4` | `YLP-3`과 같음 | 이름 규칙은 `YLP-3`과 같음. 상한과 zip64만 다름 (아래 참고) |

- `<ID>`는 소문자와 하이픈으로 된 36자 GUID입니다. 대문자·하이픈 없음·빈 GUID는 거부합니다.
- 이름 규칙을 확장할 때는 외부 버전을 올립니다.
- 이전 리더는 잘못된 이름이 아니라 더 새로운 앱에서 작성된 파일이라는 이유로 거부합니다.

<a id="上限"></a>

### 상한

| 상한 | `YLP-1`〜`3` | `YLP-4` |
|---|---|---|
| 엔트리 1개 | 512 MiB | 세트 원본의 부분 (`document.utpaint.<n>`)은 256 MiB, 나머지는 512 MiB |
| 합계 | 768 MiB | 아래의 “`YLP-4`” 참조 |
| 엔트리 수 | 1000 | 65000 |
| manifest | 1 MiB | 16 MiB |
| zip64 | 없음 | 필요할 때만 |

어떤 외부 버전이든 선언한 길이를 초과하여 압축을 풀지 않습니다.

#### `YLP-4`

`YOLUPAINTER-YLP-4` (`package.rs`)는 `YLP-3` 상한에 들어가지 않는 파일에만 사용합니다.
상한 안에 들어가는 프로젝트는 `YLP-3`으로 쓰며 바이트열도 `YLP-4` 추가 전과 같습니다.

다음 2가지 상한 (세트별·전체)은 리더별 설정으로 정해지는 예산입니다. 형식 자체의 제약은 아닙니다.

- 세트별 원본 (`document.utpaint`와 부분 길이의 합계)은 “레이어 메모리” 설정 예산의 최대 4배입니다.
  이 예산은 256 MiB보다 작아지지 않습니다.
- 전체는 “원본이 있는 세트 수 × 세트별 상한 ＋ 768 MiB”까지입니다.

예산을 초과할 때의 동작은 다음과 같습니다.

- 이 앱은 예산을 초과해도 씁니다. 현재 예산으로 다시 열 수 없다는 사실을 저장할 때 알립니다.
- 읽을 때는 어떤 예산인지 알리고 압축을 풀기 전에 거부합니다.

zip64는 필요할 때만 사용합니다.

- 4 GiB를 넘는 위치의 로컬 헤더는 중앙 디렉터리의 zip64 확장으로 가리킵니다. 해당 레코드의 버전은 45입니다.
- 엔트리가 65535개를 넘거나 중앙 디렉터리가 4 GiB를 넘으면 zip64 종료 레코드와 식별자를 씁니다.
- `YLP-3` 이하 파일에 zip64 구조가 있으면 거부합니다.
- 이 앱은 데이터 디스크립터를 쓰지 않습니다. 읽을 때는 허용합니다.

### JSON 공통 규칙

- 모든 라이터는 UTF-8 JSON 객체로 씁니다.

  이 앱은 이러한 데이터를 거부합니다.
- 본체와 기록 JSON (`ylp.json`·`project.json`·`resources.json`, `.ylsmart`의 `smart.json`)은 이 규칙으로 읽습니다.

엔트리별 크기 상한은 다음과 같습니다.

| 엔트리 | 상한 |
|---|---|
| `ylp.json`·`project.json` | 64 KiB |
| `resources.json` | 1 MiB |
| `view.json` | 256 KiB |
| `pose.json` | 8 MiB |
| `look.json` | 1 MiB |
| `livelink.json` | 16 MiB |
| `selections.json` | 256 KiB |

### ylp.json

내부 형식과 작성 앱을 보유하는 기록입니다.

```json
{
  "format": 7,
  "savedBy": { "app": "YoluPainter", "version": "0.4.0", "unity": "standalone" },
  "createdBy": { "app": "YoluPainter", "version": "0.4.0", "unity": "standalone" }
}
```

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `format` | 정수 | 필수. 2 이상 | 내부 형식 |
| `savedBy` | 객체 | 필수 | 마지막으로 저장한 앱 |
| `createdBy` | 객체 | 생략 가능 | 처음 만든 앱 |

`savedBy`와 `createdBy` 내부의 키는 같습니다.

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `app` | 문자열 | 1〜256자 | 앱 이름 |
| `version` | 문자열 | 1〜256자 | 앱 버전 |
| `unity` | 문자열 | 1〜256자 | 0.4.x까지의 Unity 브리지는 Unity 버전을 씀. 이 앱은 `standalone`을 씀 |

- 내부 형식 1 파일에서 만든 경우 처음 작성한 앱을 알 수 없으므로 `createdBy`를 쓰지 않습니다.
- 알 수 없는 키는 건너뜁니다.

### project.json

세트 순서와 현재 세트를 가진 본체 엔트리입니다. 여기에 설명한 구조는 내부 형식 7입니다.
머티리얼을 2개 이상 가진 세트만 내부 형식 9의 `materials`로 씁니다 (아래 두 번째 예).

```json
{
  "sets": [
    {
      "id": "0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0",
      "name": "Body",
      "material": { "name": "Skin", "guid": "0123456789abcdef0123456789abcdef", "fileId": 2100000 }
    },
    { "id": "11111111-2222-3333-4444-555555555555", "name": "Hair", "material": { "name": "Hair" } },
    { "id": "22222222-3333-4444-5555-666666666666", "name": "Unassigned", "material": { "unassigned": true } },
    { "id": "33333333-4444-5555-6666-777777777777", "name": "Texture Set 1", "material": { "slot": 0 } }
  ],
  "current": "11111111-2222-3333-4444-555555555555"
}
```

내부 형식 9에서 하나의 세트가 머티리얼 2개를 가지는 예입니다.

```json
{
  "sets": [
    { "id": "0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0", "name": "Face", "materials": [ { "name": "Face" }, { "name": "Ear" } ] },
    { "id": "11111111-2222-3333-4444-555555555555", "name": "Hair", "material": { "name": "Hair" } }
  ],
  "current": "0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0"
}
```

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `sets` | 배열 | 필수. 1〜64개 | 세트 순서. 배열 순서가 패널 순서 |
| `sets[].id` | 문자열 | 필수. 소문자와 하이픈으로 된 GUID. 다른 세트와 중복되지 않음 | 세트 ID. 엔트리 위치 `sets/<id>/`의 이름 |
| `sets[].name` | 문자열 | 필수. 1〜256자. 공백만으로 구성되지 않음. 제어 문자 없음. 대소문자를 구분하지 않고 다른 세트 이름과 중복되지 않음 (중복되면 거부) | 세트 이름. 내보내는 파일 이름에 사용 |
| `sets[].material` | 객체 | 내부 형식 7부터. `materials`가 없는 세트에 필수 | 머티리얼 키 (아래). 세트의 머티리얼이 1개일 때의 구조 |
| `sets[].materials` | 배열 | 내부 형식 9부터. 2〜1024개. `material`과 함께 쓰지 않음 | 머티리얼 키 (아래)의 배열. 세트의 머티리얼이 2개 이상일 때의 구조 |
| `sets[].materialSlot` | 정수 | 내부 형식 6까지 | 내부 형식 7에서는 읽지 않음. 마이그레이션이 `material`의 `slot`으로 변환 |
| `current` | 문자열 | 필수. `sets`에 있는 `id` | 현재 세트 |

- 알 수 없는 키 (루트·각 세트)는 건너뛰며 다시 쓸 때도 유지합니다.
- 규칙에 맞지 않으면 기본값으로 되돌려 열지 않고, 열기 자체를 거부합니다.
- 목록에 있는 세트에 `sets/<id>/document.utpaint`가 없으면 거부합니다.

<a id="materialマテリアルの鍵"></a>

#### material (머티리얼 키)

다음 중 하나의 구조로 씁니다. 두 가지 이상이거나 어느 구조에도 해당하지 않으면 거부합니다.

| 구조 | 키 | 범위 | 의미 |
|---|---|---|---|
| 이름 | `name` | 0〜256자. 제어 문자 없음 | 머티리얼 이름 |
| Unity 에셋 | `name`과 `guid`·`fileId` | `guid`는 소문자 16진수 32자. `fileId`는 부호 있는 64 bit 정수 | Unity 에셋 머티리얼. `guid`와 `fileId`를 함께 씀 |
| 미할당 | `unassigned` | `true` | 모델에서 머티리얼이 없는 모든 슬롯 |
| 슬롯 | `slot` | 0〜65535 | 아직 머티리얼에 연결하지 않은 슬롯 번호. 내부 형식 6 이하 파일 |

- 같은 `guid`·`fileId` 쌍 2개, `unassigned` 2개, 같은 `slot` 2개는 거부합니다. `materials` 안의 키도 다른 세트의 키와 비교합니다.
- 이름만 있는 키는 서로 다른 세트에서 중복되어도 됩니다. 같은 세트의 `materials`에 같은 키가 2번 있으면 거부합니다.
- 모델 머티리얼과의 매칭은 식별자 (`guid`·`fileId`), `unassigned`, 이름, `slot` 순서로 진행합니다.
- 이름은 대소문자까지 같은 것을 먼저 비교한 다음 대소문자를 구분하지 않고 비교합니다.
- 하나의 머티리얼은 하나의 세트만 보유합니다.
- 하나의 세트는 `materials`로 머티리얼 2개 이상을 가질 수 있습니다 (내부 형식 9). 해당 머티리얼의 면은 모두 같은 텍스처에 그립니다.
- 매칭은 키별로 수행합니다. 일치하지 않는 키도 그대로 유지합니다.
- 이 앱은 어떤 머티리얼에도 연결하지 않는 세트에 모델의 슬롯 수보다 뒤의 `slot`을 씁니다. 키가 없는 세트는 쓰지 않습니다.
- 일치하지 않는 세트도 열 수 있습니다. 3D에 보이지 않을 뿐입니다.
- `material`과 `materials`가 모두 있는 세트, 항목이 2개보다 적은 `materials`, 내부 형식 8 이하 파일의 `materials`는 거부합니다.

<a id="resourcesjson-と-resources"></a>

### resources.json과 resources/

에셋 (프로젝트 리소스)의 순서와 내용입니다.
에셋이 비어 있으면 `resources.json`을 쓰지 않습니다. 이 파일이 없으면 에셋이 비어 있습니다.

```json
{
  "resources": [
    {
      "id": "aaaaaaaa-0000-4000-8000-000000000001",
      "kind": "image",
      "name": "Scratches",
      "content": "<64 桁の小文字 16 進>",
      "width": 1024,
      "height": 1024,
      "colorSpace": "srgb",
      "origin": {
        "type": "unityAsset",
        "guid": "0123456789abcdef0123456789abcdef",
        "path": "Assets/Textures/Scratches.png",
        "stamp": "<Unity の依存ハッシュ>",
        "localFileID": 2800000
      }
    },
    {
      "id": "bbbbbbbb-0000-4000-8000-000000000002",
      "kind": "smartMaterial",
      "name": "Rusty",
      "content": "<ファイルの SHA-256>",
      "length": 5519,
      "origin": { "type": "library", "file": "Rusty.ylsmart", "sha256": "<同じ>", "length": 5519 }
    }
  ]
}
```

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `resources` | 배열 | 필수. 0〜256개 | 에셋 순서. 배열 순서가 패널 순서 |
| `resources[].id` | 문자열 | 필수. 소문자와 하이픈으로 된 GUID. 중복 없음 | 에셋 ID. 세트 원본의 레이어 (채우기 이미지의 `resource_id`)와 `look.json`의 `image`가 참조하는 이름 |
| `resources[].kind` | 문자열 | 필수 (아래) | 에셋 종류 |
| `resources[].name` | 문자열 | 필수. 1〜256자. 공백만으로 구성되지 않음. 제어 문자 없음. 중복 허용 | 에셋 이름 |
| `resources[].content` | 문자열 | 필수. 소문자 16진수 64자리 | 내용의 SHA-256 (아래) |
| `resources[].width`·`resources[].height` | 정수 | `image`만 해당. 필수. 1〜8192. PNG와 다르면 거부 | 이미지 크기 |
| `resources[].colorSpace` | 문자열 | `image`만 해당. 생략 가능. `srgb`·`linear`·`unspecified`. 기본값은 `unspecified` | 이미지 색 공간 |
| `resources[].length` | 정수 | `image` 이외. 필수. 1〜512 MiB. 파일 길이와 같음 | 파일 길이 |
| `resources[].origin` | 객체 | 생략 가능. 기본값은 `{ "type": "none" }` | 출처. 출처가 사라져도 복사본은 사용 가능 |

`kind` 값은 다음과 같습니다. 알 수 없는 종류는 거부합니다 (제외하고 저장하지 않음).

| `kind` | 시작 | 내용 파일 |
|---|---|---|
| `image` | 내부 형식 4 | `resources/<content>.png` |
| `smartMaterial`·`smartMask` | 내부 형식 5 | `resources/<content>.ylsmart` |
| `brush` | 내부 형식 6 | `resources/<content>.ylbrush` |
| `material` | 내부 형식 6 | `resources/<content>.ylsmart` |

`content`는 다음 해시입니다.

- `image`: ASCII `YLPRGBA8`, 너비와 높이 (32 bit little-endian), straight RGBA8 픽셀 (아래쪽 행부터)을 이어 붙인 SHA-256.
- 나머지: 파일 바이트열의 SHA-256.

<a id="origin出どころ"></a>

#### origin (출처)

| `type` | 키 | 범위·의미 |
|---|---|---|
| `none` | | 복사본만 |
| `unityAsset` | `guid` | 소문자 16진수 32자리 |
| | `path` | 1〜1024자. 표시용으로만 사용 |
| | `stamp` | 생략 가능. 0〜128자. Unity 의존성 해시 |
| | `localFileID` | 생략 가능. 부호 있는 64 bit. 없거나 0이면 주 에셋 |
| | `readThroughGpu` | 생략 가능 |
| `file` | `path` | 절대 경로. 1〜1024자 |
| | `sha256` | 파일의 SHA-256 |
| | `length` | 파일 길이 |
| `library` | `file` | 저장 위치 안의 `/`로 구분한 상대 경로. `\`·`:`·빈 구간·`.`·`..`는 거부 |
| | `sha256` | 파일의 SHA-256 |
| | `length` | 파일 길이 |
| `builtIn` | `key` | 1〜64자의 `a-z 0-9 -` |
| | `version` | 1 이상 |

<a id="resources-の中身"></a>

#### resources/의 내용

- 리소스 2개가 같은 내용을 가져도 되며 이 경우 엔트리는 하나입니다.
- `resources/<content>.png`
  - 색상 유형 6 (RGBA)·8 bit·인터레이스 없음·보조 청크 없음입니다. ICC·gAMA를 추가하지 않습니다.
  - 투명 픽셀의 RGB도 유지합니다.
  - 열 때 모두 디코딩하여 픽셀 해시가 이름과 같은지, 크기가 목록과 같은지 확인합니다.
  - 저장할 때는 읽은 바이트열을 그대로 씁니다.
- `resources/<content>.ylsmart`·`.ylbrush`
  - [.ylsmart](#ylsmart)와 [.ylbrush](#ylbrush) 파일을 저장 위치의 파일과 같은 바이트열로 넣습니다.
  - 열 때 길이·SHA-256·내용 종류를 확인합니다.

규칙은 다음과 같습니다.

- 목록에 있지만 엔트리가 없거나 손상되었으면 해당 항목을 알려 주고 열기를 거부합니다.
- 목록에 없는 `resources/` 엔트리는 알 수 없는 엔트리로 알립니다.
- 이 앱은 에셋을 변경했을 때만 `resources.json`과 `resources/`를 다시 씁니다.
  바꾸지 않았으면 열었을 때의 바이트열 그대로 씁니다.
- 메모리 예산은 768 MiB입니다. 디코딩한 이미지 픽셀·스마트 머티리얼 파일과 픽셀·브러시 파일과 브러시 끝을 합산합니다.

### view.json

화면 상태를 가진 상태 엔트리입니다. 이 앱은 객체가 아니면 읽지 않습니다. 알 수 없는 키는 유지합니다.

| 키 | 라이터 | 내용 |
|---|---|---|
| `modelAssetGuid` | 0.4.x까지의 Unity 브리지 | 모델 에셋 GUID. 이 앱이 새로 만들 때는 빈 문자열 |
| `selectedChannel` | 0.4.x까지의 Unity 브리지 | 선택한 채널. 이 앱이 새로 만들 때는 0 |
| `visibility` | 0.4.x까지의 Unity 브리지 | 숨김 지정 (아래) |
| `standaloneModel` | 이 앱 | 모델 파일 참조 (아래) |
| `materialSlot` | 내부 형식 2까지 | 내부 형식 3으로 마이그레이션할 때 읽음. 현재는 쓰지 않음 |

`visibility` 내부의 키입니다.

| 키 | 내용 |
|---|---|
| `hiddenSets` | 숨긴 세트 ID |
| `hiddenRenderers` | 숨긴 렌더러 키. 모델 내부의 형제 번호 경로와 렌더러 번호. 예: `000001/000000:0` |

상한은 세트 64개, 렌더러 4096개, 키 2048자입니다.

`standaloneModel`은 `{ "path": <道> }` 구조입니다.
`path`는 모델 파일 (FBX 등)의 .ylp 기준 상대 경로 또는 절대 경로입니다. 1〜1024자 (UTF-16)이며 제어 문자는 사용할 수 없습니다.

상대 경로의 기준은 다음과 같습니다.

- 기준은 .ylp가 있는 폴더입니다.
- 백업 폴더 (`<ファイル名>-backups~/`) 안의 백업은 원래 .ylp가 있던 폴더를 기준으로 합니다.
- 백업 이름은 다음 두 구조 중 하나입니다.
  - 원래 파일에서 확장자를 뺀 이름에 `-`와 UTC 시각 `yyyyMMddTHHmmssfffZ`를 붙인 이름. 시각이 겹치면 뒤에 `_`가 붙습니다.
  - 이전 버전의 SHA-256. 소문자 16진수 64자리입니다.
- 백업의 백업은 원래 파일까지 따라갑니다.
- 모델은 이 기준 폴더 한 곳에서만 찾습니다.
- 이 앱은 저장할 때 같은 기준으로 상대 경로를 씁니다.

### pose.json

모델의 현재 포즈를 가진 상태 엔트리입니다 (루트). 포즈 프리셋 (`.ylpose`)과 같은 표현 방식입니다.

- 기본 형태와의 차이만 보유합니다.
- 본은 이름 경로로, BlendShape는 메시 이름과 BlendShape 이름의 쌍으로 보유합니다.
- 이름 조합이 같은 모델에 복원할 수 있습니다. 일치하지 않는 항목은 복원할 때 이유를 덧붙여 건너뜁니다.

```json
{
  "format": 1,
  "bones": [
    {
      "path": ["Hips", "Spine"],
      "translation": [0.0, 0.01, 0.0],
      "rotation": [0.0, 0.0, 0.1, 0.99],
      "scale": [1.0, 1.0, 1.0]
    }
  ],
  "shapes": [ { "mesh": "Face", "name": "Smile", "weight": 40.0 } ],
  "take": { "name": "Take 001", "frame": 12 }
}
```

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `format` | 정수 | 1 | 다른 값은 읽지 않고 거부 |
| `bones` | 배열 | 최대 4096개 | 본의 차이 |
| `shapes` | 배열 | 최대 4096개 | BlendShape 가중치 |
| `take` | 객체 | 없어도 됨 | 포즈 필드에서 선택한 모델 테이크 |

`bones[]`의 필드입니다.

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `path` | 문자열 배열 | 1〜256단계. 이름은 1〜256자 | 루트에서 본까지의 이름 배열 |
| `translation` | 숫자 3개 | 절댓값 최대 1e6 | 부모 공간에서 더하는 차이 |
| `rotation` | 숫자 4개 | 단위 쿼터니언 x·y·z·w. 길이 허용 오차 0.01 | 본의 로컬 차이. 읽은 뒤 정규화. 현재 회전 = 기본 회전 × 차이 |
| `scale` | 숫자 3개 | 절댓값 최대 1e6 | 기본 크기에 대한 비율 |

`shapes[]`의 필드입니다.

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `mesh` | 문자열 | 1〜256자 | 메시 이름 |
| `name` | 문자열 | 1〜256자 | BlendShape 이름 |
| `weight` | 숫자 | 절댓값 최대 1e4 | Unity와 같은 0〜100 척도 |

`take`의 필드입니다.

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `name` | 문자열 | 1〜256자 | 테이크 (FBX 내부 애니메이션 스택) 이름 |
| `frame` | 정수 | 절댓값 최대 1e9 | 프레임 |

- `take`는 열 때 필드의 선택 상태만 복원합니다. 포즈 값은 `bones`와 `shapes`가 보유합니다.
- 모델에 테이크가 없으면 필드는 첫 테이크를 유지합니다.
- [배포용으로 저장](SAVE_FOR_DISTRIBUTION.md)에서 “모델 참조”를 제외한 복사본에는 이 엔트리를 넣지 않습니다.
- 범위를 벗어난 값·숫자가 아닌 값·단위가 아닌 회전·본이나 BlendShape 중복·개수 상한 초과는 엔트리 전체를 거부합니다.
  일부만 읽지 않습니다. 거부한 엔트리는 바이트열 그대로 남습니다.
- 내부 형식과 원본 버전을 모두 올리지 않는 상태 엔트리입니다.
- `take`는 0.5.0부터 씁니다. 0.4.x 독립 실행형 앱은 알 수 없는 키로 간주하여 건너뜁니다.
  다시 저장하면 사라지지만 잃는 것은 필드의 선택 상태뿐입니다.
- 0.4.x까지의 Unity 브리지는 알 수 없는 엔트리로 알리고 저장 시 제거합니다. 잃는 것은 포즈뿐입니다.
- 독립 실행형 0.3.x는 바이트열 그대로 유지합니다.

### look.json

세트의 3D 뷰 렌더링 방식 (`standard` 물리 기반 렌더링 (PBR) 또는 `lilToon` 재현)과 lilToon일 때의 머티리얼 값을 가진 상태 엔트리입니다.
표준 표시 방식에서 아무것도 설정하지 않은 세트는 엔트리를 쓰지 않습니다.

```json
{
  "format": 1,
  "kind": "lilToon",
  "shader": "Hidden/lilToonCutoutOutline",
  "properties": {
    "_ShadowBorder": { "float": 0.5 },
    "_UseShadow": { "int": 1 },
    "_ShadowColor": { "color": [0.82, 0.76, 0.85, 1.0] },
    "_MainTex_ST": { "vector": [1.0, 1.0, 0.0, 0.0] }
  },
  "textures": {
    "_MainTex": { "channel": 0 },
    "_ShadowStrengthMask": {
      "packed": [ { "channel": 7, "component": 0 }, { "channel": 7, "component": 0 }, "zero", "one" ]
    },
    "_MatCapTex": { "image": "<アセットの画像の id からハイフンを除いた 32 桁の 16 進>" }
  },
  "keywords": [],
  "kindChosen": true,
  "received": {
    "kind": "lilToon",
    "shader": "Hidden/lilToonTransparent",
    "source": "lilToon 2.3.4 · Standard/Transparent",
    "properties": {},
    "textures": { "_MainTex": { "channel": 0 } },
    "keywords": [],
    "missing": { "_MatCapTex": "pending", "_ShadowColorTex": "overBudget" }
  }
}
```

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `format` | 정수 | 1 | 2 이상은 읽지 않고 거부 |
| `kind` | 문자열 | `standard`·`lilToon` | 렌더링 방식. 알 수 없는 `kind`는 읽지 않고 거부 |
| `shader` | 문자열 | 1〜256자 | lilToon 셰이더 이름. 렌더링 모드와 윤곽선은 여기서 읽음 |
| `properties` | 객체 | 최대 2048개 | lilToon 속성 (아래) |
| `textures` | 객체 | 최대 256개 슬롯 | 슬롯별 텍스처 출처 (아래) |
| `keywords` | 배열 | 최대 256개 | 셰이더 키워드 |
| `kindChosen` | 불리언 | 없으면 거짓 | 사용자가 렌더링 방식을 선택했는지 여부 |
| `shaderGuid` | 문자열 | 선택 사항. 1〜128자 | Unity 셰이더 에셋 GUID. 보관만 함. 없으면 알 수 없음 |
| `shaderVersion` | 문자열 | 선택 사항. 1〜128자 | Unity 셰이더 에셋 버전. 보관만 함. 없으면 알 수 없음 |
| `renderQueue` | 정수 | 선택 사항. 부호 있는 32 bit | Unity 머티리얼 렌더링 순서. 보관만 함. 없으면 셰이더 기본값 |
| `received` | 객체 | 선택 사항 | Live Link로 Unity 머티리얼에서 받은 값 (아래) |

- 이름은 1〜128자 (UTF-16)이며 제어 문자는 사용할 수 없습니다. 셰이더 이름은 최대 256자입니다.
- 값은 유한한 숫자만 허용합니다.
- `properties`는 속성 이름과 자료형 (`float`·`int`·`color`·`vector`)을 쌍으로 묶습니다.
  색상은 감마 공간이며 Unity 머티리얼 값과 같습니다. 알 수 없는 속성도 유지합니다.
- `kindChosen`이 거짓이고 Unity에서 받은 값이 있으면 수신한 렌더링 방식으로 그립니다.

`textures`의 슬롯 (텍스처 속성 이름)별 출처는 다음 중 하나입니다.

| 키 | 값 | 의미 |
|---|---|---|
| `channel` | 표준 0〜5, 사용자 채널 6〜63 | 채널 이미지. 문서에 없는 채널은 미할당으로 처리 |
| `packed` | R·G·B·A의 4개. 각각 `zero`·`one`·`{ "channel", "component" }` | 채널 성분을 패킹한 이미지 |
| `image` | 에셋 이미지의 `id`에서 하이픈을 뺀 32자리 16진수 | 에셋 이미지 |

`received` 내부의 키입니다.

| 키 | 의미 |
|---|---|
| `kind`·`shader`·`shaderGuid`·`shaderVersion`·`renderQueue`·`properties`·`textures`·`keywords` | 본체와 같은 구조 |
| `source` | 출처 설명문 |
| `missing` | 이미지가 없는 슬롯의 이유 (아래) |

`missing`의 이유입니다.

| 값 | 의미 |
|---|---|
| `overBudget` | 수신한 이미지 예산 초과 |
| `unreadable` | 이미지 파일을 읽을 수 없음 |
| `notAFile` | 이미지가 Unity 내부에만 있음 |

- 수신한 이미지 픽셀은 쓰지 않습니다.
- 이미지가 있던 슬롯은 `missing`에도 쓰지 않습니다. 다시 열 때 `livelink.json`의 이미지 파일에서 다시 읽습니다.
- 0.4 이하 라이터의 `pending` (아직 도착하지 않음)은 `unreadable`로 읽습니다.
- 그릴 때는 수신한 값 위에 본체를 겹칩니다.
- 다시 쓸 때 이전 엔트리의 `format`이 같으면 알 수 없는 키를 유지합니다.
- 읽을 수 없는 엔트리 (`format`이 2 이상·알 수 없는 `kind`)는 그대로 유지합니다.
  표준 표시 방식으로 열며 표시 설정을 바꾸지 않고 저장하면 유지합니다.
  표시 설정을 바꾸어 저장하면 현재 설정으로 덮어쓰고 저장 알림에서 알려 줍니다.
- 내부 형식과 원본 버전을 모두 올리지 않는 상태 엔트리입니다.
  0.4.x까지의 Unity 브리지는 알 수 없는 엔트리로 알리고 저장 시 제거합니다. 잃는 것은 표시 설정뿐입니다.

### livelink.json

Live Link 상대 문서 (Unity 장면의 오브젝트를 연 문서)를 보유하는 상태 엔트리입니다 (루트).
Unity 없이 다시 열어도 같은 모델 (FBX 순서·렌더러와 머티리얼 연결)과 포즈가 되도록 저장합니다.
내용은 Live Link 요청 ([LIVELINK.md](LIVELINK.md)의 “요청”)과 같은 구조이며 `format`은 1, `kind`는 `"open"`입니다.

| 키 | 내용 |
|---|---|
| `target` | 상대 식별 정보 `key`·이름·내보내기 위치 |
| `models` | FBX 절대 경로·GUID·가져오기 설정 |
| `renderers` | 렌더러 경로·FBX 내부 메시 경로·켜짐/꺼짐·서브메시별 머티리얼 번호·현재 BlendShape 가중치 |
| `bones` | 현재 포즈에서 기본 상태와 다른 본의 FBX 부모 본에 대한 로컬 값 |
| `materials` | 키·이름·셰이더 식별 정보·텍스처 경로 (아래) |
| `refused` | Unity가 보내지 못한 렌더러 |

- `materials`에는 값을 쓰지 않습니다. 값은 각 세트의 `look.json`의 `received`에 있습니다.
- 단, lilToon 식별 값 `_lilToonVersion`만 유지합니다. 다시 열 때 lilToon 슬롯의 이미지를 파일에서 읽을지 결정합니다.
- 본 경로는 Unity 루트에서 이름을 따라 내려갑니다.
- 경로로 가리킬 수 없는 본의 값은 쓸 수 없습니다. 접힌 FBX 루트 본처럼 Unity 루트 밖에 있는 본과 이름이 같은 형제 본이 이에 해당합니다.
  저장 알림에 본 이름을 표시합니다. 다시 열면 기본 상태로 돌아갑니다.
- 이 앱은 크기·JSON 객체·`format` 1을 확인하며 (`livelink::validate`), 내용은 Live Link 요청과 같은 규칙으로 읽습니다.
  규칙은 개수 상한·유한한 숫자·번호 범위입니다.
- 읽을 수 없으면 모델을 다시 열지 않고 엔트리를 바이트열 그대로 유지합니다.
- FBX·이미지 경로가 네트워크 경로 (`\\host\share`)이면 열 때 자동으로 읽지 않습니다.
- 다시 열 때는 키로 세트를 연결하기만 하며 추가하지 않습니다. 원래 이미지를 다시 넣지 않습니다 (레이어에 포함되어 있음).
  슬롯 이미지는 경로에서 다시 읽습니다.
- 모델을 FBX 또는 형상과 함께 전달된 메시로 바꾸어 저장하면 엔트리를 제거합니다.
- 아직 모델이 없는 동안의 저장은 엔트리를 건드리지 않습니다. 모델이 없는 경우는 다시 여는 도중과 다시 열지 못했을 때입니다.
- [배포용으로 저장](SAVE_FOR_DISTRIBUTION.md)에서 “모델 참조”를 제외한 복사본에는 이 엔트리를 넣지 않습니다. FBX와 이미지 파일의 절대 위치를 포함하기 때문입니다.
- 내부 형식과 원본 버전을 모두 올리지 않는 상태 엔트리입니다.
  - 독립 실행형 0.4.x는 알 수 없는 엔트리로 알리며 다시 저장해도 바이트열 그대로 유지합니다.
    모델은 열지 않지만 세트는 열 수 있습니다.
  - 0.4.x까지의 Unity 브리지는 알리고 저장 시 제거합니다. 잃는 것은 상대 기록과 포즈뿐입니다.

### selection.bin

현재 선택 영역입니다. 본체 엔트리이며 little-endian입니다. 선택 영역 버전은 1입니다.

| 필드 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| 식별자 | 4 byte | `YLSL` | |
| 선택 영역 버전 | int | 1 | |
| 너비·높이·타일 크기 | int 3개 | 세트 원본과 다르면 거부 | |
| 타일 수 | int | 0〜열 × 행 | |
| 각 타일 | | | `x`·`y` int와 양 (아래) |

타일별 필드입니다.

| 필드 | 자료형 | 의미 |
|---|---|---|
| `x`·`y` | int 2개 | 타일 위치. 왼쪽 아래 타일은 (0, 0). `y × 列 + x`의 오름차순 |
| 양 | 타일 크기² byte | 아래쪽 행부터. 0이 아닌 양이 1개 이상. 문서 밖 여백은 0 |

- 양이 있는 타일만 쓰므로 같은 선택 영역은 항상 같은 바이트열입니다.
- 길이 불일치·순서 불일치·세트 원본과 크기 불일치는 열기를 거부합니다.
- 0.4.x까지의 Unity 브리지는 이유를 알리고 선택 영역 없이 엽니다.

### selections.json과 저장한 선택 영역

이름을 붙여 저장한 선택 영역입니다 (내부 형식 8).

```json
{ "format": 1, "selections": [ { "name": "前髪", "content": "<中身の印>" } ] }
```

색인은 `sets/<ID>/selections.json`입니다.

| 키 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `format` | 정수 | 1 | 다른 값은 읽지 않음 |
| `selections` | 배열 | 세트 1개당 최대 32개 | 저장한 선택 영역. 배열 순서 |
| `selections[].name` | 문자열 | 1〜256자. 앞뒤 공백 없음. 제어 문자 없음 | 이름. 배열 안에서 중복 없음 |
| `selections[].content` | 문자열 | 소문자 16진수 32자리 | 내용 식별자 |

내용은 `sets/<ID>/selection-<印>.bin`입니다.

- 구조는 `selection.bin`과 같으며 `YLSL`의 선택 영역 버전은 1입니다.
- 식별자는 내용 바이트열의 SHA-256 앞쪽 128 bit입니다. 엔트리 이름이 최대 96바이트이므로 소문자 16진수 32자리로 나타냅니다.
- 같은 내용은 하나의 엔트리를 공유합니다.

규칙은 다음과 같습니다.

- 알 수 없는 키는 건너뜁니다.
- 이 앱은 손상된 항목만 이유를 덧붙여 건너뛰고 읽을 수 있는 항목은 읽습니다.
- 건너뛴 엔트리는 저장된 선택 영역을 다시 쓸 때까지 바이트열 그대로 남습니다.
- 문서와 크기가 다른 것은 건너뜁니다.
- 이 앱은 다시 쓸 때 이전 색인과 `selection-*.bin`을 세트별로 모두 교체합니다. 더 이상 사용하지 않는 내용은 남기지 않습니다.
- 엔트리가 하나라도 있으면 `ylp.json`의 `format`을 8로 설정합니다. 전부 없어지면 7로 되돌립니다.
  외부 `YLP-3`은 바꾸지 않습니다.

## document.utpaint

`document.utpaint`는 세트 원본입니다. 한 세트의 모든 레이어·픽셀·설정을 가진 바이너리입니다.
이 앱의 리더는 `native.rs`의 `NativeDocument::read`이며 core 문서와의 변환은 `core_bridge.rs`에서 수행합니다.

아래 표는 다음과 같이 읽습니다.

- 표의 행은 파일에 쓰이는 순서로 나열합니다.
- “필드”는 이 앱의 리더가 항목에 붙이는 이름입니다. `NativeDocument::fields()`의 경로이며 예는 `layers[0].opacity`입니다.
- “버전” 열은 해당 필드가 있는 원본 버전입니다. 빈칸은 모든 원본 버전에 있는 필드입니다.

<a id="値の型"></a>

### 값의 자료형

little-endian입니다.

| 자료형 | 바이트 |
|---|---|
| int | 4 (부호 있음) |
| byte | 1 |
| bool | 1. 0 또는 1. 그 외는 거부 |
| double | 8 (IEEE 754). 범위 밖·NaN·무한대는 거부 |
| GUID | 16. C#의 `Guid.ToByteArray()` 순서이며 처음 3개 구간은 little-endian. 비어 있으면 모두 0 |
| 문자열 | int 길이 (0〜4096바이트)와 UTF-8 |
| 바이트열 | 고정 길이. 색상의 RGBA8은 4, RGB는 3, 타일은 타일 크기² × 4 |
| 블록 | 필드를 연속으로 배치한 것. 표에서 “블록”이라고 쓰면 그 아래 표가 내용 |

- 좌표 원점은 왼쪽 아래입니다.
- 타일의 `x`·`y`는 왼쪽 아래 타일이 (0, 0)입니다.
- 타일 안의 픽셀은 아래쪽 행부터, 행 안에서는 왼쪽부터 나열합니다.
- 픽셀은 straight RGBA8이며 투명 픽셀의 RGB도 유지합니다.

#### layer_sets와 route

레이어 세트 (원본 버전 36)는 세트 안의 이름 있는 레이어 묶음입니다.
출력 할당은 채널별로 세트의 최종 결과를 어느 레이어 세트에서 가져올지 지정합니다.

- 모든 레이어는 어느 하나의 레이어 세트에 속합니다 (레이어 끝의 `set`). 그룹의 자식은 부모와 같은 레이어 세트에 속합니다.
- 문서에는 하나의 레이어 배열이 있습니다. 합성은 레이어 세트별로 해당 레이어 세트의 레이어만 사용하여 수행합니다.
  최상위 형제는 같은 레이어 세트의 레이어만 해당합니다 (클리핑 바탕도 해당 레이어 세트 안에서 결정).
- 채널 c의 최종 결과는 `route`에서 c에 할당한 레이어 세트의 c 합성입니다. 할당이 비어 있으면 c의 기본값으로 채운 픽셀입니다.
  내보내기·합성 PNG·베이크 읽기·Live Link는 최종 결과를 읽습니다.
- 효과 (필터·Generator·Anchor)는 해당 레이어의 레이어 세트 안에서만 읽습니다.
  다른 레이어 세트의 Anchor를 가리키는 참조는 사라진 Anchor처럼 처리합니다 (열기를 거부하지 않고 해당 단계가 입력을 통과시키며 이유를 알림).

`layer_sets[i]`의 필드입니다.

| 필드 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `id` | GUID | 비어 있지 않음. 문서 안에서 중복 없음 | 레이어 세트 ID |
| `name` | 문자열 | 0〜4096바이트. 제어 문자 없음. 비어 있어도 됨 | 이름. 비어 있으면 화면에서 언어별 기본 이름으로 표시 |

`route[i]`의 필드입니다.

| 필드 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `channel` | int | 문서의 채널. 모든 채널을 오름차순으로 한 번씩 | 채널 번호 |
| `set` | GUID | 비어 있거나 `layer_sets`에 있는 ID | 최종 결과를 가져올 레이어 세트. 비어 있으면 해당 채널의 기본값 |

- 이 앱은 레이어 세트가 하나이고 이름이 비어 있으며 모든 채널이 그 세트에 할당된 문서를 원본 버전 35 이하로 씁니다.
  필드를 쓰지 않으며 레이어 세트가 없던 시절과 같은 바이트열입니다. 이전 버전 원본은 이 구조로 읽습니다.
- 개수·ID·이름·할당 순서·참조 ID·그룹 자식의 레이어 세트 중 하나라도 맞지 않는 원본은 열기를 거부합니다. 알림 없이 고치지 않습니다.

| `part` | int | 0〜3999999. 엄격한 오름차순 | 메시 파트 번호 |
| `rgb` | int | 0〜0xFFFFFF | 색상. 0xRRGGBB |

- 이 앱은 색상이 하나라도 있을 때만 블록을 씁니다. 비어 있으면 블록을 쓰지 않으며 색상이 없는 문서와 같은 바이트열이 됩니다.
- 블록은 원본 버전 19부터 넣을 수 있습니다. 이 앱이 쓰는 원본 버전 (21 이상)은 모두 19 이상이므로 색상 때문에 원본 버전이 올라가지 않습니다.
  색상만 가진 문서는 0.4.x까지의 Unity 브리지가 읽을 수 있는 21을 유지합니다.
- `binding`은 색상을 지정할 때의 모델 지문입니다. 삼각형의 UV·슬롯·렌더러 토폴로지와
  모든 삼각형의 메시 파트 번호 배열로 만듭니다.
- 이 앱은 현재 모델과 일치하는지 확인하지 않고 저장된 그대로 문서에 복원합니다.
- 현재 모델과 맞지 않는 색상은 다른 모델의 것으로 처리합니다. 색상 편집과 ID 맵 베이크를 거부하지만 버리지는 않습니다.
  모두 초기화하면 제거할 수 있습니다.
- 색상은 파트 번호 (메시 파트의 일련번호)로 연결됩니다.
  모델의 파트 수나 순서가 바뀌면 지문이 달라져 다른 모델의 것으로 처리합니다. 번호를 이용하여 색상을 다른 파트에 할당하지 않습니다.

#### 자

자 (원본 버전 35)는 레이어 (그룹 포함)에 부착하는 그리기용 스냅 대상과 대칭입니다. 레이어와 함께 저장합니다.

- 위치는 레이어 끝입니다. `text` 뒤이며 `text`가 없는 레이어도 같은 위치입니다.
- `ruler_count`는 1〜64입니다. 한 레이어에 최대 64개의 자를 부착할 수 있습니다.
- ID는 문서 안에서 중복되지 않습니다. 레이어·Anchor·필터 ID와는 별개입니다.

`rulers[i]`의 필드입니다.

| 필드 | 자료형 | 범위 | 의미 |
|---|---|---|---|
| `id` | GUID | 비어 있지 않음. 문서 안에서 중복 없음 | 자 ID |
| `kind` | byte | 0〜4 | 0 직선자·1 평행선·2 동심원·3 원근·4 대칭 |
| `space` | byte | 0〜1 | 0 2D (문서 픽셀, 왼쪽 아래 원점)·1 3D (모델 공간) |
| `flags` | byte | 아래 비트만 | 플래그 |
| `scope` | byte | 0〜2 | 표시 범위. 0 모든 레이어·1 같은 그룹 내부·2 선택했을 때만 |
| `lines` | byte | 대칭은 2〜16, 나머지는 0 | 선 개수 |
| `a_x`·`a_y`·`a_z` | double | 2D는 ±1e7, 3D는 ±1e6 | 점 a. `a_z`는 3D만 |
| `b_x`·`b_y`·`b_z` | double | `a_x`와 같음. a와 떨어져 있음 | 점 b. `b_z`는 3D만 |
| `up_x`·`up_y`·`up_z` | double | 3D만. ±1e6. 길이가 0이 아님 | 방향. 읽은 뒤 단위 벡터로 변환 |

`flags`의 비트입니다.

| 비트 | 의미 |
|---|---|
| 0 | 표시 |
| 1 | 스냅하는 특수자 플래그. 직선자는 0 |
| 2 | 2점 원근. 원근만 |
| 3 | 선대칭. 대칭에서 `lines`가 짝수일 때만. 0은 회전 대칭 |
| 4 | 보이지 않는 면에도 복사. 3D 대칭만 |
| 5〜7 | 0 |

점의 의미는 종류별로 다음과 같습니다.

| 종류 | a | b | up (3D) |
|---|---|---|---|
| 직선자 | 끝점 | 끝점 | 생성한 면의 노멀 |
| 평행선 | 선 위의 한 점 | 방향 (a에서 b) | 생성한 면의 노멀 |
| 동심원 | 중심 | 표시 반경 (a에서 b까지의 길이) | 원 평면의 노멀 |
| 원근 | 소실점 1 | 2점일 때 소실점 2 | 생성한 면의 노멀 |
| 대칭 | 중심 | 첫 번째 선 방향 (a에서 b) | 회전축. 첫 거울 평면은 `up`과 b − a를 포함 |

- 3D 점은 모델 공간입니다. 투영 박스·데칼·3D 대칭과 같은 공간이며 모델의 삼각형에 연결되지 않습니다.
- 대칭 복사본은 선대칭 N개가 이면체군의 N개, 회전 대칭 N개가 회전 N개입니다.
  - 2D에서 선대칭은 `canvas_symmetry`의 `mode` 5와, 회전 대칭은 방사형 (`mode` 4)과 같은 복사입니다.
  - 3D에서는 거울 1개 (`a`를 지나며 `up`과 b − a를 포함하는 평면)와 `up` 주위 회전입니다.
    선대칭 N개는 거울 1개와 N/2개 회전 (N이 2이면 거울만), 회전 대칭 N개는 N개 회전입니다.
- 값 검사는 다음과 같습니다. 좌표가 유한하고 `a`와 `b`가 떨어져 있어야 하며 (2D는 0.01픽셀, 3D는 1e-6),
  3D 대칭에서는 b − a가 `up`과 평행하지 않아야 합니다.
- 해당 종류에 없는 플래그는 0입니다. `lines`는 대칭만 가지며, `flags` 비트 2는 원근, 비트 3은 대칭, 비트 4는 3D 대칭만 사용합니다.

아일랜드별 변동 (67)의 값은 다음과 같이 결정합니다.

- 텍셀의 모델 UV 아일랜드 (UV에서 변을 공유하여 연결된 삼각형) 번호 i와 `seed`로 u를 구합니다.
  - u = `cell_hash(seeds(seed)[0], i, 0, 0)` × 2^-32이며 [0, 1)입니다.
  - `cell_hash`는 노이즈와 같은 정수 hash입니다.
- `min + (max − min) × u`를 `low`·`high`·`softness`·`invert`에 통과시킨 값을 `blend`로 결합합니다.
- 아일랜드 번호는 1부터 시작하며 아일랜드의 가장 작은 삼각형 번호순입니다. 모델이 같으면 해상도와 관계없이 같습니다.
- 아일랜드 밖의 텍셀은 입력 그대로입니다.
- UV가 겹친 텍셀은 번호가 작은 삼각형의 아일랜드 값을 사용합니다.
- 모델이 없거나 아일랜드 맵이 작업 메모리 예산에 들어가지 않으면 단계가 입력을 통과시키고 이유를 알립니다.
  예산은 문서의 아일랜드 맵·행 구간 복사본 예산입니다.
- 아일랜드 맵은 저장하지 않습니다. 모델에서 다시 만듭니다.

이미지 (70) 단계는 다음과 같이 값을 결정합니다.

- 채우기 레이어 이미지와 같은 투영·같은 밉맵 읽기 방식으로 이미지를 읽습니다.
- 색상 채널에서는 해당 픽셀 색상을 사용합니다. `invert`는 RGB를 반전하고 알파는 표시 정도에 곱합니다.
- 마스크·스칼라 채널에서는 선택한 성분을 `low`·`high`·`softness`·`invert`에 통과시킨 값을 `blend`로 결합합니다.
- 이미지 값이 없는 픽셀은 입력 그대로입니다. 바깥을 투명하게 처리하는 이미지의 외부와 위치 맵에서 면이 없는 픽셀이 이에 해당합니다.
- 이미지를 선택하지 않았거나·에셋에 없거나·읽을 수 없거나·투영이 읽는 맵을 사용할 수 없으면 단계가 입력을 통과시키고 이유를 알립니다.

### 경로 목록

한 레이어에서 아래부터 순서대로 그리는 경로 배열입니다 (원본 버전 27).

- 레이어 대상 채널의 픽셀은 표시할 경로를 같은 작업 표면에 순서대로 그린 결과입니다.
- 뒤쪽 경로가 앞쪽 경로 위에 겹쳐집니다. 지우개 경로는 앞쪽 경로의 픽셀을 지웁니다.

채우기 레이어의 경로는 다음과 같습니다.

- 픽셀 (`channels`)은 경로를 그린 결과만 포함합니다.
- 합성은 채우기 → 해당 레이어의 효과 스택 → 경로 픽셀 순서로 겹칩니다.
- 경로 픽셀은 “일반” 모드로 겹칩니다. 공식은 `src · a + dst · da · (1 − a)`입니다.
- 채우기 레이어의 경로는 하나여도 목록 구조로 씁니다. 단일 경로 필드는 래스터 레이어만 사용할 수 있습니다.

| 필드 | 자료형 | 내용 |
|---|---|---|
| `count` | int | 1〜256 |
| `items[i].name` | 문자열 | 0〜128자 (UTF-16). 제어 문자 없음. 비어 있으면 화면에서 순서 번호로 이름을 만듦 |
| `items[i].visible` | bool | 거짓이면 그리지 않음. 점과 설정은 유지 |
| `items[i].surface` | bool | 참이면 3D 경로 (`model_fingerprint`가 있는 배열), 거짓이면 2D 경로 |
| `items[i].path` | 블록 | [경로](#パス)와 같은 배열 |
| `items[i].extra` | 블록 | 단일 경로 배열에 없는 설정 ([경로 확장](#パスの拡張)) |

- 목록의 경로는 모두 같은 구분 (2D 또는 3D)·같은 `channel`·같은 `model_fingerprint` (3D일 때)를 사용하며 `id`가 중복되지 않습니다.
  이 앱은 일치하지 않는 것을 거부합니다.
- 이 앱은 다음 경로 레이어만 목록 구조로 씁니다.
  - 채우기 레이어의 경로
  - 경로가 2개 이상인 경로 레이어
  - 이름을 붙인 경로 레이어
  - 숨긴 경로 레이어
  - 확장 설정을 사용하는 경로 레이어. 스트로크·지우개 외의 종류·브러시 끝·깊이·대칭·부드럽지 않은 점입니다.
- 이름 없이 표시되는 경로 하나는 기존처럼 `surface_path`·`canvas_path`에 씁니다.
  스트로크 또는 지우개이며 원형 브러시 끝·각도 0·자동 깊이·대칭 없음·부드러운 점만 있는 경로입니다.

그리는 방법의 자세한 규칙은 `crates/yolu-core/src/paths/README.md`에 있습니다. 각 종류의 의미는 다음과 같습니다.

- 스트로크: 원형 브러시 스트로크입니다. 기존 경로와 같습니다.
- 지우개: 스트로크와 같은 방식으로 목록 앞쪽 경로의 픽셀을 지웁니다.
  단일 경로 필드로 쓸 때는 브러시의 `erase` 플래그로 지우개 종류를 표시합니다. 0.4.x까지의 Unity 브리지와 같은 배열입니다.
  모든 리더는 단일 경로 필드의 `erase` 플래그를 지우개 종류로 읽습니다.
- 문지르기: 목록 앞쪽 경로의 픽셀을 경로를 따라 끌어당깁니다.
- 채우기: 경로 곡선의 안쪽을 브러시 색상·머티리얼 쌍의 값과 불투명도로 칠합니다.
  - 열린 경로는 끝에서 시작으로 닫습니다.
  - 내부는 감김 수가 0이 아닌 영역입니다.
  - 3D는 모든 점이 하나의 UV 아일랜드에 있을 때만 가능합니다.
    곡선을 표면에 투영한 UV 다각형의 내부 중 해당 아일랜드 UV에 들어가는 영역을 칠합니다.
- 리본: 에셋 이미지를 경로 방향으로 회전한 직사각형 브러시 자국으로 나열합니다. 너비는 브러시 지름입니다.
  - 색상 유형 채널 (Color·Emission)은 이미지 색상을 사용합니다.
  - 다른 채널은 머티리얼 쌍의 값 (없으면 브러시 색상)을 사용합니다.
  - 둘 다 이미지 알파를 커버리지로 사용하여 겹칩니다.
  - 에셋에 없는 이미지의 리본은 다시 그릴 수 없습니다. 저장된 픽셀은 유지됩니다.

대칭은 다음과 같이 작동합니다.

- 반사된 쪽은 저장하지 않습니다. 그릴 때 생성하여 원래 경로 바로 뒤에 그립니다.
- 2D는 캔버스 대칭 복사로 점과 핸들을 복사합니다. 첫 항등 복사본은 원래 경로입니다.
  - 선대칭 (`mode` 5)의 복사본은 `count`개입니다. `count / 2`개의 거울 (축 각도는 `angle` + 180도 × k / (`count` / 2))과 `count / 2`개의 회전입니다.
  - `mode` 5에서 `angle`이 90도이고 `count`가 2이면 세로, 0도이고 2이면 가로, 0도이고 4이면 양쪽과 같은 복사입니다.
- 3D는 거울 평면으로 점 위치를 반사하여 반사된 위치에서 가장 가까운 면에 배치합니다.
  배치 가능한 면은 같은 머티리얼이고 방향이 맞으며 허용 거리 안에 있는 면입니다.
  허용 거리는 브러시 반경과 모델 바운딩 박스 대각선의 1% 중 큰 값입니다.
- 배치할 수 없는 점이 있으면 해당 복사본은 그리지 않습니다.

브러시 끝은 다음과 같이 배치합니다.

- 2D는 일반 브러시 끝과 같습니다. 각도는 캔버스 방향 기준이며 `follow`이면 선 방향 기준입니다.
- 3D는 표면 브러시 자국 중심의 접평면에 브러시 끝을 배치합니다.
  - 가로축은 `follow`이면 경로 진행 방향입니다.
  - 그렇지 않으면 모델 +Y를 접평면에 투영한 방향입니다. 평행하면 +X·+Z를 사용합니다.
  - 거기서 지정 각도만큼 회전합니다.
- 자동 깊이는 브러시 자국 간격의 4배·구간 길이의 1/4·반경의 4배 중 가장 큰 값입니다. 기존 공식과 같습니다.

탄젠트의 의미는 다음과 같습니다.

- 구간 (점 s → s + 1)의 양 끝이 부드러우면 곡선은 기존처럼 점을 순서대로 통과하는 centripetal Catmull–Rom입니다.
- 어느 한쪽 끝이 모서리 또는 핸들이면 3차 베지어입니다.
  - 부드러운 끝의 제어점은 해당 끝의 Catmull–Rom 미분 m으로부터 `点 ± m · (t2 − t1) / 3`입니다. t는 centripetal 매개변수입니다.
  - 모서리 끝의 제어점은 점 자체입니다.
  - 핸들 끝의 제어점은 점 + 핸들입니다. 나가는 쪽은 `outgoing`, 들어오는 쪽은 `incoming`입니다.

### 텍스트

텍스트 레이어 (원본 버전 30)는 래스터 레이어가 텍스트 값을 가진 것입니다.

- 레이어 Color 채널의 픽셀은 이 값과 글꼴로 그린 결과입니다. 다른 레이어와 같은 타일로 저장합니다.
- 이 앱은 픽셀을 그대로 표시하며 열 때 다시 그리지 않습니다.
- 글꼴 파일은 포함하지 않습니다.

| 필드 | 자료형 | 내용 |
|---|---|---|
| `algorithm` | int | 1. 배치와 채우기 버전 (아래) |
| `content` | 문자열 | 텍스트. UTF-8 기준 최대 4096바이트. 줄바꿈은 LF, 다른 제어 문자는 탭만 허용 |
| `font_kind` | int | 0 앱에 포함된 글꼴·1 글꼴 파일. OS에 설치된 글꼴과 사용자가 선택한 파일 모두 1 |
| `font_name` | 문자열 | `font_kind`가 0일 때. 포함된 글꼴 이름. `a-z`·`0-9`·`-`의 1〜64자. 현재 이름은 `biz-udpgothic`·`biz-udpgothic-bold` |
| `font_path` | 문자열 | `font_kind`가 1일 때. 글꼴 파일 경로. 1〜4096바이트, 제어 문자 없음. [배포용으로 저장](SAVE_FOR_DISTRIBUTION.md) 복사본은 “에셋 출처 경로”를 제외하도록 선택했을 때만 (기본 전체 선택에서는 제외) 디렉터리를 뺀 파일 이름만 사용. 제외하지 않으면 절대 경로 (사용자 이름이 포함될 수 있음)가 그대로 남음 |
| `font_index` | int | `font_kind`가 1일 때. 컬렉션 (.ttc) 내부 번호. 0 이상. 컬렉션이 아니면 0 |
| `font_sha256` | 문자열 | `font_kind`가 1일 때. 선택 당시 파일 내용의 SHA-256. 소문자 64자리 |
| `font_family` | 문자열 | `font_kind`가 1일 때. 글꼴 패밀리 이름. name의 16번, 없으면 1번. 영어 이름, 없으면 첫 이름. 0〜256바이트, 제어 문자 없음. 읽지 못한 이름은 빈 문자열 |
| `font_postscript` | 문자열 | `font_kind`가 1일 때. PostScript 이름 (name의 6번). 0〜256바이트, 제어 문자 없음. 읽지 못한 이름은 빈 문자열 |
| `font_weight` | int | `font_kind`가 1일 때. 굵기. OS/2의 usWeightClass, 1〜1000 |
| `font_italic` | bool | `font_kind`가 1일 때. 기울임꼴 여부. OS/2의 fsSelection에서 이탤릭·오블리크 |
| `size` | double | 크기. 1 em의 픽셀 수, 1〜4096 |
| `rgba` | RGBA8 | 글자 색상. 알파는 글자 불투명도이며 레이어 불투명도와 별개 |
| `line_height` | double | 줄 간격 (줄 이동량). 크기에 곱함, 0.1〜10 |
| `letter_spacing` | double | 자간 (글자마다 추가할 이동량). 크기에 곱함, −1〜10 |
| `align` | int | 0 왼쪽·1 가운데·2 오른쪽 |
| `x`·`y` | double | 기준점. 문서 픽셀, 왼쪽 아래 원점, ±1000000. 첫 줄 위쪽 끝이며 줄은 아래로 진행 |
| `rotation` | double | 기준점 주위 회전. 도, 시계 반대 방향이 양수, −360〜360 |
| `wrap_width` | double | 줄바꿈 너비. 픽셀, 0〜1000000. 0은 줄바꿈 없음 |

`wrap_width`가 0이면 정렬 기준은 기준점입니다. 0이 아니면 기준점에서 오른쪽으로 이 너비만큼의 박스가 기준입니다.

배치와 채우기 (`algorithm` 1)는 다음과 같습니다.

- 문단별로 왼쪽에서 오른쪽으로 배치합니다. 오른쪽에서 왼쪽으로 쓰는 문자와 세로쓰기는 처리하지 않습니다.
- 줄바꿈 너비가 있으면 공백 뒤와 CJK 문자 사이에서 나눕니다.
- 힌팅 없이 윤곽을 채웁니다. 안티앨리어싱 커버리지를 알파로 사용합니다.
  덮이지 않는 픽셀은 투명하며 RGB도 0입니다.
- 값·글꼴이 같으면 CPU·스레드 수와 관계없이 같은 바이트가 됩니다.
- 공식을 바꾸어 같은 값의 픽셀이 달라지면 `algorithm`을 올립니다.
  저장된 픽셀은 바뀌지 않으며 텍스트를 수정하여 다시 그릴 때만 새 공식을 사용합니다.
- 가변 글꼴은 기본 인스턴스로 그립니다.

글꼴 검색 규칙은 이 앱의 규칙입니다. 모든 리더가 지켜야 하는 검사는 아닙니다.

- 포함된 글꼴은 이름으로 찾습니다.
- 파일 글꼴은 다음 순서로 찾습니다.
  1. `font_path` 파일의 내용이 `font_sha256`과 같으면 이를 사용합니다.
  2. 다르거나 없으면 OS에 설치된 글꼴을 `font_postscript` → `font_family`와 `font_weight` (및 `font_italic`) 순서로 찾습니다.
  3. 마지막으로 `font_path`의 파일을 사용합니다.
     절대 경로일 때만 사용합니다. 파일 이름만 있거나 상대 경로이면 현재 작업 폴더의 다른 파일을 잘못 선택하지 않도록 사용하지 않습니다.
- 찾은 내용의 SHA-256이 다르면 “글꼴이 다릅니다”라고 알립니다.
  저장된 픽셀은 유지하며 텍스트를 수정할 때 찾은 글꼴로 다시 그립니다.
  값의 경로·SHA-256·이름도 해당 글꼴의 것으로 바뀝니다.
- 어디에도 없으면 열기를 거부하지 않고 저장된 픽셀을 그대로 표시합니다.
  텍스트 값 편집만 이유를 덧붙여 거부합니다. 알림 없이 다른 글꼴로 다시 그리지 않습니다.

### 문서 전반의 규칙

- 효과 (필터·Generator·Anchor·채우기 이미지와 그라데이션)와 경로는 세트 원본에 설정을 보유하며 평가 출력은 쓰지 않습니다.
  - 평가는 읽은 뒤 합성할 때 수행합니다.
  - `composite/<チャンネル>.png` 합성에도 효과가 포함됩니다.
  - 입력이 갖추어지지 않은 단계는 입력을 그대로 통과시킵니다.
- 부모 (`parent`)는 문서에 있는 그룹이며 자식보다 위 (더 큰 번호)에 있습니다. 그룹 자식은 부모 바로 아래에 연속으로 나열됩니다.
- 이 앱의 그룹 중첩은 최대 64단계입니다 (`yolu_core::MAX_GROUP_DEPTH`).
  이를 넘는 파일은 상한 초과로 거부합니다. 0.4.x까지의 Unity 브리지 리더에는 상한이 없습니다.
- Anchor ID와 필터 ID는 문서 안에서 중복되지 않습니다.
- Anchor 단계가 자신의 레이어 Anchor를 가리키면 거부합니다.
- 사라진 Anchor나 읽는 레이어보다 위에 있는 Anchor를 가리키는 참조는 열기를 거부하지 않고 그대로 읽습니다.
  해당 단계는 입력을 통과시키고 이유를 알립니다. 저장해도 참조는 유지됩니다.
- 에셋에 없는 `resource_id`는 열기를 거부하지 않고 ID를 유지합니다.
  채우기 값을 표시하고 알립니다. 이미지 Generator 단계는 입력을 통과시키고 알립니다.
- 채우기 그라데이션은 알고리즘 버전 2·혼합 Replace여야 합니다.
- 포인트 그라데이션 (알고리즘 버전 1)의 값은 다음과 같습니다.
  - 점 i의 가중치는 `1 / (d² + s²)`입니다. d는 점까지의 거리, s는 퍼짐 × 길이입니다.
  - 길이는 모델 공간이면 위치 맵 박스의 대각선, UV 공간이면 1입니다.
  - 색상은 불투명도로 가중하여 혼합합니다. 불투명도는 가중치로 혼합합니다.
  - s가 0이고 점 바로 위이면 해당 점의 색상입니다.
  - 모델 공간에서는 다음 경우 채우기 값을 표시하고 이유를 알립니다.
    위치 맵이 덮지 않는 픽셀과, 위치 맵 또는 모델 루트를 사용할 수 없는 문서입니다.

### 분할 원본

분할 전 원본 (분할 전 원본 버전 21〜25·27〜30·32〜36 배열)이 512 MiB를 넘는 문서만 나누어 씁니다. 원본 버전은 26입니다.

| 엔트리 | 내용 |
|---|---|
| `document.utpaint` (헤더) | `DOTPAINT`, int 26, int 분할 전 원본 버전, int 부분 수 (1 이상). 이어서 분할 전 배열 (`id`부터 끝까지)에서 바이트열 값 (색상·픽셀. `magic` 이외 전부)을 뺀 내용 |
| `document.utpaint.1`·`.2`… | 바이트열 값을 배열 순서로 기록. 번호는 1부터 연속. 0 시작·앞에 0 채움·번호 건너뛰기는 거부 |

이 앱은 다음과 같이 나누어 씁니다.

- 두 번째 레이어부터 각 레이어의 시작과 256 MiB를 넘기 직전에 나눕니다. 하나의 값은 나누지 않습니다.
- 현재 부분과 다음 레이어 값이 모두 16 MiB 미만이면 레이어 시작에서 나누지 않습니다.
- 변경되지 않은 레이어 부분은 이전과 같은 내용이 되어 복구 세대 사이에 공유됩니다.
- 레이어 뒤의 값 (수동 ID 색상의 `tag`)은 마지막 레이어 값으로 계산합니다.
- 수동 ID 색상 블록은 `tag` (`YLID`)가 `Bytes` 값이므로 마지막 부분에 들어갑니다.
  `count`·`binding`·색상 배열은 일반 값이므로 헤더 끝에 들어갑니다.

분할 위치는 고정되어 있지 않습니다. 모든 리더는 위치를 가정하지 않고 다음을 확인합니다.

- 값이 부분 경계를 넘지 않음.
- 빈 부분이 없음.
- 부분 수 (헤더와 엔트리)가 일치함.
- 모든 부분을 남김없이 사용함.

읽은 항목은 분할 전 원본을 읽은 것과 같습니다.

부분 이름은 현재 이름 규칙 안에 들어갑니다. 따라서 `YLP-3` 크기 한도 안의 파일에도 원본 버전 26의 원본이 들어갈 수 있습니다.

### composite의 합성 PNG

`composite/<チャンネル>.png`입니다. `<チャンネル>`은 `Color`·`Roughness`·`Metallic`·`Height`·`Normal`·`Emission`입니다.

- 어느 레이어에서든 활성화한 각 표준 채널에 대해 세트 원본의 합성을 씁니다.
- 형식은 straight RGBA8 PNG입니다. 색상 유형 6이며 보조 청크가 없고 픽셀은 위쪽 행부터입니다.
- `Color`는 사용하는 레이어가 없어도 씁니다.
- Height에서 Normal을 생성하는 설정이고 Height를 사용하면 `Normal`도 씁니다. Normal은 OpenGL 방향입니다.
- 사용자 채널 합성은 쓰지 않습니다.
- 세트 원본을 교체하면 해당 세트의 `composite/`를 지운 뒤 다시 씁니다.
- 0.4.x까지의 Unity 브리지 임포터는 이 배열에서 세트 채널을 추출합니다.

| UV 채널 | int | |
| 너비 | int | |
| 높이 | int | |

| 패딩 | int | |

- 압축 해제한 내용은 커버리지 byte (텍셀 수) 다음에 채널별 평면 2개가 이어집니다.
  - 16 bit 값의 상위 byte 평면
  - 16 bit 값의 하위 byte 평면

설정 키는 다음과 같습니다.

- ID 맵 출처는 `source=<元>;algorithm=2`입니다. 필요하면 다음 키가 붙습니다.
  - 머티리얼 식별: `materials=<SHA-256>`
  - 수동 색상: `manual=<SHA-256>`
- 모든 종류의 키에서 겹친 UV 우선순위가 기본값이 아닐 때만 다음 중 바뀐 항목을 끝에 붙입니다.
  겹친 UV 우선순위는 원본 버전 33 헤더의 `bake_priority` 필드입니다. 기본값이면 아무것도 붙이지 않습니다.
  - `;owner=<決め方の名前>`: `LowestIndex`가 아닐 때
  - `;outside=skip`: 0〜1 밖의 아일랜드를 베이크하지 않을 때
  - `;islands=<SHA-256>`: 수동 선택 아일랜드가 있을 때

규칙은 다음과 같습니다.

- 이 앱은 베이크한 뒤 아직 저장하지 않은 맵만 씁니다. 열었을 때의 맵은 파일 바이트열 그대로 유지합니다.
- 베이크 조건 (출처 정보)이 현재 모델·설정과 다르면 오래된 것으로 간주하여 사용하지 않습니다. 다시 베이크하도록 안내합니다.
- Generator와 투영은 메시 맵을 읽습니다. 없거나 오래되었으면 값을 그대로 출력하고 이유를 알립니다.

<a id="読み書きの決まり"></a>

## 읽기와 쓰기 규칙

이 앱의 동작 중 외부 도구가 지켜야 하거나 알아야 하는 내용입니다.

<a id="開くとき"></a>

### 열 때

1. 외부를 읽고 manifest와 모든 엔트리의 길이·CRC·SHA-256을 확인합니다.
   파일에서 열 때는 큰 엔트리의 위치만 기억하고 필요할 때 재확인하며 읽습니다.
2. `ylp.json`을 읽습니다. 없으면 내부 형식 1입니다.
   현재보다 새로운 내부 형식이면 어떤 엔트리도 건드리지 않고 형식 번호와 작성 앱을 덧붙여 거부합니다.
3. 이전 내부 형식이면 마이그레이션 단계를 순서대로 통과합니다. 메모리에서만 수행하며 파일을 다시 쓰지 않습니다 ([내부 형식 버전](#中身の形式のバージョン)).
4. `project.json`을 읽고 목록의 모든 세트 원본과 선택 영역, 에셋 순서와 내용을 읽습니다.
   하나라도 읽지 못하면 열려 있는 프로젝트를 전혀 변경하지 않습니다.
5. 알 수 없는 엔트리를 목록으로 알립니다.
   - core 문서로 변환할 수 없는 세트 원본은 세트와 이유를 알리고 읽기 전용으로 엽니다. 원래 바이트열 그대로 저장합니다.
     예를 들어 조정 종류가 사용하지 않는 값이 기본값이 아닌 경우입니다.
   - 수동 ID 색상은 문서에 복원하여 엽니다.
6. 입력이 갖추어지지 않은 효과를 포함한 세트도 엽니다.
   입력이 부족한 경우는 베이크한 맵이 없거나·오래되었거나·모델과 대조할 수 없는 경우, 이미지가 에셋에 없는 경우, 모델이 없는 경우입니다.
   - 연 뒤에는 읽기 전용으로 두고 부족한 입력을 알립니다.
   - 저장된 합성 (`composite/Color.png`)을 표시합니다.
   - 저장할 때 합성 이미지로 교체하지 않고 원래 편집 정보 (세트 원본)를 그대로 유지합니다.
   - 입력이 갖추어지면 같은 세트를 편집할 수 있습니다. 베이크·모델 불러오기·에셋에 이미지 추가 후가 이에 해당합니다.
   - 저장된 합성 이미지는 최신 효과를 다시 계산한 결과가 아닐 수도 있습니다.

<a id="読めないエントリ"></a>

### 읽을 수 없는 엔트리

읽을 수 없는 엔트리의 처리는 종류에 따라 결정됩니다.

| 종류 | 읽을 수 없을 때 |
|---|---|
| 본체 | 열기를 거부. 0.4.x까지의 Unity 브리지는 `selection.bin`에 한해 이유를 알리고 선택 영역 없이 엶 |
| 기록 (`ylp.json`) | 열기를 거부 |
| 상태 | 기본값으로 되돌리고 알림. 다시 쓰기 전까지 엔트리를 바이트열 그대로 유지 |
| 파생 | 사용하지 않고 다시 생성. 본체 대신 사용하지 않음 |

<a id="知らないエントリ"></a>

### 알 수 없는 엔트리

알 수 없는 엔트리는 현재 내부 형식의 어떤 리더도 모르는 이름의 엔트리와, 목록에 없는 세트의 `sets/<ID>/`입니다.

- 열 때 목록으로 알립니다.
- 이 앱은 바이트열 그대로 유지합니다.
- 0.4.x까지의 Unity 브리지는 저장할 때 제거합니다.

<a id="保存"></a>

### 저장

1. 쓴 내용을 다시 읽어 확인합니다.
2. 같은 폴더의 임시 파일에 쓰고 플러시합니다.
   - 이름은 `.<名前>.<プロセス番号>-<通し番号>.pending~`입니다.
   - 이름이 200바이트를 넘으면 앞부분을 자르고 지문을 붙인 짧은 형태로 만듭니다.
3. 임시 파일을 다시 읽어 확인합니다.
4. 열거나 저장한 시점의 파일 식별 정보 (SHA-256·길이·수정 시각)와 현재 파일이 같은지 확인합니다.
   다르면 외부 변경으로 간주하여 덮어쓰기를 거부합니다.
5. 마지막 한 번에 교체합니다. 도중에 실패해도 원래 파일은 그대로입니다.

- 직전 버전은 `<ファイル名>-backups~/`에 백업합니다.
- 남길 백업 수는 설정으로 정합니다 (기본값은 모두). 이를 초과하는 오래된 항목만 지웁니다.
- 항상 현재 형식으로 쓰며 `ylp.json`에 저장한 앱과 (알 수 있으면) 처음 만든 앱을 기록합니다.
- Undo 기록은 저장하지 않습니다.
- 이전 리더를 위해 형식을 낮추어 쓰는 변환은 없습니다.
  쓰는 버전은 사용하는 기능에 필요한 최소 버전입니다. 기능을 제거하고 다시 저장하면 낮아집니다 ([원본 버전 결정 규칙](#正本のバージョンの決まり)).

<a id="復旧の世代"></a>

### 복구 세대

저장하지 않은 작업을 기록해 두는 데이터입니다. `generation.rs`의 `GenerationStore`가 씁니다. .ylp가 아닙니다.

- 저장 위치 안에 `current`·`previous` (세대 이름), `generations/<世代>/manifest.sha256`, `contents/<SHA-256>.bin`을 둡니다.
- 세대를 확인한 다음 `current`를 마지막에 교체하여 확정합니다.
- manifest의 첫 번째 줄은 다음 중 하나입니다.
  - `DOTPAINT-MANIFEST-1`: 내용을 세대 안에 보유.
  - `DOTPAINT-MANIFEST-2`: 내용은 `contents/`에 있으며 같은 내용은 세대 간에 하나를 공유.
- 이어지는 줄은 `<SHA-256> <長さ> <名前>`입니다.
  이름은 .ylp 엔트리와 같은 범위입니다. `ylp.json`·`project.json`·`resources.json`·`resources/*`·`sets/<ID>/*` 등입니다.
- 세대에 덧붙이는 목록용 정보는 `recovery.json`입니다. .ylp에는 포함되지 않습니다.
- 0.4.x까지의 Unity 브리지가 쓴 세대는 이 앱에서 읽을 수 있습니다.
- 반대는 읽을 수 없습니다. `sets/<ID>/composite/Color.png`처럼 중첩 이름을 포함하는 세대는 0.4.x까지의 Unity 브리지가 거부합니다.
- 용량 계산 방법과 저장 위치는 [RECOVERY.md](RECOVERY.md)에 있습니다.

## 버전과 호환성

### 리더별 범위

이 문서의 “0.4.x까지의 Unity 브리지”는 `.ylp`를 열어 Unity 안에서 그릴 수 있던 시기의 Unity 패키지입니다.

- Unity 브리지 0.5.0 이후는 Live Link와 머티리얼 적용만 제공합니다. .ylp를 열거나 쓰지 않습니다.
- Assets에 놓은 .ylp는 파일 내용과 GUID를 바꾸지 않은 채 Unity에서 일반 파일 (DefaultAsset)이 됩니다.
- 0.4.x까지의 Unity 브리지는 0.2.0 이후 새로운 형식을 추가하지 않았습니다.

| 이 앱 (0.7.0〜) | `YLP-1`〜`4` | 1〜9 | 1〜30·32〜36 | 알리고 바이트열 그대로 유지 |

| 독립 실행형 0.5.x | `YLP-1`〜`4` | 1〜8. 9는 작성 앱을 덧붙여 거부 | 1〜30·32·33. 34 이상은 거부 | 알리고 바이트열 그대로 유지 |

- 분할 원본의 분할 전 원본 버전도 같은 범위로 읽습니다.
  - 독립 실행형 0.6.x는 분할 전 원본 버전 36 이상을 거부합니다.
  - 독립 실행형 0.5.x는 분할 전 원본 버전 34 이상을 거부합니다.
  - 독립 실행형 0.4.x는 분할 전 원본 버전 27 이상을 거부합니다.
- 세트 하나라도 원본 버전이 22 이상이면 해당 .ylp는 0.4.x까지의 Unity 브리지에서 열 수 없습니다.
  0.4.x까지의 Unity 브리지에서 열려면 해당 기능을 제거하고 다시 저장하여 원본 버전을 21로 되돌립니다.
- 0.4.x까지의 Unity 브리지 리더에서 실제로 읽은 기록은 `crates/yolu-io/tests/fixtures/*.unity.txt`에 있습니다.
  원본 버전 22·23·24는 `Runtime/Core` 리더에서 읽어 보았습니다.

수동 ID 색상 블록 (원본 버전 19부터)의 리더는 다음과 같습니다.

- 0.4.x까지의 Unity 브리지 (라이터이기도 함)와 이 앱의 0.3.0 이상에서 읽을 수 있습니다.
- 0.4.x까지의 앱은 블록이 있는 세트를 읽기 전용으로 엽니다. 이유를 알리고 원래 바이트열 그대로 저장합니다. 색상은 편집할 수 없습니다.
- 0.5.0부터는 색상을 문서에 복원하여 편집할 수 있으며 저장할 때도 유지합니다.

분할 원본 (원본 버전 26)과 `YLP-4`에 대한 이전 리더의 동작은 다음과 같습니다.

- 원본 버전 26은 원본 버전 25까지 읽는 독립 실행형 앱과 0.4.x까지의 Unity 브리지 모두 범위를 벗어났다는 이유로 거부합니다.
- 0.4.x까지의 Unity 브리지는 모든 `YLP-4` 파일을 거부합니다. 거부 이유는 파일에 따라 다음과 같이 달라집니다.
  - 832 MiB 초과: 읽기 예산 초과.
  - 그 이하이지만 엔트리 1002개 초과: 엔트리가 너무 많음.
  - manifest가 1 MiB 초과: manifest가 너무 큼.
  - 나머지: manifest 외부 버전이 더 새로운 앱의 버전임.

<a id="古い中身の形式の移行"></a>

#### 이전 내부 형식의 마이그레이션

이전 내부 형식을 열 때의 마이그레이션은 메모리에서만 수행합니다. 파일을 다시 쓰지 않습니다.

- 내부 형식 1·2 → 3: 다음과 같이 세트 구조로 변환합니다.
  - 다음 엔트리를 루트에서 `sets/<文書の ID>/` 아래로 이동합니다.
    `document.utpaint`·`selection.bin`·`imported-original.psd`·`composite/*`·`meshmap-*.bin`입니다.
    ID는 세트 원본의 헤더에 있는 문서 ID입니다.
  - `view.json`의 `materialSlot`으로 세트 하나를 가진 `project.json`을 만듭니다. `materialSlot`이 없거나 읽을 수 없으면 0입니다.
  - 세트 이름은 임시 이름 `Texture Set 1`입니다.
  - 다른 엔트리는 루트에 남깁니다.
- 내부 형식 3〜6 → 7: 각 세트의 `materialSlot`을 `"material": { "slot": <番号> }`로 변환합니다.
- 다른 단계 (1 → 2, 3 → 4, 4 → 5, 5 → 6, 7 → 8, 8 → 9)는 아무 작업도 하지 않습니다.

쓸 때는 현재 내부 형식으로 씁니다.

- 이전 형식 파일을 열어 저장하면 내부 형식 7이 됩니다. 저장한 선택 영역이 있으면 8입니다.
- 해당 파일은 이전 리더에서 열 수 없게 됩니다.
- 직전 버전은 백업에 남습니다 ([저장](#保存)).

### 원본 버전 결정 규칙

원본 버전에는 다음 규칙이 있습니다.

- 이 앱은 1〜25·27〜30·32〜36과 26을 읽습니다. 해당 버전에 없는 필드·값을 가진 것은 거부합니다.
- 새 기능을 사용하지 않는 문서는 이전 버전과 같은 배열이며 버전 번호만 다릅니다.
- 분할 전 원본 버전은 21〜25·27〜30·32〜36만 가능합니다. 나머지와 26 자체는 거부합니다.
- 31은 사용하지 않는 번호입니다. 의미를 정의하지 않았으며 이 앱은 범위에 포함하지 않고 버전 번호로 거부합니다. 분할 전 원본 버전도 같습니다.
- 31은 앞으로도 할당하지 않습니다. 새 기능 버전은 배포한 최고 버전보다 큰 번호를 사용합니다.

이 앱의 라이터 (`NativeDocument::from_core`)는 사용하는 기능에 필요한 가장 작은 버전으로 씁니다.

| 사용하는 기능 | 쓸 원본 버전 |
|---|---|
| 레이어 세트가 2개 이상, 이름을 붙인 레이어 세트, 또는 모든 채널을 하나의 레이어 세트에 할당하지 않는 출력 할당 | 36 |
| 자가 있는 레이어 (그룹), 또는 선대칭 (`mode` 5)의 2D 경로 | 35 |
| 안티앨리어싱이 없음이 아닌 경로 브러시 | 34 |
| 베이크 우선순위를 기본값에서 변경 | 33 |
| 이음새 설정을 끔 | 32 |
| 텍스트 레이어 | 30 |
| 포인트 그라데이션 또는 이방성을 끈 채우기 이미지 | 29 |
| 필터 단계 종류 70〜79 또는 Generator 종류 66〜70 | 28 |
| 경로 목록 | 27 |
| 그라데이션 맵 혼색 | 25 |
| 색조 보정 | 24 |
| 노이즈·그런지 | 23 |
| 사용자 채널 | 22 |
| 모두 없음 | 21 |

- 표를 위에서부터 적용합니다. 가장 위에서 해당하는 항목이 쓸 버전입니다.
- 기능을 제거하고 다시 저장하면 버전도 낮아집니다.
- 연 뒤 변경하지 않은 세트 원본은 원래 바이트열 그대로 씁니다.
- 512 MiB를 넘는 원본만 분할 원본 (원본 버전 26)으로 씁니다. 분할 전 원본 버전은 이 표로 결정합니다.

0.4.x까지의 Unity 브리지에 없는 기능을 사용하는 문서만 새 버전으로 만들기 위한 규칙입니다.

- 원본 버전 22〜25와 27〜30·32〜36은 0.4.x까지의 Unity 브리지에 없는 기능을 사용하는 문서만 새 버전이 됩니다.
- 0.4.x까지의 Unity 브리지 리더는 버전 번호만으로 파일을 건드리지 않고 거부합니다.
- 내부 형식 (7)은 올리지 않습니다.
- Unity 브리지는 0.5.0부터 .ylp를 처리하지 않지만 버전 번호의 의미는 바꾸지 않습니다.
- 종류 번호 8〜63 (Generator)·3〜63 (조정)·7〜63 (필터)은 0.4.x까지의 Unity 브리지 배열을 위해 계속 예약해 둡니다.
- 이 앱에만 있는 종류는 64부터 할당합니다.
- 이 규칙의 이유는 [YLP_DECISIONS.md](YLP_DECISIONS.md)의 [버전 번호 부여 방법](YLP_DECISIONS.md#バージョンの番号の付け方)에 있습니다.

### .ylsmart

스마트 머티리얼·스마트 마스크 하나를 담은 파일입니다. 저장 위치에 두며 .ylp 에셋에도 같은 바이트열로 들어갑니다. 코드는 `smart.rs`입니다.

- 외부는 .ylp와 같은 zip입니다. `mimetype`은 `application/x-yolupainter-smart`입니다.
- manifest 첫 번째 줄은 `YOLUPAINTER-SMART-1`입니다.
- 이름은 루트와 `resources/` 아래 한 단계입니다.

| 엔트리 | 종류 | 내용 |
|---|---|---|
| `smart.json` | 본체 | 아래 참고 |
| `layers.utpaint` | 본체 | 선택한 레이어만 보유하며 `document.utpaint`와 같은 구조의 바이너리 |
| `resources.json`·`resources/<content>.png` | 본체 | 레이어가 참조하는 이미지가 있을 때. .ylp와 같은 구조 (이미지만) |
| `thumbnail.png` | 파생 | 패널 견본 |

`smart.json`의 필드입니다.

| 키 | 자료형 | 의미 |
|---|---|---|
| `format` | 정수 | 1 |
| `kind` | 문자열 | `smartMaterial`·`smartMask` |
| `name` | 문자열 | 이름 |
| `width`·`height`·`layers`·`channels` | 정수 | 읽을 때 레이어와 비교하며 다르면 거부 |
| `repin` | 배열 | 베이크에 고정되어 있던 Generator 단계 ID. 배치한 대상에서 다시 연결 |
| `savedBy` | 객체 | 필수 |
| `thumbnailShape` | 문자열 | 선택 사항. `"sphere"`이면 견본이 구형 |

- 알 수 없는 키는 건너뜁니다.
- `layers.utpaint`는 원본 버전 1〜21이며 저장한 텍스처 세트 크기입니다.
  - 스마트 마스크는 값이 없는 채우기 레이어 하나가 마스크를 보유합니다.
  - 모델 위의 경로는 보유하지 않습니다.
  - Generator는 베이크 고정을 보유하지 않습니다.
- 사용자 채널과 64 이상의 종류는 넣지 않습니다. 이 앱은 이유를 덧붙여 거부합니다.
- `.ylmaterial` (저장 위치의 머티리얼)은 채우기 레이어가 있는 `.ylsmart`와 같은 구조입니다.

### .ylbrush

.ylp 에셋에 들어가는 0.4.x까지의 Unity 브리지 브러시 구조입니다. 이 앱은 읽고 바이트열 그대로 유지합니다.

- zip입니다. `mimetype`은 `application/x-yolupainter-brush`, manifest 첫 번째 줄은 `YOLUPAINTER-BRUSH-1`입니다.
- `state.json`에 `schema` 1〜3을 씁니다. 외부 브러시 끝 ID `tipId`·`textureId`·`dualTipId`는 비어 있어야 합니다.
- `tip-0.png`부터 이어지는 브러시 끝은 최대 256개입니다.
- 선택적으로 `texture.png`·`dual.png`를 보유합니다.
- PNG는 RGBA8이며 1〜2048 px입니다.

이 앱의 사용자 브러시 파일 (설정 폴더의 `brushes/`)은 같은 확장자의 텍스트 형식이며 [BRUSH.md](BRUSH.md)에 설명되어 있습니다.

## 형식을 바꿀 때

<a id="手順"></a>

### 절차

1. **본체·상태 엔트리를 추가하거나·이름이나 위치를 바꾸거나·의미를 바꿀 때**는 내부 형식을 올리고 (`project::MAX_FORMAT`) 이전 형식에서의 마이그레이션을 추가합니다.
   - 올리지 않으면 이전 리더가 알 수 없는 엔트리를 제거하여 저장하므로 작업을 잃게 됩니다.
   - 사용하는 문서만 새 형식으로 만들 수 있다면 그렇게 합니다. 내부 형식 8·9가 그 예입니다.
2. 파생 엔트리만 추가할 때는 내부 형식을 올리지 않아도 됩니다.
   이전 리더는 알 수 없는 엔트리로 알리고 다시 만듭니다.
   - 이름 규칙 (배치 가능한 폴더)을 확장한다면 외부 버전도 올립니다.
   - 상태 엔트리는 이전 리더가 제거해도 해당 상태만 잃는다면 형식을 올리지 않고 추가할 수 있습니다. `look.json`·`pose.json`이 그 예입니다.
3. 엔트리 내용의 버전만 바꿀 때는 해당 엔트리 버전을 올리고 이전 버전도 읽을 수 있게 합니다.
   원본 버전을 올릴 때는 새 기능을 사용하는 문서만 새 버전으로 씁니다. 원본 버전 22〜25가 그 예입니다.
4. **같은 커밋에서 이 문서를 수정합니다.**
   - 수정할 곳은 다음과 같습니다.
     - 개요의 버전 번호 표 (범위와 이 앱이 쓰는 값 포함)
     - 리더별 범위
     - 원본 버전별 추가 사항과 원본 버전 결정 규칙
     - 코드 상수
     - 엔트리 목록과 각 필드
   - 구조를 선택한 이유·채택하지 않은 대안·보장 범위는 [YLP_DECISIONS.md](YLP_DECISIONS.md)에 절을 추가합니다.
5. 이전 형식·버전 파일을 테스트 픽스처로 사용하여 열 수 있는지, 내용을 동일하게 읽고 쓸 수 있는지 확인합니다.
   예는 `crates/yolu-io/tests/ylp/compatibility.rs`입니다.

### 테스트

`crates/yolu-io/tests/ylp/format_doc.rs`가 다음 내용의 누락을 검사합니다.

- 이 앱이 읽고 쓰는 엔트리가 엔트리 목록에 있는지.
- 코드 상수 값이 위 표와 일치하는지.
- 버전 번호 범위와 원본 버전별 추가 행이 있는지.
- 원본 필드 이름과 JSON 키가 각 절에 있는지.
