# 저장·내보내기·가져오기


프로젝트 (`.ylp`) 저장, 배포용 사본, 비정상 종료 시 복구, PNG와 PSD 내보내기·가져오기, 큰 문서를 위한 디스크 캐시를 설명합니다. 새로 만들기와 열기는 [GUIDE_START.md](GUIDE_START.md)에 있습니다.

<a id="プロジェクトを保存する"></a>

## 프로젝트 저장

“파일”의 “저장” (`Ctrl+S`)과 “다른 이름으로 저장…” (`Ctrl+Shift+S`)으로 `.ylp`에 저장합니다. 저장할 파일 이름은 `.ylp`로 끝나야 하며 (대소문자 무관), 폴더가 없으면 만듭니다.

- 저장은 별도 스레드에서 진행하며 오른쪽 아래 카드에 “저장 중”과 진행 상황이 표시됩니다 (취소 불가). 저장 중에도 그리고 볼 수 있지만, 저장 시작 이후 그린 내용은 해당 저장에 포함되지 않아 완료 후에도 “변경 사항 있음” 상태로 남습니다.
- 저장 중에는 추가 1회의 저장·열기·새로 만들기·배포용 저장을 이유와 함께 거부합니다. 저장 도중 창을 닫으면 저장이 끝나기를 기다리고, 결과가 나온 뒤 (저장하지 않은 변경 사항이 남으면 확인 후) 닫습니다.
- 저장할 수 없으면 아무것도 변경하지 않고 이유를 표시합니다. 검증한 임시 파일을 1회 교체하는 것으로 저장을 확정하므로 도중에 실패해도 원본 파일은 이전 상태로 남습니다. 연 후 다른 앱이 파일 내용을 변경했다면 덮어쓰기를 거부합니다 (수정 시간만 바뀐 경우에는 내용 변경으로 보지 않음). 같은 파일을 2개 앱에서 동시에 편집하지 말고 저장한 뒤 다른 앱에서 다시 열어 주세요.
- 덮어쓰기 전 버전은 같은 폴더의 `<ファイル名>-backups~/`에 최신순으로 남습니다. 보관 수는 “편집” → “설정…”의 “파일” 구분에 있는 “보관할 백업 수” (0〜1000. 0은 보관 안 함)에서 선택하며, 초과한 오래된 버전만 삭제합니다. “모두 보관”을 켜면 삭제하지 않습니다 (초기 설정). 백업 `.ylp`를 열면 저장 위치가 없는 문서로 열리고 (열었던 백업은 변경하지 않음), “저장”은 “다른 이름으로 저장”이 됩니다. 모델 파일은 원래 `.ylp`가 있는 폴더에서 찾습니다.

## 배포용으로 저장

“파일”의 “배포용으로 저장…”은 현재 프로젝트의 사본에서 작성자가 모르는 사이 `.ylp`에 남아 있는 항목을 제외해 별도 파일로 기록합니다. 제외할 수 있는 항목 (원본 PSD·에셋·소재 원본 경로·모델 참조·메시 맵·Unity 머티리얼 값·저장된 선택 영역 등)이 창에 나열되며, 선택한 항목이 사본에 포함됩니다. 에셋은 1개씩 선택할 수 있고 기본값은 사용 중인 항목만 포함합니다. 작업 파일은 변경되지 않습니다. 제외 항목과 호환성 세부 사항은 [SAVE_FOR_DISTRIBUTION.md](SAVE_FOR_DISTRIBUTION.md)에 있습니다.

## 비정상 종료에도 작업 보존

저장하지 않은 변경 사항이 있는 동안 앱이 백그라운드에서 복구용 세대를 기록합니다. 다음 시점에 기록합니다.

- 변경을 발견한 뒤 일정 시간 경과 (처음에는 15초. 계속 그리는 중이면 이전 기록 이후)
- 완료한 스트로크가 쌓였을 때 (처음에는 10개)
- 포커스를 잃었을 때, 종료할 때

그리는 도중이나 PSD를 가져오는 도중에는 캡처하지 않고 그리기를 마친 뒤 기록합니다. 기록 실패는 이유만 알리며 그리기를 중단하지 않습니다. 세대는 `.ylp`와 같은 구조이며 합성 PNG와 메시 맵은 포함하지 않습니다.

비정상 종료 후 다음 시작 시 “복구” 창이 열립니다 (“파일”의 “복구…”에서 언제든 열 수 있음). 세대 목록 (원래 이름·세트 수·경과 시간)에서 “열기” 또는 “폐기”를 선택합니다. 열린 문서는 “제목 없음 (복구)”이며 원래 `.ylp`에는 기록하지 않습니다. 저장할 때 위치를 선택합니다.

창에서 기록 간격 (10초〜5분), 보관할 세대 (2〜20), 사용량 (자동·적게·표준·많게, “자세히”에서 GB 지정)을 선택할 수 있습니다. 복구가 사용하는 디스크 공간에는 상한이 있으며 초과한 만큼 오래된 세대부터 삭제됩니다. 여유 공간이 부족하면 기록을 건너뜁니다 ([RECOVERY.md](RECOVERY.md)).

## PNG로 내보내기

“파일”의 “텍스처 내보내기…”로 “텍스처 내보내기” 창을 엽니다. 왼쪽 목록에서 내보낼 텍스처 세트를 선택하고, 오른쪽에서 “출력 위치”, “출력 템플릿”, “패딩”을 정합니다. “내보낼 파일” 목록에서 파일 이름을 확인한 뒤 “내보내기”를 누릅니다. 기록을 시작하면 창이 닫힙니다. 선택한 출력 템플릿은 설정에 저장되어 다음에 열 때도 같습니다.

- **텍스처 세트**: 내보낼 수 있는 세트가 나열되며 처음에는 모두 선택되어 있습니다. 선택을 해제한 세트는 내보내지 않습니다. 선택 상태는 프로젝트를 바꿀 때까지 유지하며, 세트를 추가하면 선택되고 이름을 바꾸면 목록의 이름도 바뀝니다. 읽기 전용 세트는 내보낼 수 없으므로 자물쇠 표시가 붙고 선택 해제 상태에서 조작할 수 없습니다. 1개도 선택되지 않았으면 “내보내기”를 누를 수 없습니다. 출력 템플릿이 “현재 채널”이면 현재 세트만 표시되며 선택을 해제할 수 없습니다.
- **출력 위치**: “현재 채널”은 파일, 다른 템플릿은 폴더이며 “선택…”으로 바꿉니다. 선택하기 전의 기본값은 현재 프로젝트 폴더입니다 (Live Link로 연 모델은 Unity가 알려 준 폴더). 선택한 위치는 다른 프로젝트를 열 때까지 유지합니다. 출력 위치가 정해지지 않았거나 내보내기가 진행 중이면 “내보내기”를 누를 수 없습니다.
- **출력 템플릿**: “현재 채널”, “채널별”, “Unity Standard / URP Lit”, “HDRP Lit”, “lilToon” 중 선택합니다.
- **패딩**: UV 밖으로 색을 확장하는 너비로, “없음”, “n px 확장”, “무제한 확장” 중 선택합니다. 설정의 “내보내기 패딩”과 같은 값입니다 (어느 쪽에서 바꿔도 동일). 모델이 없으면 확장하지 않습니다.
- **내보낼 파일**: 현재 출력 템플릿·선택한 세트·출력 위치에 따라 작성할 파일 이름과 색 공간 (sRGB 또는 선형)을 기록 전에 표시합니다. 실제 내보내기와 같은 규칙으로 정한 이름입니다. 출력 위치에 이미 있는 파일은 이름 왼쪽에 점이 붙습니다. 기록할 수 없는 이유 (내보낼 내용 없음, 같은 파일이 되는 이름 존재 등)가 있으면 목록 대신 이유를 표시합니다.

기존 파일은 교체 전에 확인합니다 (취소하면 창으로 돌아감). 취소했거나 마지막 교체를 시작하기 전에 실패한 경우에는 원본 파일을 변경하지 않습니다.

“파일”의 “이전 설정으로 내보내기” (“텍스처 내보내기…” 바로 아래)는 이 프로젝트에서 마지막으로 “내보내기”를 눌렀을 때의 출력 템플릿·출력 위치·텍스처 세트로 창을 열지 않고 내보냅니다 (기존 파일 확인은 동일). 아직 내보낸 적이 없다면 창을 엽니다. 이전 설정은 프로젝트를 바꾸면 잊습니다 (저장하지 않음). 이후 삭제되거나 읽기 전용이 된 세트는 제외하며 모두 제외되면 거부합니다.

내보내는 내용은 각 채널의 최종 결과 (출력에 할당한 레이어 세트의 합성, “없음”인 채널은 기본값)입니다 ([GUIDE_LAYERS.md](GUIDE_LAYERS.md)의 “레이어 세트”). 새 문서는 맨 아래에 흰색 단색이 있으므로 내보낸 Color PNG는 흰색 불투명 이미지입니다 (투명도를 유지하려면 흰색 채우기 레이어를 숨기거나 삭제). 1개의 텍스처 세트에 여러 머티리얼을 할당해도 세트마다 1조만 내보냅니다.

### 템플릿으로 내보내기

“Unity Standard / URP Lit”, “HDRP Lit”, “lilToon”은 해당 셰이더가 읽는 패킹 PNG를 선택한 텍스처 세트별로 지정 폴더에 기록합니다. 이름은 `<名前>[_<セット名>]_<画像>.png`이며 세트 이름은 세트가 여러 개일 때만 붙습니다 (선택을 해제해도 다른 세트의 이름은 바뀌지 않음).

- 베이크한 AO가 있으면 사용하며 오래된 AO는 사용하지 않습니다.
- 화면과 같은 효과 (필터·메시 맵을 읽는 생성기·에셋 이미지)가 포함됩니다. 읽을 맵이 없는 등의 이유로 적용되지 않는 효과가 남아 있다면 내보낸 이미지에 포함되지 않았음을 알립니다.
- 읽기 전용 세트는 내보내지 않습니다.
- Live Link로 연 모델에서는 Unity가 알려 준 폴더가 기본 출력 위치입니다.

<a id="チャンネルごとに書き出す"></a>

### 채널별로 내보내기

“현재 채널”은 그릴 채널을 PNG 1장으로, “채널별”은 선택한 텍스처 세트에서 사용하는 모든 채널을 폴더에 기록합니다. 값은 채널 합성 그대로이며 (패킹하거나 색을 곱하지 않음), Normal만은 노멀 설정의 파일 Y 방향을 사용합니다. 이름은 `<名前>[_<セット名>]_<チャンネル>.png`입니다.

## PSD 불러오기

“파일”의 “가져오기”에서 “PSD를 새 텍스처 세트로…” 또는 “PSD를 현재 텍스처 세트로…”를 선택해 PSD (RGB 8 bit)를 가져옵니다. 창에 .psd를 드롭하면 아래의 “파일 가져오기” 창에서 대상을 선택합니다.

- PSD는 원본 파일에 다시 기록하지 않는 사본으로 가져옵니다. 래스터·그룹·단색 채우기·보정 (반전·레벨 보정·색조/채도·그라데이션 맵·톤 곡선·색상 균형·밝기/대비·2진화·포스터화)·마스크·클리핑은 레이어가 됩니다. 레이어 잠금도 복원합니다.
- 레이어 효과·스마트 오브젝트·텍스트·지원하지 않는 보정 등 제외되거나 외관이 바뀌는 항목이 있으면 가져오기 전 “PSD 가져오기 확인” 창에 레이어 이름과 함께 나열합니다. “가져오기”를 누르기 전에는 아무것도 넣지 않습니다.
- PSB·RGB 8 bit 이외의 형식·예산을 초과하는 PSD는 이유를 표시하고 아무것도 변경하지 않습니다. 크기 상한은 설정의 “레이어 메모리” 예산으로 결정됩니다.
- 가져온 문서의 합성을 PSD 통합 이미지와 비교하고 차이가 크면 창에 표시합니다.
- 이름이 너무 긴 레이어 (4096 UTF-16 단위 초과)는 이름을 잘라 가져오며 확인 창에 표시합니다. 레이어가 2048장 (`.ylp`에 저장할 수 있는 상한)을 초과하는 PSD는 가져오지 않습니다. 캔버스 밖으로 크게 뻗은 레이어는 캔버스 내부 픽셀만 읽습니다.

처리 분류와 상한은 [PSD.md](PSD.md)에 있습니다.

## 창에 드롭한 PSD와 이미지 가져오기

PSD와 이미지 (PNG·JPEG·TGA)를 창에 드롭하면 “파일 가져오기” 창에 파일이 1개씩 행으로 나열됩니다. 행마다 “대상”을 선택한 뒤 “가져오기”를 누릅니다. 읽을 수 있는 파일의 대상을 모두 정하기 전에는 “가져오기”를 누를 수 없습니다. “모두”에서 선택한 대상은 해당 대상에 넣을 수 있는 행에만 적용됩니다.

- “에셋만” (이미지 전용): 에셋에 넣습니다 (PNG 이외의 형식도 같은 이미지로 변환).
- 텍스처 세트 행: 해당 텍스처 세트에 파일 이름의 새 레이어 세트를 만들어 넣습니다.
- 레이어 세트 행: 해당 레이어 세트의 맨 위에 넣습니다.
- 이미지는 에셋에 넣은 뒤 이미지 채우기 레이어 (“새 채우기 레이어”의 “이미지”와 같은 형태)를 1장 만듭니다. 레이어 이름은 파일 이름입니다.
- PSD는 행을 펼치면 “PSD 가져오기 확인”과 같은 목록을 표시합니다. 그룹·마스크·합성 방식에 맞춰 레이어를 넣습니다. 텍스처 세트와 크기가 다른 PSD는 해당 텍스처 세트로 가져올 수 없습니다 (크기를 바꾸어 넣지 않음). 에셋에도 넣을 수 없습니다.
- 실행 취소는 대상 텍스처 세트마다 1회입니다 (같은 텍스처 세트에 넣은 여러 파일은 1회로 되돌림).
- 가져온 뒤에는 마지막 대상 텍스처 세트와 레이어 세트로 전환합니다.
- WebP·TIFF·EXR 등의 다른 형식은 이유가 표시된 행으로 나타나며 가져올 수 없습니다. PNG를 브러시 목록·라이브러리·스텐실 이미지 위에 드롭하면 기존처럼 해당 위치에서 읽습니다.

## PSD로 내보내기

“파일”의 “PSD 내보내기…”로 “PSD 내보내기” 창을 열고 방식과 채널을 선택한 뒤 “내보내기…”를 누릅니다.

- 방식은 “베이크하여 저장” (레이어를 유지하고 PSD에 표현 방식이 없는 필터·생성기·이미지·경로 등은 평가한 픽셀로 기록) 또는 “1장으로 병합” (합성 이미지만 레이어 1장으로 기록)입니다.
- 채널은 처음에는 Color만 선택됩니다. 여러 채널을 선택하면 채널마다 `名前_チャンネル.psd`를 기록합니다.
- 베이크·반올림·제외되는 항목이 있다면 기록 전에 “PSD 내보내기 확인” 창에 레이어 이름과 함께 나열합니다. “기록”을 누르기 전에는 아무것도 쓰지 않습니다.
- 레이어 세트가 2개 이상인 문서는 레이어 세트마다 최상위 그룹 (이름은 레이어 세트 이름)으로 기록하며, 내보낼 채널을 출력하는 레이어 세트의 그룹만 표시합니다. 출력 할당이 “없음”인 채널은 모든 그룹을 숨기고 맨 아래에 기본값의 채우기 레이어 (`Default`)를 추가합니다. 두 경우 모두 PSD 합성이 최종 결과와 같아지도록 구성합니다.
- 포인트 그라데이션이 있는 채우기 레이어는 픽셀로 베이크해 기록하며 확인 창에 표시합니다 (점의 위치와 색은 PSD에 남지 않음).
- 내보내기는 문서의 사본을 만들며 문서 자체는 변경하지 않습니다. 효과는 문서에 남지만 베이크한 레이어는 효과 설정을 보유하지 않으므로 PSD를 다시 가져와도 효과는 복원되지 않습니다.

Photoshop이나 CLIP STUDIO PAINT에서 열면 보정 레이어가 다시 평가되어 외관이 달라질 수 있습니다. 기록 방식과 상한은 [PSD.md](PSD.md)에 있습니다.

## PNG 가져오기

PNG 파일을 가져올 수 있는 위치는 다음과 같습니다.

- 스텐실 (속성의 “스텐실” 탭)
- 에셋 이미지: 채우기 레이어 이미지 목록의 “파일에서 가져오기…” 또는 라이브러리의 “프로젝트에서 사용”으로 넣습니다. 채우기·이미지 생성기·경로 리본에서 사용합니다 ([GUIDE_FILL.md](GUIDE_FILL.md))
- 라이브러리: “라이브러리에 파일 추가…” 또는 격자로 드롭
- 창으로 드롭: “파일 가져오기” 창에서 에셋 또는 이미지 채우기 레이어로 가져옵니다 (위의 “창에 드롭한 PSD와 이미지 가져오기”)

스마트 머티리얼 `.ylsmart`는 에셋과 라이브러리로 불러올 수 있습니다.

## 큰 문서 다루기

설정의 “디스크 캐시” (초기값 켜짐)는 “레이어 메모리”와 “실행 취소 기록” 예산의 합을 초과한 타일을 사용하지 않는 것부터 캐시 파일로 옮겨 계속 그릴 수 있게 합니다. 끄면 예산을 초과하는 작업을 거부합니다.

“자세히”를 열면 사용할 수 있는 양인 “캐시 상한” (자동은 64 GiB와 저장 위치 여유 공간 절반 중 작은 값)과 “캐시 위치” (초기값은 OS 임시 폴더. 빠른 드라이브일수록 복원이 빠름)를 정할 수 있습니다. 상한을 모두 사용하면 초과하는 작업을 거부하고 오래된 실행 취소 단계를 버립니다.

- 타일은 압축하지 않고 기록하므로 디스크 사용량은 문서의 픽셀 데이터 양까지입니다. 이전 실행이 남긴 캐시 파일은 시작 시 백그라운드에서 삭제합니다.
- 디스크에서 읽을 수 없는 타일이 생기면 해당 텍스처 세트를 읽기 전용으로 바꾸고 알립니다. 저장은 열었을 때의 내용 그대로 기록합니다. 저장한 적 없는 세트는 원본 내용이 없으므로 해당 세트만 저장과 복구 기록에서 제외합니다.

## 파일 선택 창의 시작 위치

파일이나 폴더 선택 창은 다음 순서로 처음 찾은, 현재 존재하는 위치에서 시작합니다.

- **열기·가져오기·내보내기**: 해당 종류 (프로젝트·모델·PSD 불러오기와 내보내기·이미지 가져오기와 내보내기·브러시·글꼴·키 설정·에셋과 라이브러리·색상 세트·배포용 저장·설정 위치)에서 이전에 선택한 폴더 → 현재 프로젝트의 `.ylp`가 있는 폴더 → OS 문서 폴더.
- **저장·다른 이름으로 저장**: 백업 `.ylp`를 연 문서는 원래 `.ylp` 폴더 → 현재 프로젝트의 `.ylp`가 있는 폴더 → 프로젝트에서 이전에 선택한 폴더 → OS 문서 폴더.

이전에 선택한 폴더는 설정 폴더의 `places.conf`에 종류별로 저장됩니다 (삭제해도 다음 선택부터 다시 기억). 없어진 폴더는 사용하지 않습니다. “텍스처 내보내기” 창에서 선택할 때 이미 출력 위치가 정해졌다면 (선택한 위치, 없으면 Live Link로 연 모델에서 Unity가 알려 준 폴더, 그것도 없으면 프로젝트 폴더) 해당 위치가 우선입니다. 저장하지 않은 문서처럼 위치가 정해지지 않았을 때만 위 순서로 시작합니다.

## 이전 버전 또는 Unity로 전달

다음 기능을 사용한 `.ylp`는 새 버전 번호로 저장되며 독립 실행형 0.4.x와 0.4.x까지의 Unity 브리지에서 열 수 없습니다 (Unity 브리지는 0.5.0부터 `.ylp`를 열지 않음).

- 텍스트 레이어
- 경로 2개 이상·경로 종류·브러시 팁·대칭·모서리나 핸들·채우기 레이어의 경로 ([GUIDE_PATHS.md](GUIDE_PATHS.md))
- 포인트 그라데이션, 비등방성 필터링을 끈 이미지, 0.5.0 효과, “UV 이음새 넘기”를 끈 설정 ([GUIDE_FILL.md](GUIDE_FILL.md))
- 베이크 우선순위를 기본값에서 변경한 설정 ([GUIDE_3D.md](GUIDE_3D.md))

사용하지 않은 문서는 기존 버전을 유지합니다. 0.4.x까지의 Unity 브리지로 되돌릴 때는 해당 기능을 제거한 뒤 다시 저장해 주세요.

경로 브러시의 앤티앨리어싱이 “없음”이 아닌 경로 (새 경로는 현재 브러시 단계를 사용하며 기본값은 “중간”. [BRUSH.md](BRUSH.md)), 자 (레이어나 그룹에 추가한 자, 대칭자 포함), 대각선 선대칭·6개 이상의 선대칭 경로 ([GUIDE_PAINT.md](GUIDE_PAINT.md)) 중 하나라도 사용한 `.ylp`는 0.5.x까지의 독립 실행형 앱에서도 열 수 없습니다 (버전 번호만 보고 파일을 변경하지 않은 채 거부). 각 경로의 앤티앨리어싱을 “없음”으로 바꿔 다시 저장하면 이전 버전을 유지합니다. 경로 대칭을 끄거나, 세로 또는 가로 방향의 2개·4개 대칭자로 다시 설정한 뒤 자를 모두 삭제하고 다시 저장하면 열 수 있습니다. 버전별로 읽을 수 있는 범위는 [UNITY.md](UNITY.md)와 [YLP_FORMAT.md](YLP_FORMAT.md)에 있습니다.

레이어 세트가 2개 이상인 문서·출력 할당이 “없음”인 채널이 있는 문서 ([GUIDE_LAYERS.md](GUIDE_LAYERS.md)의 “레이어 세트”), 그리고 1개의 텍스처 세트에 2개 이상의 머티리얼을 할당한 프로젝트 (`.ylp` 내부 형식 9)는 0.6.x까지의 독립 실행형 앱에서 열 수 없습니다 (이유를 표시하고 거부). 레이어 세트가 1개이고 모든 세트의 머티리얼도 1개라면 기존과 같은 구조로 기록합니다.
