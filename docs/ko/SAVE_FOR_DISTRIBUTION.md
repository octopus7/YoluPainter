# 배포용으로 저장

「파일 → 배포용으로 저장…」은 열린 프로젝트의 **사본**을 만들고, 제작자가 알아차리지 못한 채 .ylp에 남을 수 있는 항목을 제외하여 다른 파일에 저장합니다. .ylp를 판매물이나 배포물에 넣을 때 사용하는 기능이며 일반 저장(작업용 파일)은 바뀌지 않습니다. 작업용 파일에 남는 정보도 그대로입니다(Undo 기록·삭제한 레이어·자동 저장·시각은 원래 .ylp에 포함되지 않음).

<a id="流れ"></a>

## 진행 순서

1. 메뉴를 선택하면 현재 상태(저장하지 않은 변경 사항 포함)의 사본을 백그라운드에서 만듭니다. 열린 문서·프로젝트·미저장 표시·Undo·열린 파일은 1바이트도 바뀌지 않습니다. 그리는 중에는 시작할 수 없습니다.
2. 창에 사본에 포함할 항목을 나열합니다. 체크한 항목이 사본에 들어갑니다. 에셋은 종류별 구역(이미지·스마트 소재·브러시 등, 0개인 종류는 표시하지 않음)에 하나씩 나열되며 구역 행의 체크는 그 안의 항목 전체에 적용됩니다. 기본적으로 사용 중인 에셋을 포함하고 사용하지 않는 에셋(「미사용」 표시)은 제외합니다. 사용 중인 에셋도 제외할 수 있으며 해당 행에 경고가 표시됩니다(레이어 채우기 이미지로 사용하던 에셋을 제외하면 사본을 열 때 해당 세트는 읽기 전용으로 열림). 에셋 이외의 항목은 종류별 한 행이며 기본적으로 모두 제외합니다(해당 항목이 하나도 없는 종류는 표시하지 않음. 나열할 항목이 전혀 없으면 창 없이 저장 위치 선택으로 진행).
3. 「저장…」으로 저장 위치를 선택합니다. 기본 이름은 현재 이름에 `-dist`를 붙인 것입니다. **열린 작업용 파일과 같은 위치·이름은 선택할 수 없습니다.** 기존 파일은 확인 후 교체합니다(이전 사본은 보관하지 않음). .ylp로 읽을 수 없는 파일은 교체하지 않습니다.
4. 기록은 백그라운드에서 수행하고 검증한 임시 파일을 한 번 교체하여 확정합니다. 취소·실패 시 아무것도 쓰지 않으며 저장 대상은 그대로입니다. 배포용 사본 옆에는 `-backups~`를 만들지 않습니다(이전 버전 백업은 작업용 파일에서 담당).

## 제외하는 항목

| 종류 | 제외하는 항목 | 남기는 항목 |
|---|---|---|
| PSD 원본 | `sets/<ID>/imported-original.psd`(0.4.x까지의 Unity 브리지가 PSD 가져오기 시 보관한 원본 전체 바이트) | 레이어로 가져온 내용 |
| 에셋(선택한 항목) | 기본적으로 어떤 레이어(채우기 이미지·그라데이션 모양·Generator 등 정본이 ID로 에셋을 참조하는 모든 항목)와 외관 설정의 이미지 할당에서도 사용하지 않는 에셋(이미지·스마트 소재·브러시) | 하나씩 선택할 수 있습니다. 기본적으로 사용 중인 소재를 내용과 출처 모두 남깁니다 |
| 소재 출처 경로 | 에셋 출처 중 가져온 파일의 절대 경로(`file`)·Unity 에셋 경로(`unityAsset`)·저장소의 상대 경로(`library`). 출처를 `none`으로 바꿉니다. 텍스트 레이어의 글꼴 파일 위치(절대 경로, 사용자 폴더의 글꼴이면 사용자 이름 포함)는 파일 이름만 남깁니다 | 픽셀·이름. 내장 소재의 키와 버전(경로가 아님). 글꼴 SHA-256·패밀리 이름·PostScript 이름·굵기·기울임(사본을 열면 OS에 설치된 글꼴을 이름으로 찾음) |
| 모델 참조 | `view.json`의 모델 파일 위치와 Unity 모델 GUID, 모델 내부 렌더러의 표시 여부, 루트 `pose.json`(모델 포즈, 어떤 모델의 포즈인지 알 수 없게 되므로 제외), 루트 `livelink.json`(Live Link로 연 모델 기록, FBX와 이미지 파일 위치·Unity 프로젝트 위치·내보내기 위치·포즈 포함) | 세트 표시 여부·선택한 채널 등 표시 상태 |
| 메시 맵 | `sets/<ID>/meshmap-*.bin`(모델 형상에서 베이크한 파생 데이터) | 다시 베이크할 수 있습니다(Generator가 사용하는 맵은 파일을 연 뒤 모델에서 다시 베이크할 때까지 해당 세트가 읽기 전용일 수 있음) |
| Unity 머티리얼 값 | 외관 설정(`look.json`)의 `received`(Live Link로 Unity 머티리얼에서 받은 값) | 사용자의 외관 설정 |
| 저장된 선택 영역 | 이름을 붙여 저장한 선택 영역(`sets/<ID>/selections.json`과 `selection-*.bin`, 작업 보조 정보이며 이미지가 아님). 형식 8 항목이므로 제외하면 사본은 0.4.x까지의 Unity 브리지에서도 열 수 있는 형식 7이 됩니다 | 현재 선택 영역(`selection.bin`, 이미지의 일부) |
| 오래된 썸네일 등 | 루트 `thumbnail.png`·`brush.json`·`model.json`(0.4.x까지의 Unity 브리지가 남긴 항목, 독립 실행형은 업데이트하지 않음) | |
| 알 수 없는 항목 | 이 앱이 알지 못하는 항목(새 버전에서 기록한 항목 등, 열 때 「저장하면 유지되지 않음」이라고 알리는 항목) | |

무엇이 「사용 중」인지는 제외 후 남는 외관 설정으로 결정합니다(Unity 값을 제외하면 그 안의 할당은 집계하지 않음). 창의 「미사용」 표시와 경고는 선택에 따라 바뀌며 사본에 남는 항목과 일치합니다.

<a id="除かないもの保証しないこと"></a>

## 제외하지 않는 항목·보장하지 않는 사항

- 레이어·마스크·채널·현재 선택 영역·합성 PNG(이미지 자체), 세트 이름·머티리얼 참조는 제외하지 않습니다. 사본 레이어의 픽셀은 준비를 시작한 시점의 열린 문서와 같습니다(이후 추가로 그린 내용은 포함하지 않음).
- 에셋 파일(`.ylsmart`·`.ylbrush`)은 파일 전체를 남기거나 제외합니다. 내용을 다시 쓰지 않으므로 스마트 소재 내부 이미지의 출처는 제거하지 않습니다.
- 0.4.x까지의 Unity 브리지가 남긴 `brush.json` 등의 상태 항목을 남기도록 선택해도 그 항목이 참조하는 에셋 이미지는 「사용 중」으로 집계하지 않습니다(해당 Unity 브리지는 상태를 읽지 못하면 기본값으로 되돌려 엶).
- 레이어 이름·세트 이름·소재 이름 등 제작자가 붙인 이름은 사본에 남습니다. 글꼴 파일 이름도 남습니다.
- 사본의 정본을 다시 쓰는 세트(글꼴 파일을 사용하는 텍스트 레이어가 있는 세트)는 그동안 메모리로 읽습니다. 정본이 512 MiB를 초과하여 읽을 수 없는 세트는 다시 쓸 수 없어 사본을 만들 수 없습니다(이유가 표시됨. 「소재 출처 경로」를 제외 대상에서 해제하면 만들 수 있지만 글꼴 위치가 사본에 남음).
- 디스크 캐시에서 읽을 수 없게 되었고 한 번도 저장하지 않은 세트는 일반 저장과 마찬가지로 사본에 포함되지 않습니다([RECOVERY.md](RECOVERY.md)의 「디스크 캐시와의 관계」).

<a id="互換性"></a>

## 호환성

사본은 현재 파일과 같은 형식(형식 7, 저장된 선택 영역을 남기는 사본은 형식 8, 머티리얼이 2개 이상인 텍스처 세트가 있는 사본은 형식 9, 정본 버전도 같음)이며 독립 실행형에서 열 수 있습니다(작성한 사본을 다시 읽는 테스트로 확인). 저장된 선택 영역을 남기는 사본(형식 8)은 0.3.x 독립 실행형과 0.4.x까지의 Unity 브리지가 「새 형식」으로 거부하므로 해당 버전에서 사용할 사본은 선택 영역을 제외한 상태로 둡니다(기본값). 0.4.x까지의 Unity 브리지가 열 수 있는 것은 **정본 버전 21의 세트만 포함한 사본**입니다. 배포용 사본은 정본 버전을 바꾸지 않으므로 정본 버전 22 이상인 세트(사용자 채널·노이즈·그런지 단계·그라데이션 맵 색상 혼합 등을 사용한 문서)가 하나라도 포함되면 해당 Unity 브리지에서 「Unsupported archive version」으로 거부되어 열리지 않습니다([YLP_FORMAT.md](YLP_FORMAT.md)의 「읽기 구현별 지원 범위」). 해당 Unity 브리지에서도 열리는 사본을 만들려면 독립 실행형에서 해당 기능을 삭제하고 다시 저장하여 버전을 21로 되돌린 뒤 배포용으로 저장합니다.

제외하는 항목은 모두 0.4.x까지의 Unity 브리지 읽기 구현에서 없어도 열 수 있는 항목(PSD 원본·상태·파생 항목)이거나 인덱스와 함께 다시 쓰는 에셋이며, 인덱스의 소재와 실제 내용은 반드시 일치합니다(소재가 하나도 남지 않으면 `resources.json`을 쓰지 않음). 해당 Unity 브리지에서 열 수 있다는 점은 읽기 코드와 형식 규칙을 검토하여 확인했으며 **Unity 브리지에서 실제로 열어 본 것은 아닙니다.**

<a id="いつもの保存と取り込み直した-psd"></a>

## 일반 저장과 다시 가져온 PSD

PSD를 「현재 텍스처 세트로」 다시 가져와 문서를 교체한 세트는 다음 일반 저장부터 그 세트의 이전 `imported-original.psd`를 이어받지 않습니다(새 문서의 원본이 아니기 때문). 복구 지점도 같으며 복구 지점에서 복원하여 연 뒤 저장해도 이전 원본은 돌아오지 않습니다. 같은 문서에 그림을 추가한 경우에는 0.4.x까지의 Unity 브리지가 가져온 원본이 그대로 남습니다. 이전 버전은 백업(설정의 「유지할 백업 수」)에 남습니다.
