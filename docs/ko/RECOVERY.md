# 복구

충돌이 발생해도 저장하지 않은 작업을 잃지 않도록 YoluPainter는 백그라운드에서 복구용 세대를 기록합니다. 이 문서는 기록 시점·열기·설정과 함께, 복구 세대가 **디스크를 지나치게 사용하지 않도록** 하는 규칙, 즉 사용량 계산·상한과 삭제 방식·여유 공간 보호·비정상 종료 세대의 보존 방식을 설명합니다.

<a id="書き置きの頃合い"></a>

## 기록 시점

저장하지 않은 변경 사항이 있으면 별도 스레드가 복구용 세대를 기록합니다. 다음 중 하나에 해당할 때 기록합니다.

- 변경을 발견한 뒤 15초가 지났을 때 (계속 그리는 중이면 이전 기록 이후 15초).
- 이전 기록 이후 완료된 스트로크가 10개 쌓였을 때.
- 창이 포커스를 잃었을 때. 메인 창에서 분리한 패널 창으로 이동한 경우에는 포커스를 잃은 것으로 보지 않습니다.
- 종료할 때. 마지막 세대를 기록하며 최대 10초 기다립니다. 시간 안에 끝나지 않으면 이전 세대가 남고, 충돌한 경우와 마찬가지로 다음 시작 시 발견됩니다.

그리는 도중이나 PSD를 가져오는 도중에는 캡처하지 않고 완료 후 기록합니다. 저장 중에는 감시를 중단합니다. 저장된 `.ylp`와 같으면 (변경 없음) 기록하지 않습니다.
기록에 실패하면 알림에 이유만 표시하며 그리기는 중단하지 않습니다.

세대는 `.ylp`와 같은 구조이며 변경되지 않은 세트는 이전 세대와 공유합니다. 합성 PNG와 메시 맵은 세대에 포함하지 않습니다 (파생 데이터. 열었던 `.ylp`에 있던 것은 유지).
정상 종료한 실행의 세대는 모두 합쳐 “보관할 세대” 수만큼 남습니다. 비정상 종료한 실행은 아래 “비정상 종료한 실행의 세대”를 따릅니다.

<a id="開く"></a>

## 열기

비정상 종료 후 다음 시작 시 “복구” 창이 열립니다 (“파일 → 복구…”에서 언제든 열 수 있음). 세대 목록에는 원래 이름·세트 수·경과 시간이 표시되며 열기·폐기를 선택할 수 있습니다.
열린 문서는 “제목 없음 (복구)”이며 원래 `.ylp`에는 기록하지 않습니다. 저장할 때 저장 위치를 선택합니다.

<a id="設定"></a>

## 설정

창의 “기록 간격”, “보관할 세대”, “사용량”에서 선택합니다. 선택 내용은 설정 폴더의 `recovery.conf`에 `キー=値` 행으로 기록합니다.

| 키 | 내용 | 파일에서 지정할 수 있는 범위 (기본값) | 창의 선택 항목 |
|---|---|---|---|
| `interval` | 기록 간격 (초) | 5〜600 (15) | 10초·15초·30초·1분·5분 |
| `strokes` | 완료한 스트로크가 이 수에 도달하면 시간을 기다리지 않고 기록. 0이면 개수 기준으로 기록하지 않음 | 0〜1000 (10) | 창에는 없음 |
| `generations` | 보관할 세대 수 (현재와 1개 이전 포함) | 2〜1000 (3) | 2·3·5·10·20 |
| `directory` | 저장 위치. 절대 경로만 허용 | 없으면 설정 폴더 아래의 `recovery` | 창에는 없음 |
| `disk` | 사용량 상한 | `auto`·`low`·`standard`·`high` 또는 GB 수 (1〜256) (`auto`) | 자동·적게·표준·많게 (수치 지정은 “자세히”) |

범위를 벗어난 값과 절대 경로가 아닌 `directory`는 해당 항목만 기본값으로 되돌리고 이유를 알립니다 (설정을 다시 선택하기 전까지 파일은 변경하지 않음). 파일은 최대 4 KiB입니다.
`disk`의 선택 항목과 수치는 아래 “사용량 상한”에 있습니다.

<a id="recoveryconf-を読めないとき"></a>

### `recovery.conf`를 읽을 수 없는 경우

`recovery.conf`를 읽을 수 없으면 (권한·파일이 너무 큼·UTF-8이 아님 등) 기본 간격으로 동작하고 이유를 알립니다. 선택한 세대 수와 저장 위치를 알 수 없으므로 세대를 정리하지 않으며 파일도 변경하지 않습니다.
창에서 세대 수를 선택하면 해당 실행 동안에는 선택한 수로 정리합니다. 사용량 상한도 같은 방식입니다 (아래 “사용량 상한”의 “설정을 읽을 수 없는 경우”).

<a id="置き場の形"></a>

## 저장 위치 구조

설정 폴더의 `recovery/` (`recovery.conf`의 `directory`로 변경 가능) 아래에 시작 1회마다 **풀** 1개를 만듭니다 (폴더. 이름은 `<UTC の時刻>-<乱数 16 桁>`). 풀 내부가 세대의 저장 위치이며 0.4.x까지의 Unity 브리지 복구와 같은 구조입니다.

```text
<置き場>/<プール>/current                世代の名前（最後に置き換えて確定）
<置き場>/<プール>/previous               1 つ前の世代の名前
<置き場>/<プール>/generations/<世代>/     manifest（どの中身を使うか）
<置き場>/<プール>/contents/<SHA-256>.bin  変わらない中身は世代の間で 1 つを共有
<置き場>/<プール>/session.lock | crashed 動いている・落ちたの印
```

공유는 **같은 풀 내부의 세대끼리만** 합니다. 풀 사이에는 공유하지 않으므로 풀 전체를 삭제해도 다른 풀의 세대는 읽을 수 있습니다.

<a id="数え方"></a>

## 사용량 계산

- 저장 위치 아래에서 이름이 위 형식에 맞는 풀만 계산합니다. 풀 내부 파일 길이의 합입니다 (공유 내용·기록 중인 데이터·표시 파일 포함). 심볼릭 링크는 따라가지 않습니다.
- 저장 위치 아래의 다른 폴더·파일 (사용자가 둔 항목, 0.4.x까지의 Unity 브리지 `recovery-<GUID>`)은 계산하지도 삭제하지도 않습니다.
- 파일시스템 압축·클러스터 반올림은 고려하지 않고 파일 길이로 계산합니다 (파일 관리자의 “크기”와 같은 기준).
- 다른 창에서 사용 중인 풀은 계산에는 포함하지만 삭제하지 않습니다 (실행 중에는 변경하지 않음).
- 기록 도중 충돌하거나 비정상 종료했을 때의 잔여물 (작성 중인 `.staging-<世代>/`, 그 안의 `<中身の SHA-256>.pending`, 확정 전에 충돌해 아무도 사용하지 않는 `contents/*.bin`)도 계산합니다. 큰 문서에서는 이것만으로 GB 단위가 됩니다. 아래 “중단된 기록의 잔여물”에서 정리합니다.

창 아래 표시줄 왼쪽에 현재 사용량을 짧게 표시합니다 (`使用中 1.2 GB`). 툴팁에는 현재 실행·비정상 종료한 실행·종료한 실행·다른 창·상한·디스크 여유 공간의 내역이 나옵니다. 단위는 1 GB = 1024 MB입니다.

<a id="使う量の上限"></a>

## 사용량 상한

창의 “사용량”에서 선택합니다. 단계 이름만 표시하며 수치는 “자세히”의 슬라이더 (1〜256 GB)에 있습니다.

| 선택 | 상한 |
|---|---|
| 자동 (기본값) | 2 GB와 복구에서 사용할 수 있는 디스크 공간 (여유 공간 + 현재 사용량)의 10% 중 작은 값. 하한은 256 MB. 디스크 여유 공간을 알 수 없으면 2 GB |
| 적게 | 1 GB |
| 표준 | 2 GB |
| 많게 | 8 GB |
| 지정 | “자세히”의 슬라이더로 정한 양. 움직이는 중에는 적용하지 않고 놓을 때 적용 |

선택 내용은 `recovery.conf`의 `disk=`에 기록합니다 (`auto`·`low`·`standard`·`high` 또는 GB 수). 범위를 벗어난 값은 기본값 (자동)으로 되돌리고 이유를 알립니다. `disk=`가 없는 이전 설정은 자동으로 읽습니다.

<a id="超えたときの消し方"></a>

### 상한 초과 시 삭제 방식

합계가 상한을 초과했을 때만 먼저 “중단된 기록의 잔여물” (아래)을 정리하고, 그래도 초과하면 **오래된 세대부터** 삭제합니다 (세대 이름순 = 시간순, 풀 전체를 대상으로 함). 기록을 확정한 직후, 시작할 때, 정상 종료할 때, 창에서 사용량을 선택했을 때 수행합니다.

- 보호하는 세대는 삭제하지 않습니다.
  - 현재 실행의 풀에서 읽을 수 있는 가장 최신 세대
  - 비정상 종료한 실행의 각 풀에서 읽을 수 있는 가장 최신 세대 (아래 “비정상 종료한 실행의 세대”)
- 세대를 삭제해 비워지는 것은 그 세대만 사용하는 공유 내용입니다. 다른 세대가 사용하는 내용은 사용하는 세대가 없어질 때까지 남습니다. 모든 내용을 다른 세대와 공유하는 세대는 삭제해도 공간이 비워지지 않으므로 건너뜁니다 (동일 내용의 세대들만 남아 상한을 초과한 경우에만 오래된 쪽 1개를 삭제해 나머지를 삭제 시 공간이 비워지는 세대로 만듦).
- 손상된 세대 (manifest를 읽을 수 없음)는 비워지는 양이 0이어도 읽을 수 있는 세대보다 먼저 삭제합니다. 남아 있으면 같은 풀의 공유 내용을 삭제하지 못해 읽을 수 있는 세대를 삭제해도 사용량이 줄지 않기 때문입니다.
- 세대가 없어진 풀은 폴더 전체를 삭제합니다 (현재 실행의 풀 제외).
- 보호하는 세대만으로 상한을 초과하면 더 삭제하지 않고 초과 상태로 둡니다.
- 세대를 삭제한 뒤 실제 사용량을 다시 계산합니다. 추정만큼 줄지 않았다면 (삭제해도 공간이 비워지지 않는 내용이 남아 있음) 더 이상 세대를 삭제하지 않습니다. 추정이 틀린 상태에서 오래된 세대를 계속 삭제해 남은 세대를 불필요하게 잃지 않도록 하기 위함입니다.
- “보관할 세대” 수에 따른 정리 (종료한 실행 전체에서 설정한 수만큼 보관)는 별도로 계속 동작합니다. 상한은 그 정리 후에 추가하는 1개의 제한 장치입니다.

보장 범위: 상한 정리는 기록을 확정한 **후**에 수행하므로 기록 중에는 새 세대 1개만큼 초과할 수 있습니다 (초과분은 여유 공간 보호가 담당). 다른 창에서 사용 중인 풀은 삭제할 수 없으므로 그만큼 상한 초과 상태가 유지될 수 있습니다.

이 버전을 처음 실행했을 때 이미 상한 (자동이면 약 2 GB)을 초과하는 세대가 쌓여 있다면 그 자리에서 오래된 세대부터 삭제합니다.

<a id="落ちた書き込みの残り"></a>

### 중단된 기록의 잔여물

기록 도중 충돌하거나 패닉이 발생하면 작성 중인 세대 `.staging-<世代>/` (공유 내용을 기록 중인 `<中身の SHA-256>.pending` 포함)가 남습니다. 아직 manifest가 없으므로 이런 항목이 1개라도 있는 풀에서는 어떤 세대도 사용하지 않는 공유 내용도 삭제할 수 없습니다. 그 결과 세대를 삭제해도 사용량이 줄지 않고, 상한 정리가 오래된 세대만 모두 지워 버릴 수 있습니다. 이를 방지하기 위해 상한 초과 시 세대를 삭제하기 전에 다음을 수행합니다.

- 해당 풀의 `.save.lock`을 획득할 수 있을 때만 (현재 기록 중인 도구가 없을 때) `.staging-*` 폴더를 삭제한 다음 어떤 세대도 사용하지 않는 공유 내용을 삭제합니다. 기록은 확정 과정 전체에 걸쳐 잠금을 유지하므로, 잠금을 얻었는데 남아 있는 항목은 중단된 기록의 잔여물입니다. 잠겨 있는 풀 (기록 중)과 다른 창에서 사용 중인 풀은 건너뜁니다.
- 세대 (`current`·`previous`가 가리키는 것 포함)는 변경하지 않습니다. 잔여물 정리만으로 상한 이내가 되면 세대를 1개도 삭제하지 않습니다.
- 심볼릭 링크인 `.staging-*`는 따라가지도 삭제하지도 않습니다 (남아 있으면 공유 내용을 삭제할 수 없으므로, 그 부분은 세대 삭제 후 사용량 확인 (위)에서 처리).

상한 이내인 동안에는 잔여물도 그대로 둡니다 (상한 안에 있으므로 디스크를 지나치게 사용하지 않음).

<a id="設定を読めないとき"></a>

### 설정을 읽을 수 없는 경우

`recovery.conf`를 읽을 수 없는 동안에는 선택한 사용량을 알 수 없으므로 상한 기준으로 삭제하지 않습니다 (세대 수 정리와 같은 처리). 창에서 사용량을 선택하면 해당 실행 동안에는 선택한 양으로 정리합니다. 읽을 수 없는 설정 파일은 변경하지 않습니다. 여유 공간 보호는 설정과 관계없이 동작합니다.

<a id="空きの守り"></a>

## 여유 공간 보호

복구 세대를 기록하기 전에 저장 위치가 있는 디스크의 여유 공간을 확인합니다.

- **이번에 새로 기록할 바이트 수** (이전 세대와 같은 내용은 제외)를 여유 공간에서 뺐을 때 나머지가 “비워 둘 양”보다 적으면 기록하지 않고 짧게 이유를 알립니다 (`復旧用の書き置きを見送りました（ディスクの空きが少ない）。`). 그리기는 중단하지 않습니다.
- 다음 간격에 여유 공간을 다시 확인하고 회복되면 기록한 뒤 “복구용 기록을 재개했습니다”를 표시합니다.
- 여유 공간이 부족한 동안에는 간격마다 입력 자료를 취하는 것 외에는 여유 공간만 확인하고 거부합니다. 기록 시작 시 쓸 양을 0으로 두고 여유 공간이 비워 둘 양보다 적은지 1번 확인합니다. 부족하면 세대 구성·직전 세대 다시 읽기·해시 계산도 하지 않습니다.
- 새로 기록할 양을 더한 확인은 실제 기록 직전에 다시 1번 수행합니다.
- 정상 종료 시 마지막 기록에도 같은 규칙을 적용합니다 (이전 세대는 유지).

<a id="落ちた実行の分"></a>

## 비정상 종료한 실행의 세대

시작 시 이전 실행 표시 (`session.lock`)가 남아 있으면 비정상 종료한 실행으로 보고 `crashed`로 바꾼 뒤 창을 표시합니다. 비정상 종료한 실행의 세대는 다음과 같이 처리합니다.

- 비정상 종료한 실행마다 읽을 수 있는 가장 최신 세대는 **사용자가 폐기하거나 해당 세대가 30일보다 오래될 때까지** 상한 기준으로 삭제하지 않습니다. 30일은 고정값이며 설정 항목은 없습니다.
- 그 밖의 세대 (해당 실행의 오래된 세대, 30일이 지난 최신 세대)는 상한을 초과했을 때 삭제 대상이며 오래된 것부터 삭제합니다. 상한 이내인 동안에는 유지합니다 (30일이 지났다는 이유만으로 삭제하지 않음).
- 창의 “폐기”는 언제든 사용할 수 있습니다.

<a id="gpu-でエラーが起きたとき"></a>

### GPU 오류가 발생한 경우

드라이버 재시작·GPU 분리 등으로 GPU 오류가 발생해 사용할 수 없게 되면 창을 다시 그릴 수 없습니다. 이때 YoluPainter는 그리던 이미지에 손대지 않고, 변경 사항이 있으면 복구 세대를 즉시 기록합니다. 이어 OS 창으로 이유 (“GPU 오류가 발생해 계속할 수 없습니다.”에 복구용 저장 성공 여부를 덧붙인 문장)를 알리고 종료합니다. GPU 오류를 감지한 후에는 창을 다시 그리지 않고 종료합니다 (감지는 GPU 오류 통보 후의 확인이므로 직전 렌더링까지 막을 수는 없음). 그리는 도중의 스트로크는 그린 지점까지 확정합니다.

- **저장 중**: 복구 세대를 기록하기 전에 저장 완료를 최대 60초 기다립니다 (이 동안 창은 갱신되지 않음). 저장 후 남은 변경 사항 (저장 중 그린 부분·저장 실패로 되돌아온 변경)은 복구 세대에 기록합니다. 60초 안에 끝나지 않으면 더 기다리지 않고 종료하며 복구용으로 저장하지 못했다고 알립니다. 저장이 도중에 끊겨도 완성된 임시 파일만 교체되므로 이전 버전이 남습니다.
- **종료 시**: 저장하지 않은 변경 사항이 있거나 저장이 끝나지 않았다면 `session.lock` 표시를 삭제하지 않습니다 (비정상 종료와 동일). 따라서 다음 시작 시 복구 창에서 이어서 열 수 있습니다. 변경 사항이 없으면 정상 종료와 마찬가지로 표시를 삭제합니다. 실행 중인 내보내기 등의 작업은 중지하며 (최대 3초 대기), 배치 파일은 다시 기록하지 않습니다 (기존 배치 유지). 같은 사건을 충돌 기록 (`logs/crash-*.log`)에도 남깁니다. 프로세스 종료 코드는 70입니다.

GPU 오류 중 처리 대상이 없는 오류 (검증·메모리 부족)는 앱을 멈추지 않고 일반 로그 (`logs/session-*.log`)에 1행을 기록합니다. 메모리 할당 실패로 중단될 때는 실패한 크기와 호출 주소를 충돌 기록에 남깁니다 (실패를 처리하고 계속 실행한 뒤 정상 종료했다면 기록에 남기지 않음).

<a id="04x-までの-unity-ブリッジが書いた世代"></a>

## 0.4.x까지의 Unity 브리지가 기록한 세대

0.4.x까지의 Unity 브리지는 Unity 프로젝트의 `Library/YoluPainter/recovery-<GUID>/`에 같은 구조의 복구 세대를 기록했습니다. 독립 실행형 앱은 이 폴더를 **계산하지도 삭제하지도 목록에 표시하지도 않습니다** (풀 이름 형식이 아니기 때문). `directory`를 Unity의 `Library/YoluPainter`로 지정해도 같습니다.
반대로 이 앱이 기록한 세대를 0.4.x까지의 Unity 브리지가 읽을 수 있는 것은 중첩 이름 (열었던 `.ylp`의 합성 PNG 등)을 포함하지 않은 세대뿐입니다 (해당 Unity 브리지는 중첩 이름을 “안전하지 않은 이름”으로 거부). 0.5.0부터의 Unity 브리지는 복구 세대를 열지 않습니다 (폴더의 파일은 삭제되지 않고 유지).
이 문서의 상한·여유 공간 보호는 세대 저장 위치의 구조 (위 도표)를 변경하지 않습니다.

<a id="ディスクキャッシュとの関係"></a>

## 디스크 캐시와의 관계

설정의 “디스크 캐시” (“편집 → 설정…”의 “메모리”, 기본값 켜짐)는 레이어 메모리와 실행 취소 기록의 예산을 초과한 타일을 사용하지 않는 것부터 디스크로 옮겨 큰 문서에서도 계속 그릴 수 있도록 하는 기능입니다. 복구 기록과는 별개이며 다음과 같이 구분됩니다.

- **저장 위치**: 캐시 파일은 OS 임시 폴더에 실행마다 1개 (`yolupainter-cache-<数字>-<乱数>.bin`) 만듭니다. 위치는 “자세히”의 “캐시 위치”에서 변경할 수 있으며, 변경하면 다음에 옮기는 데이터부터 새 위치의 파일에 기록합니다. 복구 저장 위치 (`recovery/`)와 별개이며 이 문서의 사용량 (상한·여유 공간 보호)에 포함하지 않습니다.
- **수명**: Unix에서는 파일을 연 직후 이름을 삭제하고, Windows에서는 닫을 때 삭제하는 플래그로 열기 때문에 충돌해도 남지 않습니다. 전원 차단 등으로 이전 실행의 파일이 남았다면 다음 시작 시 백그라운드에서 삭제합니다. 내용은 해당 실행 동안만 사용하는 작업용 사본이며 복구 원본으로 사용할 수 없습니다.
- **저장과 복구 기록**: 타일이 메모리에 있든 디스크로 옮겨졌든 저장과 복구 기록은 같은 내용을 작성합니다.
- **디스크에서 읽을 수 없어진 경우**: 읽을 수 없는 타일을 투명하게 처리하고 계속 진행하지 않습니다. 해당 세트는 읽기 전용이 됩니다. 저장한 적 있는 세트는 열었을 때의 내용 그대로 저장합니다. **저장한 적 없는 세트** (새 프로젝트·이전 저장 후 추가한 세트)는 원본 내용이 없으므로 해당 세트만 저장·복구 기록·배포용 저장에서 제외하고 다른 세트는 계속 기록합니다. 제외한 세트는 저장할 때마다 “텍스처 세트 ‘…’을(를) 읽을 수 없어 저장에 포함하지 않았습니다”라고 알리며, 저장 후에도 “저장하지 않은 변경 사항” 표시가 남습니다. 기록할 수 있는 세트가 1개도 없으면 이유와 함께 저장을 거부하고 복구 기록을 만들지 않습니다.
