# PSD 불러오기

YoluPainter는 PSD(RGB 8 bit)를 **원본 파일에 다시 쓰지 않는 복사본**으로 가져옵니다. 가져온 문서를 PSD로 내보낼 때는 항상 새 PSD가 됩니다(가져온 파일과 같은 위치에 쓸 때는 교체 전에 확인).

<a id="取り込みの流れ"></a>

## 가져오기 흐름

“파일 → 가져오기”의 “PSD를 새 텍스처 세트로…”(새 세트로)와 “PSD를 현재 텍스처 세트로…”(현재 세트 문서 교체) 외에도 창에 .psd를 끌어놓으면 “파일 가져오기” 창에 행이 나열됩니다. 행마다 가져올 위치를 선택하고 모두 결정하면 “가져오기”를 누를 수 있습니다. PSD의 대상은 텍스처 세트(파일 이름의 새 레이어 세트로 추가) 또는 기존 레이어 세트(맨 위에 추가)입니다.
대상 문서와 캔버스 크기가 다른 행, 읽기 전용 세트는 선택할 수 없습니다(크기를 조절하여 가져오지 않음). 기존 레이어 세트에 넣을 때는 가져온 최상위 계층의 맨 아래 레이어에서 클리핑 표시를 제거합니다(PSD 안에서는 아래에 아무것도 없어 바탕으로 합성되었기 때문). 그리는 동안에는 거부합니다. 레이어·효과·Anchor·자의 ID는 새로 할당하며 가져오기는 대상 텍스처 세트마다 한 번의 실행 취소로 되돌릴 수 있습니다.

Live Link로 연 Unity 머티리얼의 Color 원본 이미지가 PSD(sRGB)인 경우에도 같은 가져오기 과정으로 레이어를 유지한 채 텍스처 세트에 들어갑니다([LIVELINK.md](LIVELINK.md)의 “독립 실행형에서 받는 방법”의 원본 이미지).
읽기 방식·예산(PSD 하나마다 설정의 “레이어 메모리”)·제외하거나 변경되는 항목의 분류는 수동 가져오기와 같으며, 확인 창을 표시하지 않고 제외·변경 항목을 알림에 표시합니다.
원본 PSD는 읽기만 합니다. 가져올 수 없는 PSD(예산 초과 등)는 이유를 알리고 합쳐진 한 장의 이미지로 처리합니다.

1. 파일을 처음부터 스트리밍하여 읽습니다. 파일 전체를 메모리에 두지 않고 레이어 픽셀을 한 장씩 디코딩하여 문서에 넣습니다. 원본 파일 크기에는 상한이 없습니다.
2. 레이어 수·캔버스·레이어 픽셀·레이어 한 장의 부가 정보(효과나 스마트 오브젝트 내용 등) 상한은 설정의 “레이어 메모리” 예산으로 결정됩니다(레이어 수는 예산 1 MiB당 1장, 256~32767장). 초과하면 이유와 함께 거부합니다. 설정에서 예산을 올리면 가져올 수 있는 경우가 있습니다. 단, 가져온 문서를 .ylp에 저장할 수 있도록 한 변 8192·레이어 2048장(그룹도 셈. 구분 기록은 세지 않음)·그룹 중첩 64단계의 상한은 예산을 올려도 초과하여 가져올 수 없습니다.
3. 제외·변경 항목이 하나라도 있으면(무시 항목만 있으면 확인 없이 가져옴) 가져오기 전에 “PSD 가져오기 확인” 창에 레이어 이름과 기능 이름으로 나열합니다. “가져오기”를 누르기 전에는 아무것도 넣지 않습니다. 항목이 하나도 없으면 창은 표시되지 않습니다.
4. 가져온 문서의 합성을 PSD에 저장된 병합 이미지와 비교하여 차이가 2(0~255)를 넘으면 최대 차이와 차이가 있는 픽셀의 비율을 창에 표시합니다. 2 이하는 합성 반올림 차이로 간주하여 알리지 않습니다.

<a id="扱いの-3-種類"></a>

## 3가지 처리 방식

| 처리 | 의미 |
|---|---|
| 무시 | 외관과 내용 모두에 영향을 주지 않는 정보. 보관하지 않습니다 |
| 제외 | 레이어 픽셀은 남기지만 해당 기능의 설정·원본 데이터는 보관하지 않습니다. 픽셀이 없는 미지원 조정은 레이어 전체를 제외합니다 |
| 변경 | 평가할 수 없는 효과 등 합성이 PSD 병합 이미지와 달라질 수 있는 항목. 레이어 픽셀 그대로 가져옵니다 |

### 합성에 영향을 주지만 평가할 수 없는 항목(변경)

| 정보 | 가져오는 방식 |
|---|---|
| 레이어 효과(`lfx2` 등) | 레이어 픽셀 그대로. 효과는 평가하지 않습니다 |
| 벡터 마스크 | 레이어 픽셀 그대로. 평가하지 않습니다 |
| 미지원 합성 모드(디졸브 등) | 일반으로 변경 |
| 혼합 조건(Blend If)·클리핑된 레이어의 그룹 합성·내부 효과의 그룹 합성·녹아웃·채널 합성 제한 | 평가하지 않습니다 |
| 채우기 불투명도(`iOpa`) | 레이어 불투명도에 곱합니다. 합성 모드에 따라 Photoshop과 조금 달라집니다 |
| 마스크의 미지원 플래그·흐림·사용자 마스크와 벡터 마스크 조합 | 마스크 픽셀 그대로 |
| 마스크 기본값이 0·255 이외 | 가까운 쪽인 0 또는 255로 변경합니다. 사각형 밖의 표시가 바뀝니다(기본값 100이면 바깥 전체가 숨겨짐) |
| 픽셀 값이 없는 마스크(사각형 정의만 있고 채널 없음) | 기본값만 있는 마스크로 만듭니다. 사각형 내부의 표시가 바뀔 수 있습니다(사각형이 비어 있으면 원래부터 기본값뿐이므로 알리지 않음) |
| sRGB 이외의 색상 프로파일 | 색을 변환하지 않고 픽셀 값 그대로 |
| 정사각형이 아닌 픽셀 가로세로 비율 | 정사각형 픽셀로 처리 |

### 레이어 픽셀은 보관하지만 설정은 보관하지 않는 항목(제외)

| 정보 | 가져오는 방식 |
|---|---|
| 스마트 오브젝트 | 레이어 픽셀 그대로. 원본 데이터는 보관하지 않습니다 |
| 텍스트 | 레이어 픽셀 그대로. 문자 데이터는 보관하지 않습니다 |
| 그라데이션·패턴 채우기, 벡터 마스크가 있는 채우기 | 레이어 픽셀 그대로. 설정은 보관하지 않습니다 |
| 미지원 조정 레이어(선택 색상·채널 혼합기·포토 필터·활기·흑백·색상 검색·노출 등) | 픽셀이 없으므로 레이어 전체를 제외합니다 |
| 내용을 읽을 수 없는 조정(채널별 레벨·Colorize·표현할 수 없는 곡선 등) | 레이어 전체를 제외합니다 |
| 캔버스 밖의 픽셀·마스크 값 | 잘라 버립니다(바깥에 투명 픽셀만 있으면 잃는 것이 없으므로 알리지 않음) |
| 4096문자(UTF-16 단위)를 넘는 레이어 이름 | 4096문자까지 자릅니다 |
| 그룹 자체의 픽셀·RGB 채널이 모두 갖춰지지 않은 레이어 | 제외합니다 |

<a id="取り込める調整そのままレイヤーになります"></a>

### 가져올 수 있는 조정(그대로 레이어가 됨)

반전·레벨(RGB 일괄)·색상/채도·그라데이션 맵·톤 곡선·색상 균형·밝기/대비·이진화·포스터화입니다.
색조 보정 6종(그라데이션 맵·톤 곡선·색상 균형·밝기/대비·이진화·포스터화)은 Photoshop 조정 레이어(`grdm`·`curv`·`blnc`·`brit`와 `CgEd`·`thrs`·`post`)로 읽고 씁니다.
이 앱에서 표현할 수 없는 내용은 가져올 때 레이어 전체를 제외합니다(위의 “내용을 읽을 수 없는 조정”).

- 그라데이션 맵: 디더, 매끄러움이 100%가 아닌 것, 노이즈 유형, RGB 이외의 색, 분기점 수·순서·중간점을 표현할 수 없는 것.
- 톤 곡선: 점이 16개를 넘는 곡선, 양 끝 입력이 0과 255가 아닌 곡선(Photoshop의 “자동”이 흔한 예), 이웃 점 사이가 6단위보다 가까운 곡선.
- 밝기/대비: 구형 기록(`brit`만 있거나 구형을 가리키는 `CgEd`), 자동, Lab, 범위 밖, `brit`와 `CgEd` 불일치.

<a id="取り込めないもの断ります"></a>

### 가져올 수 없는 항목(거부)

| 이유 | 비고 |
|---|---|
| PSB 형식 | |
| RGB 8 bit 이외(CMYK·그레이스케일·16 bit 등) | |
| 레이어 없는 PSD(병합 이미지만 있음) | |
| 예산 초과(레이어 수·캔버스·레이어 픽셀·레이어 한 장의 부가 정보) | 설정의 “레이어 메모리”를 올리면 가져올 수 있는 경우가 있습니다 |
| 손상·도중 잘림 | 레이어 데이터가 잘린 경우. 병합 이미지만 잘렸으면 레이어는 가져오고 비교를 생략했다고 알립니다 |

읽을 수 있는 압축은 무압축·PackBits(RLE)·ZIP·예측 ZIP입니다.

<a id="psd-の書き出し"></a>

# PSD 내보내기

내보내기는 현재 문서의 복사본에서 채널마다 PSD 하나를 작성합니다(문서는 바뀌지 않음). “파일 → PSD 내보내기…”의 “PSD 내보내기” 창에서 방식(구워서 내보내기·한 장으로 평탄화)과 채널을 선택하고 “내보내기…”를 누릅니다. 굽기·반올림·제외할 항목이 있으면 쓰기 전에 “PSD 내보내기 확인” 창에 레이어 이름과 함께 나열하며 “쓰기”를 누르기 전에는 쓰지 않습니다.

<a id="書き出す中身"></a>

## 내보내는 내용

“PSD 내보내기” 창에서 채널을 선택합니다(기본값은 Color만). 채널마다 PSD 하나를 쓰며 여러 채널은 `<名前>_<チャンネル>.psd`를 나란히 씁니다.
레이어의 합성 모드·불투명도·표시 여부는 해당 채널 값을 사용하며 Normal은 문서의 파일 방향으로 씁니다.
해당 채널에 적용되지 않는 레이어(비활성·면이나 값 없음·색 채널 전용 조정)는 숨긴 레이어로 씁니다.

텍스처 세트에 레이어 세트가 2개 이상이면 레이어 세트마다 최상위 그룹(분리. 이름은 레이어 세트 이름이며 비어 있으면 `Set <番号>`)으로 작성하고, 내보내는 채널을 출력하는 레이어 세트의 그룹만 표시합니다(PSD 합성이 해당 채널의 최종 결과와 같아짐).
해당 채널에 출력 할당이 없으면 모든 그룹을 숨기고 맨 아래에 기본값으로 채운 표시 상태의 채우기 레이어(이름은 `Default`)를 추가합니다. 레이어 세트가 하나이고 출력 할당도 있으면 기존과 같은 방식으로 씁니다.

레이어 잠금(투명 영역·픽셀·위치·전체)은 `lspf`에 쓰며 가져오면 레이어 잠금으로 복원됩니다(PSD에 없는 비트는 가져오기 결과에 “잠금 비트”로 표시).

“구워서 내보내기”는 PSD에 대응 구조가 없는 항목을 다음과 같이 씁니다. 수행한 작업은 쓰기 전 확인 창에 레이어 이름과 함께 나열됩니다.

| 내용 | 작성 방식 |
|---|---|
| 레이어 필터(생성기 포함)·채우기 이미지/투영/데칼/그라데이션·반투명 채우기 | 평가한 픽셀 레이어로 변환(굽기) |
| 마스크 필터·반전 마스크 | 평가·반전한 값을 마스크 픽셀로 변환(굽기) |
| 클리핑된 그룹 | 그룹 합성을 한 장의 레이어로 변환(클리핑 표시는 유지) |
| 경로·텍스트 레이어 | 픽셀 레이어 그대로. 경로 정보·텍스트 값은 PSD에 남지 않음 |
| Anchor·적용되지 않는 필터 단계 | 제외(픽셀은 바뀌지 않음) |
| 아무것에도 클리핑되지 않는 그룹의 클리핑 표시 | 해제하여 일반 그룹으로 변경(외관은 같음) |
| PSD 단위 간격 사이의 조정(레벨·색상/채도·톤 곡선·색상 균형·밝기/대비·그라데이션 맵) | 조정 레이어를 유지하며 가장 가까운 단위로 반올림(값과 합성의 최대 차이를 나열) |
| 그라데이션 맵의 값 곡선(혼색 포함) | 조정 레이어를 유지하며 곡선을 통과한 색·불투명도 정지점 배열로 펼침(정지점 수와 합성 최대 차이를 나열) |

- 이진화·포스터화는 정수 설정만 있어 단위 사이 값이 없으므로 반올림하지 않습니다.
- 그라데이션 맵 정지점은 색·불투명도 각각 최대 32개입니다. 펼치기는 해당 조정 레이어 한 장의 출력 차이(일반 합성 모드·불투명도 100%에서 아래 색과 관계없는 최악값)가 1 이하가 되는 최소 개수를 목표로 하며, 불투명도 변화로 부족하면 2·4까지 완화합니다.
  그래도 32개 안에 들어가지 않는 경우, 해당 채널의 합성에 나타나는 레이어이면 레이어 이름과 함께 거부합니다(표시를 끈 레이어·해당 채널에 적용되지 않는 레이어는 최선의 펼치기를 숨긴 레이어로 작성).
- 이 차이는 문서 합성 차이의 상한이 아닙니다. 레이어 합성 모드·위쪽 레이어에 따라 늘어날 수 있으므로 확인 창 주석에는 문서 합성에서 실제 측정한 최대 차이가 표시됩니다.
- 내보내기는 문서의 복사본이며 문서는 바뀌지 않습니다. 효과는 문서에 남지만 구운 레이어에는 효과 설정이 없으므로 PSD를 다시 가져와도 효과가 복원되지 않습니다.
- 파일 방향이 DirectX인 Normal은 레이어의 초록 채널을 반전하여 씁니다. PSD의 레벨 조정 하나로 작성할 수 없는 레벨 레이어가 있으면 거부합니다.
- 색 채널 이외(스칼라 채널)의 톤 곡선은 RGB 전체 곡선만 적용되므로 R·G·B 곡선은 직선으로 씁니다.

작성한 PSD를 다시 읽은 합성이 내보낸 채널의 현재 합성과 일치하는지 확인했지만(내보낼 때마다가 아니라 테스트로 확인), 다음은 일치하지 않습니다.

- 반올림하거나 펼치는 조정.
- 1/255 단위에 맞지 않는 레이어 불투명도와 마스크 농도(PSD가 반올림. 확인 창에는 표시되지 않음).
- Normal 레이어가 겹치는 곳(PSD는 색 수식으로 겹치므로 노멀로 겹치는 이 앱과 다름. 확인 창에 주석 표시).
- 반전 마스크를 구운 레이어가 겹치는 곳(부동소수점 마지막 자리 차이로 드물게 한 픽셀이 1만큼 어긋남).

색조 보정 6종의 수식은 이 앱 자체의 것이며 내보낸 PSD의 병합 이미지도 이 앱 수식의 결과입니다. Photoshop·CLIP STUDIO에서 열어 조정 레이어가 다시 평가되면 외관이 바뀔 수 있습니다(실제 기기에서는 확인하지 않음).

<a id="書き出しの流れ"></a>

## 내보내기 흐름

1. 계획(무엇을 굽고·반올림하고·제외할지)과 확인 후 별도 스레드에서 씁니다.
2. 레이어는 한 장씩 평가하여(구울 것은 구워) 압축하고 저장 대상과 같은 폴더의 임시 파일에 스트리밍하여 씁니다. 메모리에 두는 것은 레이어 한 장 분량과 레이어 기록 테이블뿐이며 전체 레이어 픽셀 합계에는 상한이 없습니다.
3. 작성을 마친 임시 파일을 모든 레이어·마스크·병합 이미지의 마지막 행까지 스트리밍하여 다시 읽고 확인합니다(행 디코딩, 길이와 레이어 수가 작성한 것과 일치하는지, 가져올 때 제외·변경되는 항목이 없는지). 동시에 다시 읽은 파일이 작성한 바이트 배열과 일치하는지를 쓰면서 계산한 CRC-32와 길이로 확인합니다(바이트 단위의 완전 비교가 아니며 2^-32 확률로 데이터 변형을 놓침). 작성한 픽셀이 문서 픽셀과 같은지는 내보낼 때마다 비교하지 않습니다(다시 읽은 합성이 내보낸 문서와 같다는 것은 실제 크기의 문서로 확인). 모든 채널이 끝난 뒤 마지막에 교체합니다. 도중 실패·취소·비정상 종료 시 임시 파일을 지우고 원본 파일은 바꾸지 않습니다.

Normal 굽기와 “한 장으로 평탄화”만은 병합 이미지를 작성한 레이어에서 만들거나(Normal) 한 장의 레이어 자체이므로(평탄화), 모든 레이어를 메모리에 만든 뒤 씁니다. 이 방식의 픽셀 합계는 아래 예산이 상한입니다.

텍스트 레이어는 렌더링 결과의 픽셀 레이어로 씁니다(텍스트 값은 PSD에 남지 않으며 “PSD 내보내기 확인”에 레이어 이름과 함께 나열). PSD 가져오기에서 텍스트 레이어를 픽셀 그대로 가져오는 처리는 위 표와 같습니다.

<a id="上限"></a>

## 상한

| 항목 | 상한 |
|---|---|
| 캔버스 | 설정의 “레이어 메모리” 예산에 픽셀(1픽셀당 4바이트)이 들어가는 범위. 한 변 최대 30000 |
| 레이어 기록 | 예산 1 MiB당 1건(256~32767건). 그룹은 구분 기록도 1건으로 셈 |
| 레이어 한 장의 픽셀 | 캔버스 범위 |
| 전체 레이어 픽셀 합계 | 스트리밍 내보내기는 상한 없음. 메모리에 만드는 내보내기(Normal 굽기·평탄화)는 예산까지 |
| 파일 | 2 GiB(PSD 형식 상한. 압축 후 크기이며 쓰면서 확인) |
| 그룹 중첩 | 64단계(문서 자체 상한으로 내보내기와 가져오기 동일) |

초과하면 레이어 이름을 포함한 이유(캔버스는 크기, 레이어 기록은 건수와 상한)와 함께 거부하며 아무것도 쓰지 않습니다. 예산 때문에 거부한 경우 설정의 “레이어 메모리”를 올리면 내보낼 수 있는 경우가 있습니다(파일 2 GiB와 한 변 30000은 형식 상한이므로 올려도 쓸 수 없음). 캔버스·레이어 기록·레이어 픽셀의 예산 결정 방식은 가져오기와 같습니다.

<a id="圧縮"></a>

## 압축

레이어·마스크·병합 이미지 채널을 RLE(PackBits. Photoshop 기본값)로 씁니다. 레이어와 마스크 채널은 하나씩 압축하며 압축하면 커지는 것(난수 같은 픽셀)은 무압축으로 씁니다. 병합 이미지는 전체 채널이 하나의 압축이므로 작아지지 않으면 무압축입니다. 행별 길이 테이블은 PSD 사양을 따르며 이 도구의 읽기(원본을 보존하는 읽기와 복사본으로 가져오기)로 다시 읽을 수 있습니다. Photoshop·CLIP STUDIO 실제 기기에서는 확인하지 않았습니다.

색 면이 많은 4096²·34레이어(반투명·합성 모드·마스크·그룹·조정·구울 필터) 문서에서는 파일이 63 MiB로, 무압축 작성 시의 6%였습니다. 난수처럼 압축할 수 없는 픽셀이 많은 문서는 무압축에 가까운 크기가 됩니다.
