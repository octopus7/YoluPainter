# 브러시 가져오기

브러시 목록 아래쪽 바의 “브러시 가져오기”(파일 선택 또는 파일 끌어놓기)를 통해 다른 앱의 브러시를 사용자 브러시(“가져오기” 그룹)로 만듭니다.
읽을 수 있는 형식은 GIMP의 `.gbr`·`.gih`·`.vbr`, Photoshop의 `.abr`·`.pat`, PNG 브러시 끝, CLIP STUDIO PAINT의 `.sut`입니다. Krita 프리셋(`.kpp`)은 이유를
표시하고 거부합니다. 이 앱에서 표현할 수 없는 설정은 알리지 않고 버리지 않고, 브러시 행의 표시와 도구 설명에 **표현할 수 없었던 항목의 이름**을 표시합니다.
브러시 목록 아래쪽 바의 또 다른 버튼인 “CLIP STUDIO에서 가져오기”는 CLIP STUDIO PAINT의 보조 도구 폴더를 찾아 `.sut` 목록을 만들고 선택한 항목만 가져옵니다
(아래의 “보조 도구 폴더에서 선택하기” 참조).
읽기는 백그라운드 스레드에서 수행하며, 읽지 못한 파일은 이유를 알려줍니다. 형식별 세부 처리(상한·손상된 파일 처리)는
[`crates/yolu-io/README.md`](https://github.com/YozoraKurage/YoluPainter/blob/main/crates/yolu-io/README.md)의 “브러시 형식 가져오기”를 참조하세요.

<a id="clip-studio-paint-のブラシsut"></a>

## CLIP STUDIO PAINT 브러시(`.sut`)

`.sut`는 보조 도구 1개를 내보낸 파일이며, 내부는 SQLite 데이터베이스입니다. 공개된 사양이 없어 공개된 분석으로 알 수 있는 범위만 읽습니다.
열 이름과 일부 단위는 분석을 통한 추정이며, CLIP STUDIO 버전에 따라 열 구성이 다르므로 “존재하는 열만 읽는” 방식으로 구현했습니다.

브러시 끝과 질감 이미지는 소재의 독자 컨테이너(C2F, 확장자 `.layer`)에 있는 원본 크기의 이미지를 읽습니다(아래의 “소재 컨테이너 C2F” 참조). 읽을 수 없으면 소재에 있는
미리 보기 PNG를 사용합니다(원본 크기가 아니므로 알립니다. 모든 소재에 같은 범용 이미지가 들어 있으면 잘못된 이미지를 브러시 끝으로 사용하지 않도록 제외합니다). 그것도 없으면 원형 브러시 끝·질감
없음으로 설정(크기·간격·유량·필압 등)만 가져오고 “독자 형식이어서 읽을 수 없음”을 알립니다.
테스트는 아래에 설명한 구조를 테스트 안에서 생성한 합성 파일로 수행합니다.

### 보조 도구 폴더에서 선택하기

브러시 목록 아래쪽 바의 “CLIP STUDIO에서 가져오기”로 창을 열면 CLIP STUDIO PAINT 설정 폴더 아래의 `.sut`를 찾아 목록으로 표시합니다(이름과 브러시 끝 미리 보기, 선택 표시·
모두 선택·가져오기). 선택한 항목만 일반 `.sut` 가져오기와 같은 경로로 가져옵니다. 창 아래쪽 바의 “폴더…”로 검색할 폴더를 직접 선택할 수도 있습니다(CLIP STUDIO 외부
폴더도 같은 방법으로 검색해 목록으로 표시합니다). “다시 검색”은 현재 위치를 다시 검색합니다. 찾지 못하면 창의 상태 한 줄에 이유(폴더를 찾을 수 없음·열 수 없음·
보조 도구 없음)를 표시합니다.

- **검색 위치**: CLIP STUDIO의 공식 안내(지원 문서와 CLIP STUDIO ASK 답변)에 따르면 CELSYS 설정 폴더는 Windows의
  `C:\Users\<名前>\AppData\Roaming\CELSYSUserData\CELSYS`(V1.10.13 이후)와 그 이전의 `C:\Users\<名前>\Documents\CELSYS`(OneDrive가 문서를 동기화하면
  `OneDrive\Documents\CELSYS`)입니다. 이 2~3곳을 환경 변수 `APPDATA`·`USERPROFILE`·`OneDrive`로 구성해 검색합니다. **여기까지는 공개된 정보로 확인했습니다.**
- **그 아래**: `.sut`가 어느 폴더에 저장되는지(`CLIPStudioModule\SubTool\…`, 버전별 폴더 `CLIPStudioPaintVer…`, 다운로드한 소재의 `CLIPStudioCommon\Material\…` 등)는
  공개된 정보로 확인하지 못했습니다. 폴더 이름을 고정하지 않고 설정 폴더 아래를 얕은 곳부터 순서대로(너비 우선으로) 탐색하여 확장자가 `.sut`인 파일을 모읍니다
  (깊이 8·확인 항목 60000·수집 개수 1000까지. 상한에 도달하면 목록에 “일부만”을 표시합니다. 심볼릭 링크는 따라가지 않습니다).
  CLIP STUDIO가 `.sut`를 이 형태로 저장하지 않으면 찾지 못합니다(이때는 “폴더…”로 `.sut`를 내보낸 폴더를 선택하세요).
- **읽기 전용**: 검색할 때는 디렉터리 목록과 파일 크기만 읽고, `.sut`의 내용은 메모리로 읽은 뒤 엽니다. CLIP STUDIO 폴더에 쓰거나 파일을 이동·
  삭제하지 않으며, 옆에 작업용 파일도 만들지 않습니다. 임시 폴더에 복사한 뒤 여는 방식은 채택하지 않았습니다(복사 시점에 쓰기 도중의 내용을 가져올 수 있다는 점은 같고, 임시 파일 정리 실패 가능성도 늘어나기 때문입니다).
- **CLIP STUDIO가 열려 있을 때**: 파일은 공유 읽기로 열므로 쓰는 중이 아니면 읽을 수 있습니다(Windows의 기본 파일 열기 방식은 다른 읽기·쓰기와
  공유합니다. SQLite의 잠금은 파일 시작점보다 훨씬 뒤쪽 영역의 잠금이므로 시작 부분을 읽는 데 방해되지 않습니다). 쓰는 도중의 내용을 가져오지 않도록 읽기 전후에 다음 2가지를 확인하고, 일치하지 않으면 잠깐 기다렸다가
  다시 가져옵니다(최대 3회. 그래도 일치하지 않으면 이유를 표시하고 읽지 않습니다).
  - 파일 크기와 수정 시각이 같습니다.
  - 확정 전 페이지가 본체에 기록되었을 수 있음을 나타내는 백업 파일(`<ファイル名>-journal`)이 남아 있지 않습니다. 기록 측은 캐시가 넘치거나 커밋하는 도중에
    아직 확정하지 않은 페이지를 먼저 본체에 씁니다(원래 페이지는 백업 파일에 둡니다). 그 쓰기가 읽기 시작 전에 끝나고 멈춰 있으면 읽는 동안 본체 크기와 수정 시각이
    바뀌지 않으므로 위의 확인만으로는 구분할 수 없습니다(커밋 도중 CLIP STUDIO가 종료되어 백업 파일이 남은 경우도 같습니다). 백업 파일의 첫 1바이트는
    기록 측이 내용을 동기화한 뒤에야 0이 아니게 되고 본체 페이지는 그 이후에 덮어쓰므로, 첫 바이트가 0이 아닌 동안에만 거부합니다(SQLite 자체의 판정과 같습니다. 작은 쓰기 도중에는
    아직 0이므로 읽을 수 있습니다). SQLite가 직접 읽을 때는 남은 내용을 복원한 뒤 읽지만, 여기서는 쓰기를 하지 않으므로 복원하지 않고 거부합니다.
  쓰기 기록(`-wal`) 파일은 읽지 않으므로 아직 본체에 반영되지 않은 최신 변경 사항은 보이지 않습니다(반영이 끝난 본체를 읽습니다). 쓰기 기록을 본체에 반영하는 도중인지는
  크기와 수정 시각 확인만으로 구분합니다.
- 테스트는 테스트용 임시 폴더 구조(신·구 설정 폴더·얕은 곳과 깊은 곳·대문자 확장자·`.sut`가 아닌 파일), 읽기 전용 파일, 배타적 쓰기 도중인
  파일, 캐시를 넘치게 하여 확정 전 페이지를 본체에 쓰게 한 파일, 커밋 도중 남은 백업 파일(잔여 파일의 유무와 완료 후 무효화된 헤더), WAL 형식 파일,
  상한, 심볼릭 링크 순환을 대상으로 검색 방식·이유·“수정 시각·크기·내용·항목 수가 바뀌지 않음”을 확인합니다.
  **실제 Windows 기기에서는 확인하지 않았습니다**(CLIP STUDIO가 설치된 PC에서 폴더를 찾을 수 있는지, CLIP STUDIO가 열려 있을 때 읽을 수 있는지는 실제 기기에서 확인해야 합니다).

### 읽는 방법

- 파일을 임시 위치에 복사하지 않고 메모리의 읽기 전용 데이터베이스로 엽니다(원본 파일을 수정하지 않으며, 옆에 저널 등을 만들지 않습니다).
- 확장은 로드하지 않습니다. SQLite 자체에는 확장 로드 기능이 컴파일되어 있지만 SQL의 `load_extension()`은 활성화 함수를 호출하지 않으면
  사용할 수 없으며(“not authorized”), 리더는 그 함수를 호출하지 않습니다(테스트로 확인했습니다). 방어 모드·신뢰하지 않는 스키마·트리거와 뷰 비활성화·
  ATTACH 금지에 더해 문자열과 행 크기·표현식 깊이·명령 수·경과 시간에 상한을 둡니다. 명령 수는 파일을 읽는 동안의 합계이고 시간은 SQL 내부에서 사용한
  시간의 합계로, 이미지 디코딩 등 SQL 외부의 시간은 세지 않습니다. 상한에 도달한 파일은 이유와 함께 거부합니다. 쿼리는 정해진 테이블만 대상으로 하며, `Variant`는
  읽을 열만 선택합니다(읽지 않는 열의 생성 표현식은 평가하지 않습니다).
- 브러시는 `Node`에서 현재 설정 또는 기본 설정 번호가 있는 행입니다(최대 256개). 이름이 비어 있으면 파일명을 사용합니다. 설정 행이 없는 항목과 256개를 초과하여 읽지 않은
  항목은 가져오지 못한 것으로 셉니다(`Node`의 모든 행을 확인하여 셉니다).
- 크기 상한: 파일 128 MiB, 스키마 항목(테이블·인덱스 등) 1024개, 소재 256개, 추출 이미지 합계 128 MiB, 디코딩할 브러시 끝·질감 픽셀 합계 256 MiB
  (다른 형식과 같은 예산. 소재 C2F 디코딩은 별도로 전체 가져오기에서 최대 256 Mi픽셀), 이미지 한 변은 최대 2048픽셀입니다. 손상되거나 악의적인 파일은 패닉 없이 이유와 함께 거부합니다.
- 소재 C2F는 SQLite 자체를 거치지 않고 자체 리더(`src/brushes/sut/c2f.rs`)로 읽습니다(첫 페이지를 읽을 수 없어 유효한 데이터베이스가 되지 않기 때문입니다). 확장이나 SQL과는
  관계없으며, 청크·페이지·B 트리·행·픽셀 크기의 상한은 위의 “소재 컨테이너 C2F” 끝부분에 설명된 대로입니다.
- 헤더에 쓰기 기록(WAL) 형식 표시가 있는 파일도 일반 형식으로 읽습니다(원본 파일은 수정하지 않습니다). 헤더 앞에 별도의
  헤더가 있는 파일도 처음 4 KiB 안에 SQLite 시그니처가 있으면 읽습니다.

### 조사한 구조

| 위치 | 내용 | 확실성 |
|---|---|---|
| `Node` 테이블 | `NodeName`(이름)·`NodeVariantId`(현재 설정 번호)·`NodeInitVariantId`(기본 설정 번호) 열. 둘 다 또는 어느 한쪽이 0이 아닌 행이 브러시입니다 | 여러 분석에서 일치 |
| `Variant` 테이블 | 행 번호는 `VariantID` 열입니다(`_PW_ID`가 아닙니다. `VariantID` 열이 없으면 다른 행의 설정을 읽지 않도록 설정을 읽지 않고 기본값을 유지하며 알립니다). 열 하나가 설정 하나이며 수백 개의 열이 있습니다. 열 구성은 CLIP STUDIO 버전에 따라 다릅니다 | 여러 분석에서 일치 |

소재의 원본 크기 이미지는 소재 tar의 `data/material.layer`(또는 `material_0.layer`)에 있으며 CLIP STUDIO의 독자 컨테이너(C2F)에 들어 있습니다. 공개된 사양은 없으며,

소재 결정 방법: 참조 문자열과 소재 행의 문자열 열에서 경로와 확장자를 제거한 뒤 대조합니다(너무 짧은 이름·`thumbnail` 같은 일반적인 이름으로는 맞추지 않음).
이름으로 맞지 않은 참조는 브러시가 브러시 끝과 질감 중 한쪽만 사용하고, 참조 개수를 끝까지 읽었으며, 소재를 상한까지 모두 읽었고, 이름으로 맞지 않은 참조 수와
아직 사용하지 않은 소재 수가 **정확히 같을 때만**, 이미 맞춘 소재를 제외한 나머지 소재를 배열 순서대로 맞춥니다(파일에는 읽지 않는 설정의 소재도 들어 있을 수 있으므로
소재가 더 많으면 결정하지 않음). 순서로 맞춘 브러시 끝·질감은 추정이므로 “브러시 끝 이미지”·“질감 무늬” 항목으로 알립니다.
소재 내부의 `systemtag`로 모든 소재의 종류(브러시 끝·질감)를 알 수 있는 파일에서는 종류별로도 맞춥니다. 듀얼 브러시를 사용하는 설정 파일에는 메인 브러시 끝·질감
소재에 더해 듀얼 브러시 끝·질감 소재도 들어 있으므로, 해당 종류의 참조(메인 + 듀얼의 `DualPatternImageArray`·`DualTextureImage`) 중 이름으로 맞지 않은
개수와 아직 사용하지 않은 해당 종류의 소재 수가 **정확히 같을 때만** 참조 순서(메인이 먼저)와 소재 배열 순서로 맞춥니다(소재 이름은 CLIP STUDIO 내부 이름이며 참조 이름은
표시 언어의 이름이므로 이름으로는 맞지 않음). 종류를 모르는 소재가 하나라도 있거나 개수가 맞지 않으면 결정하지 않습니다. 이것도 추정으로 알립니다. 실제 파일 1개에서
현재 설정이 참조하는 소재 4개(브러시 끝 2·질감 2)만 들어 있고 같은 종류 안에서는 메인이 먼저였다는 사실에 근거한 규칙이며, 다른 파일에서도 같은 순서라고 보장할 수 없습니다.
참조 BLOB을 읽을 수 없으면 질감을 사용하지 않는 브러시의 모든 소재를 그 브러시의 브러시 끝으로 간주하고(이것도 추정으로 알림), 질감은 소재가 하나뿐일 때 그것을 맞춥니다.
결정할 수 없거나 이미지를 추출할 수 없는 브러시 끝은 사용하지 않습니다. 하나라도 빠지면 “브러시 끝 이미지”로 알리고, 하나도 없으면 원형 브러시 끝(질감은 질감 없음)으로 합니다
(임의로 다른 이미지를 사용하지 않음). 질감은 첫 참조만 사용하며, 첫 참조를 결정할 수 없을 때 두 번째 이후의 소재를 질감으로 사용하지 않습니다.
브러시 끝은 브러시 하나당 최대 256장이며 초과분은 사용하지 않고 알립니다.

| 시작과 끝 | 지정 방식이 백분율 지정·페이드, 옮길 수 있는 영향 대상이 하나도 없음(옮길 수 없는 영향 대상은 옮길 수 있는 대상과 함께 있어도 이름을 나열해 알림), 영향 대상 열을 읽을 수 없음, 길이 단위가 픽셀이 아님, 길이를 읽을 수 없음 |
| 시작과 끝의 속도·비율 | 시작과 끝을 옮겼을 때 속도에 따른 길이와 비율은 읽지 않았음 |
| 손떨림 보정 | 속도에 따른 손떨림 보정의 보정 유형을 읽을 수 없음(강도는 옮김) |
| 손떨림 보정 강도 | 손떨림 보정을 옮겼을 때 단계 1 = 1픽셀 환산은 추정 |
| 기울기 곡선 | 기울기 곡선을 결정하지 못해 직선으로 변경 |
| 기울기 최댓값 | 기울기 최댓값이 100%를 넘거나(이 앱은 최대 100%) 영향 입력 헤더에 없어 100%로 변경 |
| 젖은 가장자리 | Photoshop ABR의 젖은 가장자리(`.sut`의 수채 경계는 옮김. 이전 버전에서 가져온 `.sut` 브러시 파일에는 이 항목이 남아 있음) |
| 컨트롤 | 영향 입력의 속도·무작위 곡선(직선으로 변경), 읽지 못한 영향 입력 |
| 필압 곡선 | 필압 곡선의 점이 16개를 넘어 16점으로 다시 샘플링함(기울기 곡선이면 “기울기 곡선”) |
| 브러시 설정 | 설정 테이블(`Variant`) 또는 행 번호 열(`VariantID`)이 없음. 브러시 크기 단위가 px가 아님(px로 읽음). 간격 종류를 읽을 수 없음. 수채 경계 너비·흐림 너비 단위가 px가 아님(px로 읽음), 수채 경계 값이 범위 밖(범위 끝으로 맞춤) |

### 바탕색 혼합 환산

CLIP STUDIO의 물감 양·물감 농도·색 늘이기(0~100을 0~1로)는 이 앱의 물감 양·농도·색 늘이기와 같은 수치여도 같은 선이 되지 않습니다(이 앱의 양·색 늘이기는 “찍기마다 물감 적재량에 남는 비율”이며, CLIP STUDIO의 값은 선 위에서의 효과입니다). 가져올 때 물감 양·물감 농도·색 늘이기는 방식(색 혼합·색 겹치기·번짐)별 수식으로 엔진 값(물감 양·농도·색 늘이기·초기 물감 양)으로 환산합니다(근사입니다. 값은 1 대 1로 옮겨지지 않음). 색 늘이기는 물감 적재량이 아래 색을 기억하는 거리로 옮겨 찍기 간격에 영향을 받지 않도록 했습니다(찍기당 비율 그대로 옮기면 간격만 바꿔도 끌리는 거리가 달라지기 때문).
